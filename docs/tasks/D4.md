## Goal

A new engineer clones the repository and, using only `README.md` and `docs/runbook.md`, sets up, runs the daily job and opens the app. The README is the front door (what it is, quick start, where things are); the runbook is the operating manual (every run, every routine problem).

## Implementation steps

1. Each cadence section (3 to 6) has the same five parts: when to run it; the commands, ready to paste; which stages run (from `stages/*.conf`); what a good run prints and how long it takes; how to confirm it (a row in `data/ops/run_metrics`, the health page).
2. Daily: `scripts/run-labels.sh` first (it runs the `labels` module download and extraction and writes `data/interchange/labels/`), then `run daily`. Explain why in one sentence: `labels` is Scala 3 and hands files to the pipeline. State that a second run with no new label version does no work and says so.
3. Weekly, quarterly, full: the download step for each source, then `run weekly`, `run quarterly`, `run full`. Give both invocation forms that C1 supports (sbt `runMain` and `spark-submit`), and the options `--as-of`, `--force`, `--dry-run`. There is no monthly cadence; RxNorm runs under quarterly and full.
4. Publish and app: publish is the last stage of every cadence; how to run it alone; the `medsignal.serving.*` settings (H2 file by default, PostgreSQL for Compose); `sbt app/run`, the port, the five pages. Never print a password in an example.
5. Docker Compose: `docker compose up --build`, what the three services do, `docker compose down -v` to reset, where the sample data came from.
6. When a quality check fails: the exit code and what the console shows; where the result is stored and shown (health page); that nothing was published, so the app still serves the previous run; then per check (list the real checks from C5's code): what it means, how to find the offending rows (`data/ops/rejects` by `source` and `runId`), and the usual fix. End with how to re-run, and say plainly that bypassing a check is not a fix.
7. Adding a source, the four steps of `docs/ontology.md`, each with the file to create and an existing task to copy: (1) a bronze reader and case class plus a `stages/<name>.conf` (see `bronze/partd/`); (2) map its drug names through `drug_xref` with `DrugIdentity.ensureResolved`; (3) one gold object keyed by `rxcui`, defined in the package that writes it; (4) a publisher file under `publish/` if the app needs it. Nothing existing is edited.
8. Other failures table, at least: Spark on Windows (use WSL2 or Docker), out of memory on a full rebuild, a download that stops halfway, a FAERS header change, an H2 file locked by a running app.
9. Fresh-eyes run: the other engineer (or a classmate) follows the README on a clean clone without help; fix every sticking point in the text and repeat until none remain.
