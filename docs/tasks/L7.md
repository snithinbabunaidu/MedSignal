## Goal

A stage that scores the current extractor against the gold set and writes precision, recall and negation accuracy per extractor version to `data/ops/extraction_score`. It also writes a drift report: reactions whose status changed between two versions of a label, or between two extractor versions. Together they show whether a rule change helped and what it moved.

## Context

Read `docs/acceptance-criteria.md` criterion 5, `docs/pipeline-spec.md` sections 5 and 8 (the "Extraction" check), `docs/ontology.md` "Operational tables", and briefs `docs/tasks/L5.md` (`LabelExtractor`, `LabelMention`, `ExtractorVersion`) and `docs/tasks/L6.md` (gold file schema, annotation rules).

- Rule-based evaluation: set comparison only.
- The score is computed by running the extractor on the gold labels' sections, not by reading `gold.LabeledReaction`. Reason: that table keeps one mention per term per label, in the highest-priority section, while the gold set is annotated per section and only for adverse reactions and boxed warning.
- `ExtractionScore` and `ExtractionDrift` are defined here; contracts.md names the `extraction_score` table but gives no columns, and does not list `extraction_drift`. A1 publishes `extraction_score` and expects at least `extractorVersion`, `precision`, `recall`, `negationAccuracy`, `scoredAt`.
- Only top-level files `data/reference/gold_labels/*.json` are scored. `shared/` and the `.md` and `.csv` files are not read.

## Inputs

- `data/reference/gold_labels/*.json` under `medsignal.dataDir`.

## Implementation steps

1. `GoldSet.read(dir: String)(implicit spark): (Dataset[GoldLabel], Seq[Reject], String)`. Read with `spark.read.schema(Encoders.product[GoldLabel].schema).option("multiLine", "true").json(dir + "/*.json")`. The third value is `goldSetChecksum`: first 8 hex characters of SHA-256 over the file names and bytes, in name order. Rejects (`source = "gold_labels"`, `file` = file name, `line = 0`): a file that does not parse, a missing field, or a (`setId`, `version`) with no rows in `bronze.label_section`.
2. Items. A gold item is (`setId`, `version`, `loinc`, `term`) with its `negated` flag. Extracted items: take the sections of the gold labels restricted to each label's `sectionsAnnotated`, call `LabelExtractor.mentions` (dictionary and trie built as in L5), group by (`setId`, `version`, `loinc`, `term`); the extracted `negated` flag is true only when every mention in the group is negated. This mirrors L6's rule.
3. `Scorer.score(gold: Set[Item], extracted: Set[Item]): Counts` (pure, `Item` carries the key and the flag):
   - true positive: key in both, whatever the flags; false positive: extracted only; false negative: gold only.
   - `precision = tp / (tp + fp)`, `recall = tp / (tp + fn)`; `0.0` when the denominator is zero.
   - `negatedGold` = true positives whose gold flag is true; `negatedCorrect` = those whose extracted flag is also true; `negationAccuracy = negatedCorrect / negatedGold`, `0.0` when `negatedGold` is zero. Also log the number of true positives where gold is not negated but the extractor says negated (over-negation); put it in the results file.
   The gold set is small: collect both item sets to the driver and score there.
4. Regression flag: the previous score is the row with the newest `scoredAt` whose `extractorVersion` differs from the current one and whose `goldSetChecksum` is the same. `regressed = precision < prev.precision || recall < prev.recall`. With no such row, `false`. When `regressed` is true and config `medsignal.extraction.failOnRegression` is true (read from `Settings.config`; default `false` in this task's `conf.d/L7.conf`), throw after writing the row so the run stops with the two scores in the message (pipeline-spec.md section 8, "Extraction").
5. Drift (`Drift`), from `gold.LabeledReaction`. Status of a term on a label version under an extractor version: `labeled` (row with `negated = false`), `negated` (row with `negated = true`), `absent` (no row).
   - `label_version`: for the current extractor version, for each `setId`, compare each version with the next higher version present; emit one row per term whose status differs.
   - `extractor_version`: compare the current extractor version with the previous one (from step 4, ignoring the checksum) on every (`setId`, `version`) present under both; emit one row per term whose status differs.
   Each comparison is a full outer join on the key. Write with `Delta.overwrite`.
6. Stage `ExtractionScoreStage` (`name = "labeltext.eval"`, `cadences = Set(Daily, Full)`):
   - If a row for (`ExtractorVersion.current()`, `goldSetChecksum`) already exists, skip scoring; still rebuild the drift table when `gold.LabeledReaction` has changed since (simplest: always rebuild it, it is small).
   - Otherwise score, `Delta.merge` the row, write the rejects with `Rejects.write`.
   - Return `StageResult(rowsIn = gold items, rowsOut = score rows written + drift rows, rowsRejected)`. Do not call `RunMetrics.record`; the runner records (contracts.md final section, item 6).
   - `stages/labeltext.eval.conf`: `class = "medsignal.labeltext.eval.ExtractionScoreStage"`, `after = ["labeltext.extract"]`, `always = true` (a new gold file is new work that no upstream stage reports; see `docs/tasks/C1.md`).

## Tests

`ScorerSpec` (no Spark):

- "counts a worked example": gold {A, B, C(negated)}, extracted {A, C(negated), D} gives tp 2, fp 1, fn 1, precision 2/3, recall 2/3, negatedGold 1, negatedCorrect 1.
- "a missed negation lowers negation accuracy only": gold C(negated), extracted C(not negated) gives tp 1 and negationAccuracy 0.0.
- "empty sets give zeros, not NaN".

`DriftSpec` (`SparkTestSession`):

- "reports a term added in a newer label version": v1 without `PANCREATITIS`, v2 with it gives one row `absent` to `labeled`, kind `label_version`.
- "reports a flip between extractor versions": same label, `negated` under e1 and `labeled` under e2.
- "reports nothing when nothing changed".

`ExtractionScoreStageSpec` (`SparkTestSession`, fixtures in `L7/`):

- "writes one score row for the fixture gold set" with the hand-computed precision and recall.
- "does not score the same version twice".
- "scores only annotated sections": a term found only in section `43685-7` is not a false positive.
- "rejects a gold file for an unknown label".
- "fails on regression when configured": seed a previous row with higher recall and set the flag; the stage throws and the new row is present with `regressed = true`.
