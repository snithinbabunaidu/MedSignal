## Goal

A pipeline stage that pulls, for every formulary ingredient, the clinical trials that posted results with adverse events, and stores one row per trial, arm and adverse event term in `bronze.trial_adverse_event`. Task V7 uses it to show trial evidence beside a signal as a second opinion.

## Context

Read `docs/contracts.md` (bronze `trial_adverse_event`, Common library, and the final section "Decisions settled after the first draft of the briefs": decisions 1, 2, 3, 6, 7, 9, "Common library (F7) additions", "Stage names"), `docs/data-sources.md` (ClinicalTrials.gov row), `docs/pipeline-spec.md` section 10 (last bullet) and `https://clinicaltrials.gov/data-api/api`.

Believed facts about API v2; make each call once by hand, save the response as a fixture and correct this list in the results file:

- `GET https://clinicaltrials.gov/api/v2/studies?query.intr=<name>&aggFilters=results:with&pageSize=100&pageToken=<token>`. The response has `studies[]` and, when more pages exist, `nextPageToken`. `pageSize` is believed capped at 1000. A `fields` option can limit the payload; use it if it works, since full studies are large.
- In each study: `protocolSection.identificationModule.nctId`, and `resultsSection.adverseEventsModule` with:
  - `eventGroups[]`: `id` (for example `EG000`), `title` (the arm, for example "Canagliflozin 100 mg" or "Placebo");
  - `seriousEvents[]` and `otherEvents[]`: `term`, `organSystem`, and `stats[]` with `groupId`, `numAffected`, `numAtRisk`.
- Trial terms are free text or MedDRA terms in mixed case, not the upper-case FAERS terms.

How the contract's columns are filled (bronze is "as received"):

| Column | Source |
|---|---|
| `nctId` | `identificationModule.nctId` |
| `intervention` | the `title` of the event group that the stat's `groupId` points to, as written |
| `rxcui` | `Some(<formulary rxcui>)` when the arm title (`intervention`) contains, case-insensitively, the name of a formulary ingredient whose query returned this trial; `None` otherwise (placebo and comparator arms). When several such ingredients match one arm, take the smallest `rxcui` and count these arms for the results file |
| `term` | the event's `term`, as written |
| `serious` | `true` for a row from `seriousEvents[]`, `false` for a row from `otherEvents[]` |
| `affected` | `numAffected` |
| `atRisk` | `numAtRisk` |

Serious and other events both produce rows, so one (trial, arm, term) can appear twice, once with `serious = true` and once with `serious = false`.

F6 loads the formulary into `bronze.formulary` (stage `bronze.formulary`). Read that bronze table with `Delta.readOrEmpty[FormularyDrug](Tables.bronze("formulary"))`, importing `medsignal.bronze.reference.formulary.FormularyDrug`; never read `data/reference/formulary.csv` and never redefine the case class (contracts.md, decisions 2 and 3).

The stage name is `bronze.trials` (contracts.md, Stage names). The stage returns `StageResult` and never calls `RunMetrics.record`; `StageRunner` records the metrics (decision 6). Rejects are written with `Rejects.write(...)`.

## Implementation steps

1. `TrialsClient.download(rxcui, ingredient, dir): Either[String, Int]` (pages saved): URL-encode the name; loop while a `nextPageToken` is present (extract it with a small regex on the body; no JSON library is needed for that); save each page to a `.part` file then rename; throttle and retry as configured. An ingredient with zero studies saves one page with an empty `studies` array. Skip ingredients whose folder already has a complete download marker (`_done`) unless cadence is `Full`.
2. `pageSchema`: only the fields listed in Context; everything nullable.
3. `TrialJsonReader.read(rawDir, formulary, ctx)` (`formulary` = the `(rxcui, ingredient)` pairs):
   - `spark.read.schema(pageSchema).option("multiLine", true).json(rawDir + "/*/page-*.json")` with `input_file_name()`; explode `studies`.
   - A trial found under several ingredients is kept once: the copy under the smallest `rxcui` folder name. Before dropping the other copies, collect per `nctId` the set of `rxcui` folder names it was found under (its candidate ingredients).
   - A study without `adverseEventsModule` is dropped and counted (it is not an input row for this table); report the count.
   - Union `seriousEvents` (with `serious = true`) and `otherEvents` (with `serious = false`), explode `stats`, join each stat to its event group by `groupId` within the study.
   - `rxcui`: among the trial's candidate ingredients, those whose `ingredient` name occurs in the arm title, compared lower-cased; none gives `None`, one gives `Some(rxcui)`, several give the smallest `rxcui`. Broadcast the small formulary list; do this in a typed `map`, not a join that could multiply rows.
   - Reject (`file` = page path relative to `rawDir`, `line = 0`, `raw = to_json` of the stat with `nctId` and `term`): `missing nctId`, `missing term`, `missing numAffected`, `missing numAtRisk`, `unknown groupId`. A page that does not parse: `unparseable page`.
   - `rowsIn` = stats read; `rowsIn = rowsOut + rowsRejected` must hold, else throw.
4. Stage (`name = "bronze.trials"`, `cadences = Set(Cadence.Full)`): download for every formulary row, read, `Delta.overwrite(rows, Tables.bronze("trial_adverse_event"))`, `Rejects.write(rejects)`, `RunManifest.record`, then return `StageResult(rowsIn, rowsOut, rowsRejected)`. Do not call `RunMetrics.record`; `StageRunner` records the row. If `bronze.formulary` is missing or empty, fail with the message `bronze.formulary is empty; run bronze.formulary first`.
5. Run: `sbt "pipeline/runMain medsignal.common.StageRunner bronze.trials --cadence full"` (after `bronze.formulary` has run). Try it first on three ingredients and look at payload size before running all of them.
6. No `var`, no `null`.
