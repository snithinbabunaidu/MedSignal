## Goal

A table, `gold.InteractionSignal`, of reactions reported more often when two formulary drugs are taken together than either drug alone would suggest. It is computed twice: with a self-join of `silver.case_drug`, and with a GraphFrames motif query, so the two approaches can be compared for result and run time.

## Context

- Read `docs/pipeline-spec.md` sections 4 and 10 ("Interactions"); `docs/contracts.md` rows `case`, `case_drug`, `case_reaction`, `formulary` and section "Statistics".
- Definitions, for an unordered drug pair (A, B) with `rxcuiA < rxcuiB` and a reaction term r, over all cases N in `silver.case`:

  ```
  a = cases with A and B and r        b = cases with A and B, without r
  c = cases with r, without (A and B) d = N - a - b - c
  pairPrr = PRR of that table
  prrA, prrB = PRR of each drug alone with r, over all its cases (including those with the other drug)
  interactionRatio = pairPrr / max(prrA, prrB)
  ```

- `silver.case_drug` holds suspect drugs only, one row per case and ingredient. So "taken together" means "both listed as suspect in the same report". This is co-reporting, not proof of interaction; say so in the results.
- Restrict the pair join to formulary drugs before joining (broadcast the formulary), and require minimum counts, or the pair table explodes.
- GraphFrames: the artifact and version must match Spark 4.0 and Scala 2.13. Check `build.sbt` for what F1 chose and the GraphFrames documentation for that version (the Maven group and artifact naming changed between releases). If the dependency is missing or does not resolve for Spark 4.0, that is a `[Chore]` pull request on `build.sbt`, and the fallback is recorded in the results.
- This is an evaluation job. It must not lengthen normal runs: it runs only when `medsignal.evaluation.enabled` is `true`.

## Outputs

`gold.InteractionSignal`, key (`rxcuiA`, `rxcuiB`, `term`). The case class lives in this task's package, `medsignal.advanced.interactions.InteractionSignal`; V5 and V6 import it:

```scala
final case class InteractionSignal(
  rxcuiA: String, rxcuiB: String,        // rxcuiA < rxcuiB
  term: String,
  pairCases: Long,                       // cases with both drugs (a + b)
  a: Long, b: Long, c: Long, d: Long,
  pairPrr: Double, chiSquare: Double,
  prrA: Option[Double], prrB: Option[Double],
  interactionRatio: Option[Double])      // None when neither single-drug PRR is defined
```

Rows are kept when `pairCases >= minPairCases`, `a >= minPairReactionCases` and `pairPrr` is defined. The stage's total run time reaches `ops.run_metrics` through the runner; the separate run times of the two versions go to the log and the results file.

## Implementation steps

1. `PairCounts`:

   ```scala
   object PairCounts {
     def pairs(caseDrug: Dataset[CaseDrug], formulary: Dataset[FormularyDrug]): DataFrame
       // caseid, rxcuiA, rxcuiB with rxcuiA < rxcuiB, formulary drugs only
     def pairReaction(pairs: DataFrame, caseReaction: Dataset[CaseReaction], minPairCases: Long): DataFrame
       // rxcuiA, rxcuiB, term, a, pairCases
   }
   ```

   Filter `case_drug` to formulary drugs first, then self-join on `caseid` with `l.rxcui < r.rxcui`. Count `pairCases` per pair, drop pairs under the minimum, then join to `case_reaction` on `caseid` and count per (pair, term). `case_drug` and `case_reaction` are already one row per case and key, so plain counts are distinct case counts; assert that in a test.

2. Single-drug and background counts. The background totals come from G1's gold tables, summed over all quarters (each case sits in exactly one quarter, so the sums are distinct case counts): `N` = sum of `QuarterTotal.cases`; `n_r` per term = sum of `ReactionQuarterTotal.cases`; `n_d` per formulary drug = sum of `DrugQuarterTotal.cases`. `n_dr` per formulary drug and term is counted from `silver.case_drug` joined to `silver.case_reaction`. A test asserts `N` equals the row count of `silver.case` on the fixture. Then `c = n_r - a`, `d = N - pairCases - n_r + a`. Join these small tables with broadcasts.

3. `Interactions.build(...)`: `Dataset[InteractionSignal]`. Statistics through `Disproportionality.prr` and `chiSquare` in a typed `map`. `prrA` uses `TwoByTwo(n_Ar, n_A - n_Ar, n_r - n_Ar, N - n_A - n_r + n_Ar)`. Because cases with the pair are included in each drug's own cases, `n_Ar >= a >= 3`, so a single-drug PRR is either positive or undefined (zero denominator), never zero. `interactionRatio = pairPrr / max of the defined single PRRs`; `None` if neither is defined.

4. Selection functions (V5 and V6 call these):

   ```scala
   final case class TopPair(rxcuiA: String, rxcuiB: String, bestTerm: String,
                            interactionRatio: Double, pairPrr: Double, a: Long, pairCases: Long)
   object Interactions {
     def candidates(ds: Dataset[InteractionSignal]): Dataset[InteractionSignal]
       // pairPrr >= 2, chiSquare >= 4, prrA < 2 and prrB < 2 when defined, interactionRatio defined
     def topPairs(ds: Dataset[InteractionSignal], n: Int): Seq[TopPair]
       // per pair keep its candidate row with the highest interactionRatio; order by ratio desc,
       // then a desc, then rxcuiA, rxcuiB; take n
   }
   ```

5. `InteractionGraph` (GraphFrames). Vertices: one per formulary drug (`id = rxcui`, `kind = "drug"`) and one per term (`id = "R:" + term`, `kind = "reaction"`, `term`). Edges, all with columns `src`, `dst`, `kind`, `term`, `prr`, `pairPrr`:
   - drug to drug, one edge per (pair, term) row of the table from step 3: `src = rxcuiA`, `dst = rxcuiB`, `term`, `pairPrr`. The pair PRR depends on the reaction, so the pair edge must carry the term;
   - drug to reaction: `src = rxcui`, `dst = "R:" + term`, `prr` = single-drug PRR.

   ```scala
   val g = GraphFrame(vertices, edges)
   val found = g.find("(a)-[ab]->(b); (a)-[ar]->(r); (b)-[br]->(r)")
     .filter("ab.term = r.term and ab.pairPrr >= 2 and ar.prr < 2 and br.prr < 2")
     .selectExpr("a.id as rxcuiA", "b.id as rxcuiB", "r.term as term")
   ```

   The motif string and the three PRR conditions are the ones in pipeline-spec section 10; `ab.term = r.term` is added so the triangle refers to one reaction. Check the motif syntax against the GraphFrames documentation for the version in the build. To compare like with like, apply the same chi-square and minimum-count filters on the edge set before building the graph. Note that a pair where a single-drug PRR is undefined has no `ar` or `br` edge and so cannot match; handle the same case identically in `candidates` or list the difference.

6. `InteractionStage` (`name = "advanced.interactions"`, `cadences = Set(Full)`; the stage file holds `class = "medsignal.advanced.interactions.InteractionStage"` and `after = ["silver.case", "silver.case_drug", "silver.case_reaction", "bronze.formulary", "signals.counts"]`):
   - skip with a log line unless evaluation is enabled;
   - time the join version (build plus `Delta.overwrite` to `Tables.gold("InteractionSignal")`);
   - time the motif version (graph build plus `find` plus `count`), reading the persisted table so both start from the same counts;
   - compare the two key sets (`candidates` against `found`): they must be equal; log and fail if not;
   - return `StageResult(rowsIn = case_drug rows, rowsOut = interaction rows, rowsRejected = 0)`. Do not call `RunMetrics.record`; the runner records the stage (contracts.md decision 6). Log one line per version with its wall time and counts (join: interaction rows; motif: edges and triangles) and copy those numbers into `docs/results/V4.md`.

## Tests

Fixtures in `pipeline/src/test/resources/V4/`: `formulary.json` (A, B, C on the formulary), `case.json` (200 cases), `case_drug.json`, `case_reaction.json`, `drug_quarter_total.json`, `reaction_quarter_total.json`, `quarter_total.json` (consistent with the cases), built by hand so that: A and B together appear in 30 cases, 12 with term T; A alone has T at the background rate; B alone likewise; drug X is off the formulary.

- `PairCountsSpec` "pairs are ordered rxcuiA < rxcuiB and appear once per case"; "off-formulary drugs form no pair"; "pairs under the minimum are dropped"; "a case with three formulary drugs yields three pairs".
- `InteractionsSpec` "2x2 cells match the hand count" (a = 12, b = 18, c and d from the fixture); "pairPrr matches the hand calculation"; "interactionRatio divides by the higher single PRR"; "ratio is None when neither single PRR is defined"; "candidates drops pairs explained by one drug" (a second fixture pair where prrA >= 2); "topPairs returns one row per pair, best term first, ordered by ratio".
- `InteractionGraphSpec` "motif finds the same (A, B, T) as the join version"; "motif does not match when the pair edge is for another term"; "key sets are equal on the fixture".
