## Goal

Every pull request is compiled, tested, format-checked and measured for coverage on GitHub Actions, and `main` cannot be merged into without a green run and one approval. This is what lets two engineers merge many small branches safely.

## Context

Read `docs/branching.md` (pull request checklist), `CONTRIBUTING.md` and `docs/acceptance-criteria.md` (criterion 9: CI green, at least 75% statement coverage in `pipeline`). F1 already added the `sbt-scalafmt` and `sbt-scoverage` plugins and set `coverageFailOnMinimum := false`; do not edit `build.sbt` or `project/`.

Read `docs/results/F1.md` first. If TableParser or XmlDoc are not on Maven Central, CI must build and `publishLocal` them before the main build, using the exact commands F1 recorded.

The build has two Scala versions: `pipeline` is Scala 2.13, `labels` and `app` are Scala 3. scalafmt needs a dialect per folder.

## Inputs

The build from F1.

## Outputs

A required status check named `build` on every pull request, plus a coverage report artifact.

## Files to create

- `.github/workflows/ci.yml`: the workflow.
- `.scalafmt.conf`: formatter settings.
- `docs/results/F2.md`: links to one green and one deliberately red run, and the branch protection settings applied.

## Implementation steps

1. `.scalafmt.conf`:
   ```hocon
   version = "<latest 3.x; check scalameta/scalafmt releases>"
   runner.dialect = scala213
   maxColumn = 110
   fileOverride {
     "glob:**/labels/src/**" { runner.dialect = scala3 }
     "glob:**/app/src/**"    { runner.dialect = scala3 }
   }
   ```
   Run `sbt scalafmtAll scalafmtSbt` once and check whether it wants to reformat files you do not own (`build.sbt`, the F1 smoke specs). If it does, tell Nithin and let a separate `[Chore]` pull request reformat them; do not change them on this branch.
2. `ci.yml`, triggers `pull_request` and `push` to `main`, one job `build` on `ubuntu-latest`:
   - `actions/checkout`.
   - `actions/setup-java` with `distribution: temurin`, `java-version: 21`, `cache: sbt`.
   - `sbt/setup-sbt`.
   - Only if `docs/results/F1.md` says so: check out the professor's repositories at the recorded tag and run `sbt publishLocal` (cache `~/.ivy2/local`).
   - `sbt scalafmtCheckAll scalafmtSbtCheck`.
   - `sbt coverage test coverageReport`. Confirm `sbt-scoverage` instruments the Scala 3 modules; if it fails on Scala 3, run coverage for `pipeline` only (`sbt coverage pipeline/test pipeline/coverageReport labels/test app/test`) and say so in `docs/results/F2.md`.
   - Print the `pipeline` statement coverage to the job summary (read it from `pipeline/target/scala-2.13/scoverage-report/scoverage.xml`, attribute `statement-rate`; verify the path) and upload the HTML report with `actions/upload-artifact`.
   - `timeout-minutes: 30`. Set `concurrency` so a new push cancels the previous run of the same branch.
3. Tests must not use the network. If a spec in a later task needs the network, it must be tagged and excluded; CI runs plain `sbt test`.
4. Coverage gate: report only for now. The 75% figure is measured for the acceptance report (D2); do not fail the build on it, because early branches contain little code.
5. Branch protection on `main` (repository Settings, Branches, or `gh api`): require a pull request, require 1 approval, require the `build` check, require branches to be up to date, no direct pushes, merge commits only (no squash, so each task's commit and author stay in history). Record the settings in `docs/results/F2.md`. This step needs repository admin rights; if you do not have them, ask Nithin.
6. Prove it: open a throwaway pull request with a failing test, confirm merge is blocked, close it without merging.

## Tests

There is no ScalaTest code in this task. The checks are:

- A pull request with correct code shows a green `build` check.
- A pull request with `1 shouldBe 2` in a spec shows a red check and the merge button is disabled.
- A pull request with badly formatted code fails at the scalafmt step.

No fixture files.

## Done when

- [ ] The F2 pull request itself shows a green check.
- [ ] A failing test blocks merge (link to the red run in `docs/results/F2.md`).
- [ ] `main` is protected as in step 5.
- [ ] Coverage for `pipeline` appears in the job summary. Feeds criterion 9.
