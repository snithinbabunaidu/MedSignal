## Goal

The package `medsignal.common` that every pipeline stage calls: table locations, Delta read and write helpers, the run manifest, the run metrics writer, the `Reject` type, the `Stage` contract and a test mixin. Eight tasks wait on it, so the public names must match `docs/contracts.md` exactly.

## Context

Read `docs/contracts.md` ("Paths", "Common library", "Conventions", and the final section "Decisions settled after the first draft of the briefs", especially "Common library (F7) additions" and decisions 6 to 9) in full; the signatures there are binding. `Cadence`, `Settings`, `Delta.exists`, `Delta.readOrEmpty`, `Rejects.write`, `Checksum.sha256`, `RunContext.start` and `StageRunner.run` must be defined exactly as written there. Read `docs/architecture.md` (Layers; Foundry concepts table) and `docs/pipeline-spec.md` section 6.

Contracts.md leaves these points open. This brief settles them; they are additions, not changes:

- **Session and run id.** `RunManifest` and `RunMetrics` take no `SparkSession` or run id. They use `SparkSession.active`, and read the run id from the session conf key `medsignal.runId` (value `adhoc` if unset). `RunContext.start` (below) sets that key.
- **Config.** `Tables` takes no config argument. It reads `Settings.dataDir`, which resolves on every call (no caching in a `val`), so tests can redirect it.
- **`Cadence`** is defined in contracts.md (four case objects: `Daily`, `Weekly`, `Quarterly`, `Full`; there is no monthly cadence). This brief only adds `Cadence.parse`.
- **Row types** of `run_manifest` and `run_metrics` are not in contracts.md; define them here.
- **`Delta.overwrite` with `partitionBy`** replaces only the partitions present in the dataset (dynamic partition overwrite). With no `partitionBy` it replaces the table.
- **Single-stage runner.** Bronze tasks must be runnable before the orchestrator (C1) exists, so this task defines `StageRunner` (contracts.md). `StageRunner.run` runs one stage, times it and records its metrics; C1 calls it for every stage.
- **Metrics.** A stage returns `StageResult` and never calls `RunMetrics.record`. Only `StageRunner.run` does (contracts.md, decision 6).

`application.conf` is owned by F3 (paths and connection settings only) and may not be merged yet: every `Settings` lookup of a path has a default in code. Thresholds and other tunables of later tasks live in their own `pipeline/src/main/resources/conf.d/<task id>.conf`, which `Settings.config` loads (contracts.md, decision 9).

## Inputs

Config keys `medsignal.dataDir` (default `data`), `medsignal.spark.master` (default `local[*]`), `medsignal.spark.shufflePartitions` (default 16).

## Outputs

Delta tables under `data/ops/`:

```scala
final case class ManifestEntry(source: String, unit: String, checksum: String,
                               watermark: Option[String], runId: String, recordedAt: java.sql.Timestamp)   // run_manifest
final case class RunMetric(runId: String, stage: String, rowsIn: Long, rowsOut: Long, rowsRejected: Long,
                           durationMs: Long, newestSourceDate: Option[String], recordedAt: java.sql.Timestamp) // run_metrics
final case class Reject(source: String, file: String, line: Long, raw: String, reason: String, runId: String) // rejects
```

Stages write rejects with `Rejects.write(rejects)`, which appends to `Tables.ops("rejects")` (`data/ops/rejects`). Stages do not call `Delta.append` on the rejects table themselves. For a `Reject` raised by a stage that reads a table rather than a file, `file` is the input table name and `line` is 0 (contracts.md, decision 7); say so in the scaladoc of `Reject`.

## Implementation steps

1. `Settings` (Typesafe Config). `dataDir` and `config` are the contract (contracts.md); the other methods are conveniences built on `config`. `config` is rebuilt on every call (no caching in a `val`): `ConfigFactory.load()` (system properties, then `application.conf`) with, as fallback, every classpath resource `conf.d/*.conf` merged together, then `.resolve()`. To list `conf.d`, enumerate `getClassLoader.getResources("conf.d")` and handle both a directory URL (sbt, tests) and a jar URL (assembly); parse each file with `ConfigFactory.parseURL`. Task files must not define the same key twice; each task uses its own sub-tree (for example `medsignal.signals`), so merge order does not matter.
   ```scala
   object Settings {
     def dataDir: String                                   // medsignal.dataDir, default "data"
     def config: com.typesafe.config.Config                // application.conf plus every conf.d/*.conf
     def referenceDir: String                              // dataDir + "/reference"
     def rawDir(source: String): String                    // dataDir + "/raw/" + source
     def interchangeDir(name: String): String              // dataDir + "/interchange/" + name
     def string(key: String, default: String): String
     def int(key: String, default: Int): Int
     def double(key: String, default: Double): Double
   }
   ```
2. `Tables`: `bronze(name) = s"${Settings.dataDir}/bronze/$name"`, same for `silver`, `gold`, `ops`.
3. `Delta`, signatures as in contracts.md, including `def exists(path: String): Boolean` and `def readOrEmpty[T: Encoder](path: String)(implicit spark: SparkSession): Dataset[T]`.
   - `exists`: true when `path` holds a Delta table (`DeltaTable.isDeltaTable(SparkSession.active, path)`); it takes no session argument.
   - `readOrEmpty`: `read` when `exists(path)`, otherwise `spark.emptyDataset[T]`.
   - `read`: `spark.read.format("delta").load(path).as[T]`.
   - `append`: `ds.write.format("delta").mode("append").partitionBy(...)`.
   - `overwrite`: mode `overwrite`; when `partitionBy` is non-empty add `.option("partitionOverwriteMode", "dynamic")`. Never set `overwriteSchema`; a schema change must fail.
   - `merge`: if the table does not exist, `overwrite`. Otherwise `DeltaTable.forPath(ds.sparkSession, path)` merged on equality of every key column, `whenMatched().updateAll()`, `whenNotMatched().insertAll()`. Document that `ds` must be unique on `keys` (Delta fails otherwise).
4. `Stage.scala`:
   ```scala
   sealed trait Cadence
   object Cadence {
     case object Daily extends Cadence; case object Weekly extends Cadence
     case object Quarterly extends Cadence; case object Full extends Cadence
     def parse(s: String): Either[String, Cadence]          // case-insensitive
   }
   final case class RunContext(spark: SparkSession, runId: String, cadence: Cadence, asOfQuarter: Option[String])
   object RunContext {
     // new runId = yyyyMMdd-HHmmss plus 6 random hex chars; sets spark conf "medsignal.runId"
     def start(spark: SparkSession, cadence: Cadence, asOfQuarter: Option[String] = None): RunContext
   }
   final case class StageResult(rowsIn: Long, rowsOut: Long, rowsRejected: Long)
   trait Stage { def name: String; def cadences: Set[Cadence]; def run(ctx: RunContext): StageResult }
   ```
   A stage is a `class` with a public no-argument constructor. A stage returns its counts in `StageResult` and never calls `RunMetrics.record`; `StageRunner.run` records them (contracts.md, decision 6).
   Also `Rejects.scala`:
   ```scala
   object Rejects { def write(rejects: Dataset[Reject]): Unit }   // appends to Tables.ops("rejects"); an empty dataset is fine
   ```
5. `RunManifest` (table `Tables.ops("run_manifest")`): `loaded` returns the distinct `unit` values for the source, or an empty set when the table does not exist. `record` appends one `ManifestEntry`. `watermark` returns the greatest non-empty `watermark` for the source by string comparison, so callers must use sortable strings (`2024Q3`, `yyyyMMdd`).
6. `RunMetrics.record` appends one `RunMetric` to `Tables.ops("run_metrics")`. Its only caller in production code is `StageRunner.run`.
7. `SparkSessions.create(appName: String): SparkSession`: master and shuffle partitions from `Settings`; `spark.sql.extensions = io.delta.sql.DeltaSparkSessionExtension`; `spark.sql.catalog.spark_catalog = org.apache.spark.sql.delta.catalog.DeltaCatalog`; session time zone `UTC`.
8. `StageRunner`:
   ```scala
   object StageRunner { def run(stage: Stage, ctx: RunContext): StageResult }   // runs one stage, times it, records metrics
   ```
   `run` takes the wall-clock time around `stage.run(ctx)`, then calls `RunMetrics.record(stage.name, result.rowsIn, result.rowsOut, result.rowsRejected, durationMs, None)` (`StageResult` carries no source date, so `newestSourceDate` is `None`) and returns the result. If the stage throws, nothing is recorded and the exception propagates. The C1 orchestrator calls `StageRunner.run` for each stage. The same object has a `main`: `sbt "pipeline/runMain medsignal.common.StageRunner <stage name> [--cadence full] [--as-of 2024Q3]"`. It loads classpath resource `stages/<stage name>.conf`, reads `class`, instantiates it by reflection, checks it is a `Stage`, calls `RunContext.start`, calls `run`, prints the `StageResult`, and exits non-zero on an exception. It ignores `after`; ordering belongs to C1. Put the lookup in `def load(stageName: String, folder: String = "stages"): Either[String, Stage]` so the spec can point it at `F7/stages`.
9. `object Checksum { def sha256(path: String): String }`: `path` is a file path as a `String` (contracts.md); lower-case hex, streamed.
10. `SparkTestSession`:
    ```scala
    trait SparkTestSession extends BeforeAndAfterAll { self: Suite =>
      implicit lazy val spark: SparkSession          // local[2], Delta configured, UI off, 2 shuffle partitions
      def dataDir: java.nio.file.Path                // fresh temp folder per suite
      def testContext(cadence: Cadence = Cadence.Full, asOfQuarter: Option[String] = None): RunContext
      def resource(path: String): String             // absolute path of a test resource, e.g. resource("I2/drug.txt")
    }
    ```
    `beforeAll` sets system property `medsignal.dataDir` to the temp folder and calls `ConfigFactory.invalidateCaches()`; `afterAll` clears it and deletes the folder. The session is shared across suites (`getOrCreate`) and not stopped per suite. F1 runs tests forked and not in parallel, which this relies on.
11. No `var`, no `null`.

## Tests

- `SettingsSpec` "defaults dataDir to data"; "honours the system property"; "config includes keys from conf.d files" (`Settings.config.getBoolean("medsignal.common.confDirLoaded")` is true).
- `DeltaSpec` "overwrite then read returns the rows"; "append adds rows"; "partitioned overwrite replaces only its partition" (write quarters A and B, overwrite with new rows for B, A unchanged); "merge updates a matching key and inserts a new one"; "merge into a missing table creates it"; "exists is false for a missing path"; "readOrEmpty returns an empty dataset for a missing path and the rows for an existing one".
- `RejectsSpec` "write appends to ops rejects" (two calls, rows from both are read back from `Tables.ops("rejects")`).
- `RunManifestSpec` "loaded is empty before any record"; "record then loaded returns the unit"; "loaded is per source"; "watermark returns the greatest value"; "watermark is None for an unknown source"; "entry carries the run id from RunContext.start".
- `RunMetricsSpec` "record then read returns one row with the same counts and run id".
- `StageRunnerSpec` "runs a stage named in a conf file" (a test `Stage` that writes a marker row); "fails for an unknown stage name"; "run records one run_metrics row with the stage name, the StageResult counts and a duration" (the test stage itself does not call `RunMetrics.record`); "run records nothing when the stage throws".
- `Cadence.parse` "accepts daily, WEEKLY, Quarterly, full; rejects other".
