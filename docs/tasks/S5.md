## Goal

`silver.recall` holds one clean row per recall number, with parsed dates, a source link and, where the product text can be resolved, an ingredient `rxcui`. The Recalls page and the change feed read this table; recalls that cannot be tied to a drug stay visible with an empty `rxcui`.

## Context

- openFDA enforcement records describe the product in free text, for example "Metformin Hydrochloride Extended-Release Tablets, USP, 500 mg, 100-count bottles, NDC ...". There is no reliable ingredient identifier.
- `bronze.recall_raw` is upserted by `recall_number` (contracts.md, Bronze tables), so it should hold one row per recall. Step 1 still keeps the latest record per recall as a safeguard and counts any duplicates it finds.
- Names are resolved only through S2 (`DrugIdentity.ensureResolved(names: Dataset[String])`).
- Read: `docs/contracts.md` (Bronze tables `recall_raw`, Silver tables `recall`), `docs/pipeline-spec.md` section 6 (recalls row), `docs/data-issues.md` row 13, the S2 brief.

## Outputs

```scala
final case class RecallClean(recallNumber: String, rxcui: Option[String], classification: String,
```

## Implementation steps

1. Latest record per recall. `RecallRaw` has no load timestamp, so order by what the record itself says:

   ```scala
   val rank = when(col("status") === "Terminated", 3).when(col("status") === "Completed", 2)
     .when(col("status") === "Ongoing", 1).otherwise(0)
   val w = Window.partitionBy("recall_number").orderBy(col("report_date").desc, rank.desc)
   ```

   Keep `row_number == 1`. Uncertain: the exact status values. Run `select status, count(*)` on bronze and adjust the list; record the values in the results file.

2. Dates. openFDA writes `yyyyMMdd` strings (confirm on bronze). `reportDate` is required: a row whose `report_date` does not parse becomes a `Reject`. `initiationDate` and `terminationDate` are `None` when missing or unparseable.

3. Text fields: trim `classification` (expected `Class I`, `Class II`, `Class III`), `status`, `reason_for_recall` to `reason`, `product_description` to `productText`, `recalling_firm` to `firm`. Rows with an empty `recall_number` become a `Reject`.

4. Source link. `RecallRaw` has no URL column, so build one:
   `https://api.fda.gov/drug/enforcement.json?search=recall_number:"<recallNumber>"`.
   Open one in a browser to confirm it returns the record before relying on it.

5. Name candidates (pure):

   ```scala
   object ProductText {
     def candidates(productDescription: String): Seq[String]
   }
   ```

   Return, in order and without duplicates: the text before the first comma; the text before the first digit; the text before the first opening parenthesis. Trim each; drop empties and anything longer than 80 characters. S2's `stripped` method removes dose and form words, so do not strip them here.

6. Resolution:

   ```scala
   object RecallTransforms {
     def latest(raw: Dataset[RecallRaw]): Dataset[RecallRaw]
     def clean(raw: Dataset[RecallRaw], formulary: Dataset[FormularyDrug], runId: String)
              (implicit spark: SparkSession): (Dataset[RecallClean], Dataset[Reject])
   }
   ```

   Explode candidates with their position, call `DrugIdentity.ensureResolved` on the distinct strings (a `Dataset[String]`, the signature in contracts.md decision 10), join back, and for each recall take the ingredients from the earliest candidate position that resolved. `RecallClean` holds one `rxcui`, so when several ingredients resolve (a combination product) keep a formulary ingredient if there is one, then the lowest `rxcui` as a number. No resolution gives `rxcui = None`; the row is kept.

   Do not use `openfda_rxcui` in this task: those are product-level identifiers, and in this task every name becomes an `rxcui` only through S2. (`bronze.rxnorm_ingredient_map`, written by I3, could map them to ingredients; using it here is a later decision.) Report how many unresolved recalls have a non-empty `openfda_rxcui`, so the lead can judge whether that mapping is worth adding.

7. Rejects: `Reject(source = "recalls", file = "bronze.recall_raw", line = 0, raw = recall_number, reason, runId)` (the input table name and line 0, contracts.md decision 7), written with `Rejects.write(rejects)`.

8. `RecallStage`: `name = "silver.recall"`, `cadences = Set(Weekly, Full)`. Return `StageResult(rowsIn, rowsOut, rowsRejected)`: `rowsIn` bronze rows, `rowsOut` rows written, `rowsRejected` the `Reject` rows. The stage does not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics. Conf: `after = ["bronze.recalls", "bronze.formulary", "identity.drug_xref"]` (I7's and F6's stage names as listed in contracts.md).

## Tests

`ProductTextSpec` (pure):

- "takes the text before the first comma": the metformin example above gives `Metformin Hydrochloride Extended-Release Tablets` first.
- "takes the text before the first digit": `Zolpidem Tartrate 10 mg tablets` includes `Zolpidem Tartrate`.
- "returns nothing for an empty description".
- "does not repeat a candidate".

`RecallTransformsSpec` (Spark, fixture `recall_raw.json`):

- "the latest record of a recall wins": the same number with `Ongoing` then `Terminated` gives one row, `Terminated`.
- "dates are parsed": `20240115` gives 2024-01-15; a missing termination date gives `None`.
- "a bad report date is rejected".
- "a resolvable product gets its rxcui".
- "an unresolved recall is kept with an empty rxcui".
- "a combination prefers the formulary ingredient".
- "recallNumber is unique".
