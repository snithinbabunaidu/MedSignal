## Goal

A written decision on how XmlDoc extracts label metadata and section text from real DailyMed labels: which derived case classes work, and what fallback is used for section bodies with mixed content. I5 is built directly on the code pattern recorded here.

## Context

Read `docs/architecture.md` ("How the professor's libraries are used"), `docs/data-sources.md` (Label sections used), `docs/contracts.md` (`LabelSection`, Paths) and `docs/project-plan.md` (Risks, second row).

XmlDoc 1.2 is by Prof. Robin Hillyard: `github.com/rchillyard/XmlDoc`, Scala 3.9. What we believe, not yet verified: case classes get extractors with `derives Extractor`; `XmlStream` reads elements without loading the whole document; `GenericElement` is an untyped element tree; module `xmldoc-json` has `JsonLines` (writer) and `SparkSchema.ddl` (Spark DDL string from a case class). Read the README and tests first and take the real API from there.

SPL facts (HL7 v3, default namespace `urn:hl7-org:v3`):

```xml
<document xmlns="urn:hl7-org:v3">
  <setId root="..."/> <versionNumber value="12"/> <effectiveTime value="20240131"/>
  <title>mixed text and <br/> elements</title>
  <component><structuredBody>
    <component><section>
      <code code="34084-4" codeSystem="2.16.840.1.113883.6.1" displayName="ADVERSE REACTIONS SECTION"/>
      <title>6 ADVERSE REACTIONS</title>
      <text><paragraph>..<content styleCode="bold">..</content>..</paragraph><list><item>..</item></list><table>..</table></text>
      <component><section> nested subsection, same shape </section></component>
    </section></component>
  </structuredBody></component>
</document>
```

Section codes we need: boxed warning 34066-1, warnings and precautions 43685-7, adverse reactions 34084-4, drug interactions 34073-7. Older, non-PLR labels are believed to use separate "Warnings" (34071-1) and "Precautions" (42232-9) sections instead of 43685-7; check this on a real old label. Product data sits in a section with code 48780-1: product name, generic name, and `ingredient` elements whose `classCode` starts with `ACTI` (active) holding `ingredientSubstance/name`. The marketing category (`approval/code`, display names such as NDA, ANDA, BLA) is the likely basis for `isBrand`. Verify every one of these on the real files.

## Inputs

Five real labels downloaded by hand from DailyMed (`https://dailymed.nlm.nih.gov`, "Download SPL XML" or `/dailymed/services/v2/spls/{setid}.xml`). Choose for variety: a brand label with a boxed warning (for example a fluoroquinolone), a generic (ANDA) label, an old-format label without 43685-7, a combination product with two active ingredients, and a label whose adverse reactions section contains tables.

## Outputs

`docs/decisions/F5-xmldoc-on-spl.md` and spike code. The contract's four LOINC codes are confirmed or corrected.

## Implementation steps

1. **Metadata with derived extractors.** Model `document` with `setId`, `versionNumber`, `effectiveTime`, `title`. Find out how XmlDoc maps attributes (`root`, `value`) and how it treats the default namespace; record the answer.
2. **Sections.** Extract every `section` at any depth with its `code/@code`, `title` and `text`. Try a recursive derived case class first (`Section` containing `Seq[Section]`). If recursion or the `component` wrapper defeats derivation, record why and use `XmlStream` or `GenericElement`.
3. **Mixed content.** Section `text` mixes text nodes with `paragraph`, `content`, `list/item`, `table/tr/td`, `br`, `sub`, `sup`, `linkHtml`, `footnote`. Write `def plainText(e: GenericElement): String` that walks the tree in document order: one space between inline pieces, a newline after each `paragraph`, `item`, `tr` and `br`, a single space between table cells, runs of whitespace collapsed. This function is the likely fallback; state plainly whether derived extractors can do any of it.
4. **Nested sections.** Decide and record whether a parent section's text includes its subsections' text (I5 needs it to: adverse reactions is usually split into 6.1, 6.2).
5. **XmlStream.** Read one label with `XmlStream` and compare memory and code size with whole-document parsing. Labels are small (under a few MB); say whether streaming is worth using in I5.
6. **Product data.** Extract active ingredient names and the marketing category. State the `isBrand` rule that the data supports.
7. **JSON output.** Write one extracted record with `JsonLines` and generate `SparkSchema.ddl` for a spike copy of `LabelSection`. Paste both outputs into the decision record (I6 depends on the field names and on how `Seq[String]` and `Option[String]` appear).
8. **Coverage of the four codes.** For each of the five labels, list which of the four codes are present, and which other codes carry warnings content.
9. Write the decision record: Context, What was tried, What worked (the case classes, pasted), Fallback for mixed content, Findings on LOINC codes and `isBrand`, Consequences for I5 and I6, Open issues. If `LabelSection` or the code list in contracts.md needs a change, say so; that is a separate `[Chore]` pull request.

## Tests

`SplSpikeSpec` (`AnyFlatSpec with Matchers`):

- "reads setId, version and effective date": expected literal values for one fixture.
- "finds the adverse reactions section in every PLR label": code 34084-4 present with non-empty text.
- "includes subsection text in the parent": a sentence known to sit in 6.1 appears in the 34084-4 text.
- "flattens a table": a known cell value appears in the text and no `<` character remains.
- "finds two active ingredients in the combination label".
- "old-format label has no 43685-7": documents the finding.
