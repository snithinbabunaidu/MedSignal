## Goal

A command in the `labels` module that turns every downloaded label XML into `LabelSection` records, written as JSON Lines together with a Spark schema string generated from the same case class. Every label yields at least one record or one reject. This is the only place label XML is parsed; Spark (I6) reads the output.

## Context

Read first: `docs/decisions/F5-xmldoc-on-spl.md`. It gives the case classes that work with XmlDoc, the fallback for mixed content, the `isBrand` rule and the real `JsonLines` and `SparkSchema.ddl` calls. Where it differs from this brief on mechanics, the record wins.

Also read `docs/contracts.md` (bronze `label_section`, Paths: `data/interchange/labels/`), `docs/architecture.md` (Modules: why a schema string is the contract), `docs/pipeline-spec.md` sections 1 and 5, and `docs/tasks/I4.md` (input layout).

Section codes (LOINC): boxed warning `34066-1`, warnings and precautions `43685-7`, adverse reactions `34084-4`, drug interactions `34073-7`. Old-format labels are believed to carry warnings under `34071-1` (warnings) and `42232-9` (precautions) instead of `43685-7` (contracts.md, decision 14). F5 verifies this: if `docs/decisions/F5-xmldoc-on-spl.md` confirms it, both codes are also extracted and are treated as warnings and precautions (the record keeps the code found in the XML in `loinc`); if F5 did not confirm it, extract only the four codes and count what is missed.

The `labels` module is Scala 3 and cannot use the pipeline's common library (contracts.md, decision 5): this command takes `--data-dir`, keeps its own record of converted files, and writes its rejects to `data/interchange/labels/rejects.jsonl`. It is run before the pipeline's daily run by `scripts/run-labels.sh`, which C3 owns.

The `text` field is the base for character offsets in label extraction (L1 to L5). Its normalization is therefore fixed here and must be deterministic: the same XML always gives the same string.

## Inputs

- `data/raw/dailymed/<setId>/<version>.xml` and `data/raw/dailymed/manifest.tsv` (I4).
- `data/interchange/labels/converted.tsv` (this task's own record of what it has converted).

## Outputs

In `data/interchange/labels/`:

- `sections-<yyyyMMdd-HHmmss>.jsonl`: one `LabelSection` per line, only for label versions converted in this run. A label version appears in exactly one file, ever.
- `rejects.jsonl`: one `LabelReject` per line. A single file (contracts.md, decision 5); each run appends its new rejects to the end and never rewrites or reorders earlier lines, so I6 can load it by line position.
- `label_section.ddl`: the output of `SparkSchema.ddl` for `LabelSection`, rewritten each run.
- `converted.tsv`: `setId`, `version`, `status` (`ok` or `rejected`), `sections`, `outputFile`.

```scala
// field names and order exactly as contracts.md
final case class LabelSection(setId: String, version: Int, effectiveDate: String, title: String,
                              activeIngredients: Seq[String], isBrand: Boolean, loinc: String,
                              sectionTitle: Option[String], text: String)
final case class LabelReject(file: String, reason: String, raw: String)   // raw = first 500 characters of the file
```

`effectiveDate` is the `effectiveTime/@value` string as written (normally `yyyyMMdd`). `title` is the document title as plain text.

## Implementation steps

1. `PlainText.render(element): String`, rules in this order:
   - walk in document order; text nodes are kept, markup is dropped;
   - end each `paragraph`, `item`, `tr`, `caption`, `br` and section `title` with `\n`;
   - put one space between table cells and between adjacent inline pieces that would otherwise join two words;
   - replace non-breaking spaces and tabs with a space; collapse runs of spaces to one; trim each line; drop empty lines; no trailing newline.
2. `SplExtractor.extract`:
   - parse with XmlDoc as in the F5 record; a parse failure is `Left(LabelReject(file, "xml parse: <message>", raw))`;
   - missing `setId`, `versionNumber` or `effectiveTime`: reject with reason `missing <field>`;
   - `activeIngredients`: names of active ingredient substances from the product data section, trimmed, distinct, in document order; none found is allowed (empty `Seq`);
   - `isBrand`: the rule from the F5 record;
   - sections: every `section` at any depth whose `code/@code` is in `wantedCodes` gives one record. `text` is the rendered text of that section including all its subsections, each subsection's title on its own line. `sectionTitle` is the section's own title, `None` when absent or empty. A wanted section with empty text is not emitted;
   - no wanted section found: reject with reason `no wanted section`.
3. `LabelWriter`: write with XmlDoc's `JsonLines`; if it cannot write `Seq` or `Option` fields the way the DDL describes them, use circe with the same field names and say so in the results file. Write the `sections-` file to a `.part` file and rename. Append rejects to `rejects.jsonl` (open in append mode; with `--all`, delete it first along with the other old output). Write `label_section.ddl` from `SparkSchema.ddl`.
4. `SplToJsonLines.main`: options `--data-dir` (same default rule as I4) and `--all` (ignore `converted.tsv` and convert everything into a fresh file; use only after deleting old output). Convert files not in `converted.tsv`; process in a stable order (set id, then version); a failure in one file never stops the run. Print: files read, labels ok, labels rejected, records written, and counts by `loinc`. Write no `sections-` file when nothing is new.
5. Run: `sbt "labels/runMain medsignal.spl.SplToJsonLines"`.
6. Pure functions for rendering and extraction; no `var`, no `null`.

## Tests

- `PlainTextSpec`: "paragraphs become lines"; "list items become lines"; "table cells are separated by one space and rows by newline"; "inline content does not break a word or join two"; "whitespace runs collapse"; "rendering twice gives the same string".
- `SplExtractorSpec`: "brand label yields the boxed warning and adverse reactions with the expected setId, version and date"; "subsection text is inside the parent section text"; "combination label has two active ingredients"; "isBrand is true for the brand fixture and false for the generic"; "old-format label yields its 34071-1 and 42232-9 sections" (if F5 confirmed the two codes; otherwise "old-format label without the four codes is rejected with no wanted section"); "a label with none of the wanted codes is rejected with no wanted section"; "truncated XML is rejected with an xml parse reason"; "missing setId is rejected"; "sectionTitle is None when the section has no title".
- `LabelWriterSpec`: "each record is one line of valid JSON with the contract field names"; "converted labels are skipped on the next run"; "a label version is never written to two files"; "rejects of a second run are appended to rejects.jsonl after the first run's lines".
- `SchemaSpec`: "generated DDL equals the checked-in label_section.ddl"; "DDL names the nine fields in contract order".
