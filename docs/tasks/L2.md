## Goal

The vocabulary the matcher looks for in label text: every distinct FAERS reaction term plus hand-written synonyms for lay wording, each reduced to a normalized token key. The same normalizer is used on label text by L3, so the two sides cannot drift apart. The dictionary carries a version so extraction results can be traced to the rules that produced them.

## Context

Read `docs/pipeline-spec.md` section 5 (step 3), `docs/data-issues.md` rows 9 and 16, `docs/contracts.md` (Conventions: `term`; Silver `case_reaction`).

- Rule-based only: no language model, no stemmer library, no embeddings.
- FAERS reaction terms are MedDRA preferred terms in British spelling (`HYPOGLYCAEMIA`, `DIARRHOEA`, `HAEMORRHAGE`). US labels use American spelling. The normalizer folds the two digraphs; other spelling differences go in the synonym file.
- This task is a library. No stage, no table. The dictionary is built on the driver each time extraction runs.
- Design decision: `rulesVersion` covers the normalizer rules, the synonym file and the stop list, not the FAERS vocabulary. A new FAERS quarter therefore does not change the extractor version and does not re-read any label (architecture.md, decision 3). New FAERS terms reach already-extracted labels only when a version is bumped. `contentHash` records the full content for the log.

## Inputs

- `Dataset[CaseReaction]` from `Tables.silver("case_reaction")` (case class written by S3). Only `term` is used.

## Outputs

No table. Types in `medsignal.labeltext.dictionary`:

```scala
final case class Token(start: Int, end: Int, norm: String)            // offsets into the tokenized string
final case class DictionaryEntry(key: Seq[String], term: String, source: String)   // source: synonym, faers, permutation
final case class ReactionDictionary(rulesVersion: String, contentHash: String, entries: Seq[DictionaryEntry])
```

## Implementation steps

1. `Normalizer`:
   ```scala
   object Normalizer {
     val Version: Int = 1
     def tokenize(text: String): Seq[Token]      // offsets are indexes into `text`
     def stem(upperToken: String): String
     def key(text: String): Seq[String] = tokenize(text).map(_.norm)
   }
   ```
   - `tokenize`: a token is a maximal match of the regex `[\p{L}\p{N}]+(?:['’][\p{L}]+)*`. Everything else (spaces, hyphens, slashes, commas, brackets) separates tokens. `norm` = the token with apostrophes removed, upper-cased with `Locale.ROOT`, then `stem`.
   - `stem`, in this order:
     1. Replace every `AE` with `E` and every `OE` with `E`.
     2. If the length is under 4, stop.
     3. If it ends with `IES`, replace that ending with `Y` and stop.
     4. If it ends with `S` but not with `SS`, `US` or `IS`, drop the `S`.
     5. If it now ends with `E` and its length is at least 4, drop the `E`.
   - The stem is not meant to be a real word. It only has to map both forms to one string. Examples: `HEADACHES` and `HEADACHE` give `HEADACH`; `RASHES` and `RASH` give `RASH`; `INJURIES` and `INJURY` give `INJURY`; `DIARRHOEA` and `DIARRHEA` give `DIARRHEA`; `FOURNIER'S` gives `FOURNIER`; `PANCREATITIS`, `PRURITUS`, `DIZZINESS` are unchanged.
2. `ReactionDictionary.build(terms: Seq[String], synonyms: Seq[(String, String)], stopTerms: Set[String], rulesVersion: String): ReactionDictionary` (pure):
   1. Vocabulary = distinct `terms` minus `stopTerms`. Drop a term whose key is empty, or is a single token shorter than 3 characters.
   2. For each vocabulary term emit `DictionaryEntry(Normalizer.key(term), term, "faers")`.
   3. Word order. For a term with 2 or 3 tokens emit every other permutation of its key with source `permutation` (so `BLOOD GLUCOSE INCREASED` also matches "increased blood glucose"). For 4 or more tokens emit one extra key: the last token moved to the front.
   4. For each synonym row emit `DictionaryEntry(Normalizer.key(synonym), term, "synonym")`. No permutations for synonyms.
   5. When several entries share a key, keep one: `synonym` beats `faers` beats `permutation`; ties go to the alphabetically first `term`. Count the collisions.
   6. `contentHash` = first 8 hex characters of SHA-256 over the kept entries, sorted by key, rendered as `key tokens joined by space + "\t" + term + "\n"`.
3. `DictionaryLoader`:
   ```scala
   object DictionaryLoader {
     def rulesVersion(): String          // s"d${Normalizer.Version}-" + first 8 hex of SHA-256(synonym file bytes ++ stop list bytes)
     def load(reactions: Dataset[CaseReaction], runId: String)
             (implicit spark: SparkSession): (ReactionDictionary, Seq[Reject])
   }
   ```
   - Distinct terms: `reactions.map(_.term).distinct().collect()`. Expected size is tens of thousands of strings; measure it. It must fit on the driver.
   - Read the CSV with `spark.read.option("header", "true").csv(...)` and collect it. The path comes from `Settings` (`medsignal.dataDir`), never a literal.
   - Rejects (`source = "reaction_synonyms"`, `file` = the CSV path, `line` = 1-based data line): blank `synonym` or `term`; `term` not in the FAERS vocabulary (reason `unknown term`, catches typos); a synonym whose key equals the key of its own term (reason `redundant`). The caller (L5) writes them with `Rejects.write`.
4. `reaction_synonyms.csv`: write at least 60 rows by hand for the formulary's classes, using `docs/data-sources.md` "Known FDA warnings" as the starting list. Examples of the kind of row wanted: `low blood sugar,HYPOGLYCAEMIA`; `joint pain,ARTHRALGIA`; `sleepwalking,SOMNAMBULISM`; `suicidal thoughts,SUICIDAL IDEATION`; `necrotizing fasciitis of the perineum,FOURNIER'S GANGRENE`; `trouble breathing,DYSPNOEA`. These target terms are believed to be FAERS terms but are not verified: look each one up in `silver.case_reaction` and correct it; the loader's `unknown term` reject is the check. Do not generate the file with any AI tool; both engineers review every row in the pull request.
5. `stop_terms.txt`: administrative FAERS terms that are not reactions and would match ordinary label prose. Start with `DRUG INEFFECTIVE`, `OFF LABEL USE`, `NO ADVERSE EVENT`, `DRUG INTERACTION`, `CONDITION AGGRAVATED`, `PRODUCT USE IN UNAPPROVED INDICATION`; confirm each exists in the data. Add others only with a count from real labels in `docs/results/L2.md`.

## Tests

`NormalizerSpec` (no Spark):

- "maps plural and singular to one stem": the example pairs in step 1.
- "folds British digraphs": `key("Haemorrhage") == key("hemorrhage")`.
- "splits on hyphens and removes apostrophes": `key("Stevens-Johnson syndrome")` has 3 tokens; `key("Fournier's gangrene") == key("FOURNIERS GANGRENE")`.
- "token offsets reproduce the token": for `"Severe  joint pain."`, `text.substring(t.start, t.end)` is `Severe`, `joint`, `pain`.
- Property: `stem(stem(x)) == stem(x)` does not have to hold; instead test `key(s) == key(s.toLowerCase)` for any string.

`ReactionDictionarySpec`:

- "adds permutations for two-word terms": `RENAL FAILURE` yields keys for both orders.
- "moves the last token forward for long terms": a 4-token term yields exactly 2 keys.
- "synonym wins a collision": a synonym and a FAERS term with the same key resolve to the synonym's term.
- "drops stop terms and too-short terms".
- "content hash is stable": same inputs in a different order give the same hash.

`DictionaryLoaderSpec` (`SparkTestSession`, fixtures under `L2/`):

- "rejects a synonym with an unknown term": exactly one reject, reason `unknown term`.
- "rules version changes when the synonym file changes".
