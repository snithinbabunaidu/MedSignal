## Goal

Gold table `AdverseEventStat` holds distinct case counts per formulary drug, reaction term and quarter, with serious and death counts and running totals. Three small background tables hold the totals over all of FAERS that the signal statistics need. G3 builds every 2x2 table from these four tables without touching silver again.

## Context

- Counts are distinct cases, never rows.
- The comparison background is all of FAERS, not only formulary drugs. `AdverseEventStat` itself is kept only for formulary drugs so gold stays small.
- A case belongs to exactly one quarter (`Case.quarter`), so a running sum of per-quarter counts is the true cumulative distinct count.
- Serious = the case has any outcome in `DE, LT, HO, DS, CA, RI, OT`. Death = outcome `DE`.
- Gold aggregates are rebuilt in full on every run; that is cheap and always right (`docs/architecture.md`, decision 2).
- Read: `docs/contracts.md` (Silver tables, Gold tables), `docs/pipeline-spec.md` section 4, `docs/ontology.md` (`AdverseEventStat`), the S3 brief.

## Outputs

All in gold, written with `Delta.overwrite`. Define in `medsignal.signals.counts`.

```scala
// contracts.md; key rxcui, term, quarter; formulary drugs only
final case class AdverseEventStat(rxcui: String, term: String, quarter: String,
  cases: Long, seriousCases: Long, deathCases: Long, cumulativeCases: Long)

// background totals, exactly as in contracts.md (decision 15); all of FAERS
final case class DrugQuarterTotal(rxcui: String, quarter: String, cases: Long)      // key rxcui, quarter; every resolved drug
final case class ReactionQuarterTotal(term: String, quarter: String, cases: Long)   // key term, quarter
final case class QuarterTotal(quarter: String, cases: Long)                         // key quarter
```

Paths: `Tables.gold("AdverseEventStat")`, `Tables.gold("DrugQuarterTotal")`, `Tables.gold("ReactionQuarterTotal")`, `Tables.gold("QuarterTotal")`.

Meaning: `DrugQuarterTotal.cases` = cases in that quarter with the drug as a suspect. `ReactionQuarterTotal.cases` = cases in that quarter reporting the term, whatever the drugs. `QuarterTotal.cases` = all cases in `silver.case` for that quarter. A row exists only for quarters with at least one case. The three background tables hold per-quarter counts only (no cumulative column, to match contracts.md); G3 sums them over quarters. `AdverseEventStat.cumulativeCases` is the running total up to and including that quarter.

## Implementation steps

1. Signatures:

   ```scala
   object EventCounts {
     def caseFlags(outcomes: Dataset[CaseOutcome]): DataFrame            // caseid, serious: Int, death: Int
     def eventStats(cases: Dataset[Case], drugs: Dataset[CaseDrug], reactions: Dataset[CaseReaction],
                    outcomes: Dataset[CaseOutcome], formulary: Dataset[FormularyDrug]): Dataset[AdverseEventStat]
     def drugTotals(cases: Dataset[Case], drugs: Dataset[CaseDrug]): Dataset[DrugQuarterTotal]
     def reactionTotals(cases: Dataset[Case], reactions: Dataset[CaseReaction]): Dataset[ReactionQuarterTotal]
     def quarterTotals(cases: Dataset[Case]): Dataset[QuarterTotal]
   }
   ```

2. `caseFlags`: one row per case with an outcome. Every code S3 keeps is serious, so `serious = 1` for every row; `death = max(outcome == "DE")`.

3. `eventStats`:

   ```scala
   val q = cases.select("caseid", "quarter")
   val f = broadcast(formulary.select("rxcui").distinct())
   val w = Window.partitionBy("rxcui", "term").orderBy("quarter")
     .rowsBetween(Window.unboundedPreceding, Window.currentRow)

   drugs.join(f, "rxcui")                       // formulary only, before the big join
     .join(reactions, "caseid")
     .join(q, "caseid")
     .join(caseFlags(outcomes), Seq("caseid"), "left")
     .groupBy("rxcui", "term", "quarter")
     .agg(count("*").as("cases"),
          sum(coalesce(col("serious"), lit(0))).as("seriousCases"),
          sum(coalesce(col("death"), lit(0))).as("deathCases"))
     .withColumn("cumulativeCases", sum("cases").over(w))
   ```

   `count("*")` is a distinct case count only because `case_drug` is unique on (`caseid`, `rxcui`) and `case_reaction` on (`caseid`, `term`). Assert both in a test and do not add any join that could multiply rows. Quarter strings sort correctly as strings.

4. Background totals, same pattern without the formulary filter and without the cumulative window (rename `count` to `cases`):
   - `drugTotals`: `drugs.join(q, "caseid").groupBy("rxcui", "quarter").count()`.
   - `reactionTotals`: `reactions.join(q, "caseid").groupBy("term", "quarter").count()`.
   - `quarterTotals`: `cases.groupBy("quarter").count()` (about 50 rows).

5. `EventCountsStage`: `name = "signals.counts"`, `cadences = Set(Quarterly, Full)`. Cache `q` (two columns) since four aggregations use it. Write the four tables. Return `StageResult(rowsIn = rows in silver.case, rowsOut = rows in AdverseEventStat, rowsRejected = 0)`. The stage does not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics. No `Reject` rows: silver input is already clean.

6. Reconciliation, run inside the stage after writing; throw with a clear message if any fails:
   - `sum(QuarterTotal.cases) == count(silver.case)`.
   - `sum(ReactionQuarterTotal.cases)` equals the row count of `case_reaction` restricted to cases in `silver.case`.
   - For every `rxcui`: `sum(DrugQuarterTotal.cases) == countDistinct(caseid)` in `case_drug` for that drug (compare the two grouped tables with a join and count mismatches).
   - For every (`rxcui`, `term`, `quarter`): `cases <= DrugQuarterTotal.cases` and `seriousCases <= cases` and `deathCases <= seriousCases`.

7. `stages/signals.counts.conf`: `class = "medsignal.signals.counts.EventCountsStage"`, `after = ["bronze.formulary", "silver.case", "silver.case_drug", "silver.case_reaction", "silver.case_outcome"]`.

## Tests

`EventCountsSpec` (Spark, inline data; a formulary of drug A only):

- "counts distinct cases": 3 cases with drug A and NAUSEA in 2024Q1 give `cases = 3`.
- "a case with two reactions counts once in each": one case, A, NAUSEA and RASH gives two rows of 1, and `DrugQuarterTotal` for A is 1, not 2.
- "serious and death counts": of 3 cases, one `HO` and one `DE` plus `HO` give `seriousCases = 2`, `deathCases = 1`; a case with no outcome is not serious.
- "cumulative totals run over quarters": 2 cases in 2024Q1, none in Q2, 3 in Q3 give cumulative 2 then 5, and no Q2 row.
- "non-formulary drugs are absent from AdverseEventStat but present in DrugQuarterTotal".
- "reaction totals use all cases": a case with only a non-formulary drug still counts in `ReactionQuarterTotal` and `QuarterTotal`.
- "primary keys are unique" in all four tables.

`EventCountsStageSpec`: runs the stage on fixtures, checks the four tables exist and the reconciliation passes; then corrupts the input (a duplicate `case_drug` row) and expects the stage to fail.
