## Goal

Five pages the pharmacy safety officer uses each morning: Today, Signals, Drug drill-down, Recalls, Pipeline health. They are static HTML, CSS and plain JavaScript that call the A2 API. Each of her three questions is answered within two clicks of the landing page, and every signal states that reports are not proof of cause.

## Context

- Read `README.md` section "What it does" (the three questions), `docs/pipeline-spec.md` section 9 (the page table), `docs/contracts.md` section "HTTP API", and `docs/tasks/A2.md` section "Outputs" for the exact JSON shapes.
- No framework, no bundler, no build step, no external script or font. Files are served by the app from the classpath folder `web/` (A2's `StaticRoutes`). A page is plain HTML plus one script.
- The three questions and where each is answered:

  | Question | Answered on | Clicks from landing page |
  |---|---|---|
  | Which drugs have adverse events reported that the label does not mention? | Signals (default filter: unlabeled, open) | 1 |
  | Which drugs have an active recall? | Today (open Class I) and Recalls (all open) | 0 and 1 |
  | What has changed since yesterday? | Today | 0 |

- FAERS changes only quarterly, so most daily changes are label updates and recalls. Say so on Today (architecture.md, "Cadence").
- Label passages and recall text come from outside sources. Insert them with `textContent` or an escape function, never with raw `innerHTML`.
- Offsets: `LabeledReaction.startOffset` and `endOffset` are meant to locate the matched term for highlighting. contracts.md does not say whether they are relative to the passage or to the whole section text; check the L5 brief or code. The highlight function below handles both.

## Outputs

Pages, all with the same header navigation (Today, Signals, Recalls, Pipeline health):

1. **Today** (`index.html`). Three panels: change events since the last run, grouped by kind (`new_signal`, `signal_labeled`, `label_updated`, `recall_opened`, `recall_closed`), each linking to the drug drill-down when `rxcui` is present; freshness per source (stage name, `newestSourceDate`, time of last run, from `Health.metrics`); open Class I recalls. An empty panel says "No changes since the last run", not a blank space.
2. **Signals** (`signals.html`). Table ranked by score: drug, class, reaction term, cases (`a`), PRR, lower bound of the odds ratio, serious share, four-quarter growth, score, labeled status, triage status, flags (indication, spike). Filters: class (options taken from the loaded rows), labeled status (default `unlabeled`), triage status (default `open`). Changing a filter refetches. Each row links to the drill-down and has triage buttons Review, Escalate, Dismiss.
3. **Drug drill-down** (`drug.html?rxcui=<id>&term=<term>`). Left: list of the drug's signals; selecting one shows a bar chart of cases by quarter (inline SVG, serious cases as a second colour) and the score components. Right: the label evidence for that signal. When `labeledStatus` is `labeled` or `negated_only`, show the passage with the matched term highlighted and the label identity (`decidingSetId`, `decidingVersion`). When `unlabeled`, show "Not found in the sections searched:" and the list from `sectionsSearched`, with section names (34066-1 Boxed warning, 43685-7 Warnings and precautions, 34084-4 Adverse reactions, 34073-7 Drug interactions). When `no_label`, say no reference label was found. Triage buttons and a note field.
4. **Recalls** (`recalls.html`). Open recalls for formulary drugs: drug, classification, reason, firm, initiation date, link to the FDA record (`sourceUrl`, opened in a new tab with `rel="noopener"`). A toggle shows unresolved recalls (`unresolved=true`).
5. **Pipeline health** (`health.html`). Last run per stage with rows in, out, rejected and duration; check results; extraction scores per extractor version.

Fixed text shown wherever a signal appears (Signals, drill-down, the new-signal panel on Today): "Reports are not proof of cause. A signal is a prompt for review."

## Implementation steps

1. Write `common.js` first. `getJson` returns parsed JSON or throws an error carrying the HTTP status; every page shows a visible error banner when a call fails (for example "Serving database not published yet" on 503).
2. `highlightRange(passage, start, end, term)` returns `{before, match, after}`:
   - if `0 <= start < end <= passage.length` and `passage.slice(start, end)` equals the term ignoring case, use the offsets;
   - otherwise search the passage for the term ignoring case and use the first hit;
   - otherwise return the whole passage as `before` with an empty `match`.
   The page builds three text nodes with the middle one inside `<mark>`.
3. For a labeled signal the drill-down finds the matching `LabeledReaction` in `DrugDetail.labeledReactions` by `setId = decidingSetId`, `version = decidingVersion`, `term`. If none is found, fall back to `Signal.passage` and the text search.
4. `barChart`: one `<rect>` per quarter, x labels every fourth quarter, a y axis with three ticks, a `<title>` on each bar with the exact count. No library.
5. Triage: a button posts `{rxcui, term, decision, note, user}`; on 201 update the row's status in place. Ask for the user name once and keep it in `localStorage` (the project has no accounts).
6. Optional panels: call `/api/drugs/{rxcui}/trials` and `/api/exposure`; on 404 hide the panel or column without an error. When trial rows arrive, list trial id, affected and at-risk counts, and link each to `https://clinicaltrials.gov/study/<nctId>`. When exposure rows arrive, add a sortable column "Reports per 100,000 Part D claims".
7. Accessibility and layout: real `<table>`, `<th scope>`, `<label>` on filters, visible focus, status shown as text as well as colour, usable at 1280 px wide.

## Tests

ScalaTest cannot live inside the owned path, so testing is a browser self-test plus a click-through. (A2's specs already cover the endpoints.)

`selftest.html` runs these and prints pass or fail per line:

- `highlightRange("May cause pancreatitis.", 10, 22, "PANCREATITIS")` gives match `pancreatitis`.
- Offsets out of range with the term present: falls back to the text search.
- Term absent: empty match, whole passage returned.
- `escapeHtml("<script>")` gives `&lt;script&gt;`.
- `barChart` with 3 rows creates 3 bars (plus serious-case bars).

Click-through checklist, run against a published database, with a screenshot of each page in the pull request:

- [ ] Landing page shows changes, freshness and open Class I recalls with no click.
- [ ] One click on "Signals" shows unlabeled open signals ranked by score.
- [ ] One click on "Recalls" shows all open recalls; each links to the FDA record.
- [ ] From Signals, one click opens the drill-down with chart and passage side by side; the matched term is highlighted.
- [ ] An unlabeled signal shows the sections searched.
- [ ] Each filter (class, labeled status, triage status) changes the list.
- [ ] Dismissing a signal removes it from the default list and it stays removed after a reload.
- [ ] The disclaimer is visible on Signals, the drill-down and Today.
- [ ] A passage containing `<b>` shows as text.
- [ ] With the API stopped, every page shows an error banner, not a blank page.
- [ ] No request leaves the app's own host (browser network tab).
