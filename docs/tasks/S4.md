## Goal

`silver.label_version` holds one row per label version with its ingredient `rxcui` and effective date, and marks one reference label per ingredient. "Is this reaction on the label?" can only be answered once there is a single agreed label per drug; this task picks it by a fixed rule.

## Context

- One ingredient has many labels: one per manufacturer and product, each a `setId` with numbered versions.
- `bronze.label_section` has one row per section, so label metadata repeats on every section row of a version.
- Reference-label rule: the brand-name label where one exists, otherwise the most recent single-ingredient label.
- Names are resolved only through S2. This task never matches names itself.
- Read: `docs/contracts.md` (Bronze tables, Silver tables), `docs/ontology.md` (`Label`), `docs/data-issues.md` row 8, the S2 brief (`DrugIdentity.ensureResolved(names: Dataset[String])`).

## Implementation steps

1. One row per version: `distinct` on (`setId`, `version`, `effectiveDate`, `activeIngredients`, `isBrand`). If a (`setId`, `version`) still has more than one row (metadata disagrees between sections), keep the row from the lowest `loinc` and count the case.

2. Effective date. Uncertain: the format I5 writes. SPL uses `yyyyMMdd`; confirm by reading a few bronze rows. Parse to `java.sql.Date`; a value that does not parse makes the version a `Reject` (the column is not optional).

3. Ingredients. Collect every distinct string in `activeIngredients` into a `Dataset[String]` and call `DrugIdentity.ensureResolved(names)` (the signature in contracts.md, decision 10). Join back to get the set of ingredient `rxcui`s for each version.
   - No ingredient resolves: `Reject` with reason `label ingredient unresolved`.
   - Exactly one distinct `rxcui`: `isSingleIngredient = true`, `rxcui` is that one.
   - More than one: `isSingleIngredient = false`. The contract allows one `rxcui` per row, so store the formulary ingredient among them (if several or none are on the formulary, the lowest `rxcui` as a number). Such rows are never a reference label (contracts.md, decision 13: a combination label is never the reference).

4. Reference rule, decided per `rxcui` at the level of the `setId`:

   ```scala
   final case class SetSummary(setId: String, rxcui: String, isBrand: Boolean,
                               latestVersion: Int, latestEffectiveDate: java.sql.Date)
   object ReferenceLabel {
     def choose(candidates: Seq[SetSummary]): Option[String]   // the reference setId
     def mark(versions: Dataset[LabelVersion])(implicit spark: SparkSession): Dataset[LabelVersion]
   }
   ```

   - Candidates: `setId`s whose latest version is single-ingredient.
   - If any candidate has `isBrand` on its latest version, choose among those; otherwise among all candidates.
   - Within the chosen group: latest `latestEffectiveDate`, then lowest `setId`. The tie-break is only there to make the result repeatable; it is not a clinical judgement.
   - `isReference = true` on every version of the chosen `setId`, `false` elsewhere (contracts.md, decision 13). The current reference label is the highest version of that `setId`. Keeping the flag on all versions lets an as-of rebuild (the backtest, V1) pick the version that was current at an earlier date.

   In Spark: build `SetSummary` rows, `groupByKey(_.rxcui).mapGroups` calling `choose`, then a broadcast join back.

5. Rejects: `Reject(source = "labels", file = "bronze.label_section", line = 0, raw = s"$setId:$version", reason, runId)` (the input table name and line 0, contracts.md decision 7), written with `Rejects.write(rejects)`.

6. `LabelVersionStage`: `name = "silver.label_version"`, `cadences = Set(Daily, Full)`. Return `StageResult(rowsIn, rowsOut, rowsRejected)`: `rowsIn` distinct (`setId`, `version`) in bronze, `rowsOut` rows written, `rowsRejected` the `Reject` rows. The stage does not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics. Conf: `after = ["bronze.labels", "bronze.formulary", "identity.drug_xref"]` (I6's and F6's stage names as listed in contracts.md).

7. Missing list: left-anti join `bronze.formulary` against the `rxcui`s that have a reference label; log the ingredients and put them in the results file.

## Tests

`ReferenceLabelSpec` (pure):

- "brand wins over a newer generic": brand dated 2020 and generic dated 2024 give the brand.
- "most recent generic when no brand": two generics give the later date.
- "ties break on setId".
- "combination labels are never chosen": only a multi-ingredient label gives `None`.
- "no candidates gives None".

`LabelVersionsSpec` (Spark, fixture `label_section.jsonl`):

- "one row per setId and version" from four section rows.
- "every version of the reference setId is flagged": versions 1 to 3 of the chosen set are all `isReference`.
- "exactly one reference setId per ingredient".
- "an unresolved label is rejected, not dropped": one `Reject`, no row.
- "a bad effective date is rejected".
- "a two-ingredient label has isSingleIngredient false and isReference false".

## Done when

- [ ] Every formulary ingredient has exactly one reference `setId`, or appears in the missing list.
- [ ] Key (`setId`, `version`) is unique on the real data.
- [ ] `docs/results/S4.md` records: versions in bronze, rows written, rejects by reason, ingredients with more than one label `setId` (data issue 8), ingredients with more than one brand `setId`, the missing list, and the confirmed date format.
