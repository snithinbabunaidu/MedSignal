## Goal

A short written comparison of two ways to rank signals: the default score from G3 (built on the lower bound of the odds ratio) and the lower bound of the information component (IC025, a shrinkage measure). One ranking is named the default, with the reason. The project needs this so the ranking shown to the safety officer is a tested choice.

## Context

- The odds-ratio lower bound can still be large for pairs with very few cases. The information component adds 0.5 to observed and expected counts, which pulls small-count pairs towards zero.
- `IC = log2((a + 0.5) / (E + 0.5))`, `E = (a + b)(a + c) / N`. `IC025 = IC - 3.3 (a + 0.5)^(-1/2) - 2 (a + 0.5)^(-3/2)`. Both are in `medsignal.stats.Disproportionality` (G2). The IC025 formula is an approximation that G2 must have checked against a reference; read `docs/results/G2.md` first, and if that check is missing, do it before running this comparison.
- `gold.Signal` has no IC column and this task does not add one. IC025 is computed here from the stored `a, b, c, d`.
- This is an analysis job, not a pipeline stage. It writes no table and registers no file under `stages/`.
- Read: `docs/contracts.md` (Statistics, Gold `Signal`), the G2 and G3 briefs, `docs/results/G3.md`.

## Implementation steps

1. Three rankings, each a list of (`rxcui`, `term`) in order, top 100 kept:

   | Name | Population | Order |
   |---|---|---|
   | `score` | rows of `gold.Signal` | `score` descending |
   | `rorLower` | rows of `gold.Signal` | `rorLower` descending |
   | `ic025` | all formulary pairs with `a >= 3` and `ic025 > 0`, screened or not | `ic025` descending |

   Break ties by `a` descending, then `rxcui`, then `term`, so the lists are repeatable.

   ```scala
   final case class Ranked(rxcui: String, term: String, a: Long, value: Double, rank: Int)
   object ShrinkageRanking {
     def byScore(signals: Dataset[Signal], k: Int): Seq[Ranked]
     def byRorLower(signals: Dataset[Signal], k: Int): Seq[Ranked]
     def byIc025(pairs: Dataset[PairTable], k: Int): Seq[Ranked]
   }
   ```

   `byIc025` maps each `PairTable` to `Disproportionality.ic025(TwoByTwo(a, b, c, d))` in a typed `map`, filters, orders and takes `k`.

2. Comparison measures (pure):

   ```scala
   object RankingComparison {
     def overlap(x: Seq[Ranked], y: Seq[Ranked]): Int                 // pairs in both lists
     def jaccard(x: Seq[Ranked], y: Seq[Ranked]): Double              // overlap / size of union
     def spearman(x: Seq[Ranked], y: Seq[Ranked]): Option[Double]     // over pairs in both lists; None below 3 pairs
     def medianCases(x: Seq[Ranked]): Double                          // median a
     def smallCountShare(x: Seq[Ranked], below: Long = 5): Double     // share with a < 5
     def warningsHit(x: Seq[Ranked], warnings: Set[(String, String)]): Int
   }
   ```

   `spearman`: re-rank the common pairs 1 to n within each list, then `1 - 6 * sum(d^2) / (n (n^2 - 1))`.

3. Known warnings. From `bronze.fda_warning`, build the set of (`rxcui`, `term`): for `scope = "drug"`, `target` is the drug; for `scope = "class"`, expand `target` to every formulary drug whose `drugClass` equals it; one element per term in `terms`, upper-cased. `target` is an `rxcui` when `scope` is `drug` and a formulary `drugClass` when `scope` is `class` (contracts.md, decision 17), so match `rxcui` to `rxcui` and `target` to `FormularyDrug.drugClass`; `terms` is already a `Seq[String]` in bronze.

4. `ShrinkageComparisonJob.main(args)`: `args(0)` is the output path. Build the three lists and write Markdown: the measures for each pair of rankings, the per-list measures, the top 20 of each list side by side (drug name, term, `a`, value), and the pairs that are in one top 100 but not the other.

   Run with `sbt "pipeline/runMain medsignal.signals.shrinkage.ShrinkageComparisonJob docs/results/G4.md"` after a full run has produced gold. Then add the decision section by hand.

5. Decision rule, fixed before looking at the numbers:
   1. If warning data exists: the ranking with more known warnings in its top 100 wins, when the difference is at least 2.
   2. Otherwise, or on a tie: the ranking with the lower share of `a < 5` pairs in its top 100 wins, when the difference is at least 10 percentage points.
   3. Otherwise keep the G3 `score`: it is already built and its components are shown in the app.

   Write which rule decided and the numbers behind it.

6. If IC025 wins: do not change G3's code or `Signal` in this branch. State in `docs/results/G4.md` what the follow-up is: an `[Enhc]` pull request in `signals/signal/` to rank by IC025, and, if new columns are wanted on `Signal`, a `[Chore]` pull request on `docs/contracts.md` first.

7. No `RunMetrics` and no `Reject` rows: this job is not a stage and reads only gold.

## Tests

`RankingComparisonSpec` (pure):

- "overlap counts common pairs": lists sharing 3 of 5 give 3.
- "jaccard of identical lists is 1; of disjoint lists is 0".
- "spearman of the same order is 1; of the reversed order is -1".
- "spearman is undefined below three common pairs".
- "median cases" of 3, 5, 100 is 5.
- "small-count share": `a` values 3, 4, 10, 20 give 0.5.
- "warnings hit counts matching pairs only".

`ShrinkageRankingSpec` (Spark, inline data):

- "a three-case pair with a huge odds ratio ranks below a 300-case pair on IC025": `PairTable` for (3, 7, 10, 980) has `ic025` about 0.40; (300, 9700, 1000, 99000) has about 1.15; the second ranks first.
- "pairs with ic025 at or below zero are left out".
- "pairs with fewer than three cases are left out".
- "ties are broken by a, then rxcui, then term".
- "byScore returns at most k rows in descending order".
