## Goal

A pure function that says whether a matched reaction mention is negated by its sentence ("No cases of pancreatitis were observed"). Without it, a label that says a reaction did not occur would count as listing that reaction, and a real unlabeled signal would be hidden.

## Context

Read `docs/pipeline-spec.md` section 5 (step 5), `docs/data-issues.md` row 10 and `docs/tasks/L3.md` (type `Mention`).

- The method follows the idea of NegEx (Chapman and others, 2001): trigger phrases before or after a mention, a limited scope, and terminator words that end the scope. It is rule-based only: no language model, no parser, no embeddings.
- No Spark in this package. The function takes a sentence and offsets inside that sentence. L5 calls it inside a `map`.
- The trigger lists below are a starting set. Extend them from real label sentences, and bump `Version` with every change.

## Inputs

A sentence (`String`) and the start and end of the mention inside that sentence. From a `Mention` (L3): `matchStart - sentenceStart` and `matchEnd - sentenceStart`.

## Outputs

`Boolean` (negated or not), plus an explanation value for tests and debugging:

```scala
final case class NegationHit(trigger: String, kind: String)   // kind: "pre" or "post"
```

## Implementation steps

1. Signatures:
   ```scala
   object Negation {
     val Version: Int = 1
     val Window: Int = 6        // maximum number of tokens between trigger and mention
     def explain(sentence: String, mentionStart: Int, mentionEnd: Int): Option[NegationHit]
     def isNegated(sentence: String, mentionStart: Int, mentionEnd: Int): Boolean =
       explain(sentence, mentionStart, mentionEnd).isDefined
   }
   ```
2. Tokenize the sentence, lower-cased, with the regex `[a-z0-9]+(?:'[a-z]+)*|;`, keeping each token's start and end offset. `;` is its own token. This tokenizer is local to this package (it must keep `;`, which the dictionary tokenizer drops).
3. Lists in `NegationRules` (each phrase is a sequence of tokens):
   - Pre-triggers (negate what follows): `no`, `no cases of`, `no reports of`, `no evidence of`, `no occurrence of`, `not associated with`, `was not associated with`, `were not associated with`, `has not been associated with`, `have not been associated with`, `without`, `absence of`, `free of`, `did not cause`, `does not cause`, `did not result in`, `did not develop`, `did not experience`.
   - Post-triggers (negate what precedes): `was not observed`, `were not observed`, `was not reported`, `were not reported`, `was not seen`, `were not seen`, `did not occur`, `has not been observed`, `have not been observed`, `has not been reported`, `have not been reported`.
   - Pseudo-triggers (look like negation but are not): `no increase`, `no decrease`, `no change`, `no difference`, `no longer`, `not only`, `no dose adjustment`.
   - Terminators: `but`, `however`, `although`, `though`, `except`, `;`.
4. Mark phrases left to right. At each token position try pseudo-triggers first, then pre- and post-triggers; the longest phrase starting at that position wins and consumes its tokens (so the `no` inside `no increase` is not a trigger, and `no cases of` is one trigger, not `no` plus words). Tokens that lie inside the mention itself are never triggers (a term such as `NO ADVERSE EVENT` or `WITHOUT ...` must not negate itself).
5. Decide. Let the mention cover tokens `m1..m2` (tokens overlapping `[mentionStart, mentionEnd)`).
   - A pre-trigger ending at token `p < m1` negates the mention when no terminator lies in `p+1 .. m1-1` and `m1 - p - 1 <= Window`.
   - A post-trigger starting at token `q > m2` negates the mention when no terminator lies in `m2+1 .. q-1` and `q - m2 - 1 <= Window`.
   - Return the nearest qualifying trigger as `NegationHit`, pre before post on a tie. Otherwise `None`.
   The window stops "No dose adjustment is needed in patients with renal impairment" from negating `renal impairment`; lists such as "No cases of pancreatitis, hepatitis or renal failure" stay inside it.
6. Known limits to write down, not to solve: negation that spans sentences ("The following were not observed: ..." followed by a list on new lines), double negation, and "not" on its own. Collect real examples in `docs/results/L4.md`.
7. No `Reject`, no `RunMetrics`: this is a pure function.

## Tests

`NegationSpec` (no Spark). Helper: find the mention by `sentence.indexOf(mention)`.

- "negates after 'no cases of'": "No cases of pancreatitis were observed." / `pancreatitis` is negated (the sentence named in pipeline-spec.md).
- "negates a list after one trigger": "No reports of hepatitis, pancreatitis or renal failure." all three negated.
- "negates before 'was not observed'": "Hepatotoxicity was not observed in clinical trials." negated, kind `post`.
- "negates with 'not associated with'" and "with 'did not occur'": one sentence each.
- "terminator ends the scope": "No cases of pancreatitis were observed, but nausea was common." `pancreatitis` negated, `nausea` not.
- "semicolon ends the scope": "Rash was not reported; headache occurred in 5% of patients." `rash` negated, `headache` not.
- "however ends a post-trigger scope backwards": "Dizziness occurred; however, syncope was not observed." `syncope` negated, `dizziness` not.
- "window limits the scope": "No dose adjustment is needed in patients with renal impairment." not negated.
- "pseudo-trigger does not negate": "There was no increase in the incidence of nausea." not negated.
- "plain mention is not negated": "Pancreatitis has been reported."
- "trigger inside the mention is ignored".
- Table test over `L4/negation_cases.tsv`: every row gives the expected value.
