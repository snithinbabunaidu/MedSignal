## Goal

A command in the `labels` module that, for every formulary ingredient, finds its prescription drug labels on DailyMed and saves every available version as XML under `data/raw/dailymed/`, with set id, version and checksum recorded. Running it again fetches only what is new. Version history is what lets the backtest ask "was this reaction on the label at that time".

## Context

Read `docs/data-sources.md` (DailyMed row), `docs/contracts.md` (Paths), `docs/pipeline-spec.md` section 6 (Labels row), `docs/data-issues.md` issue 8 and `docs/tasks/F6.md` (formulary columns).

The `labels` module is Scala 3 and cannot use `pipeline` classes or the pipeline's common library, so there is no `RunManifest`, `Stage` or `Rejects` here (contracts.md, decision 5). "The manifest" is a plain TSV next to the downloads, `data/raw/dailymed/manifest.tsv`, kept by this task. There is also no `application.conf` in this module: settings come from command-line options with defaults, starting with `--data-dir`. For the same reason this command cannot read the Delta table `bronze.formulary`; it reads the committed `formulary.csv` under `<dataDir>/reference/`. The command is run before the pipeline's daily run by `scripts/run-labels.sh`, which C3 owns; do not create that script here.

DailyMed web services v2, base `https://dailymed.nlm.nih.gov/dailymed/services/v2`. Documentation: `https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm`. Everything below is believed, not verified; make each call once by hand and save the response as a fixture before coding:

- List labels: `GET /spls.json?drug_name=<name>&pagesize=100&page=<n>` returns `metadata` (`total_elements`, `total_pages`, `current_page`) and `data[]` with `setid`, `spl_version`, `title`, `published_date`. A `name_type` option may restrict to generic names. Check whether a filter for document type exists.
- Version history: `GET /spls/{setid}/history.json` returns the list of `spl_version` and `published_date`.
- Current XML: `GET /spls/{setid}.xml`.
- A specific older version: believed to be `https://dailymed.nlm.nih.gov/dailymed/getFile.cfm?setid={setid}&type=zip&version={n}`, a zip holding one `.xml` plus images. Confirm that old versions are really served; if only some are, record how many are missing.

Volume risk: over-the-counter products (pain relievers, antihistamines) have thousands of labels. Keep human prescription labels only: document type code `34391-3` at `document/code/@code` in the XML. If the list call cannot filter by type, fetch the current XML first and skip the set id when the code differs. Run `--list-only` first and report the counts before downloading everything.

## Inputs

- `<dataDir>/reference/formulary.csv` (columns `rxcui,ingredient,drugClass,reason`).
- DailyMed services.

## Outputs

```
data/raw/dailymed/<setId>/<version>.xml
data/raw/dailymed/manifest.tsv
data/raw/dailymed/skipped.tsv        (setId, ingredient, reason)
```

`manifest.tsv`: tab-separated with header, one row per saved file: `setId`, `version`, `rxcui` (formulary ingredient that led here), `ingredient`, `publishedDate`, `bytes`, `sha256`, `downloadedAt`, `file`. Rewritten atomically after each set id.

## Implementation steps

1. Options: `--data-dir <path>` (default: system property `medsignal.dataDir`, else environment `MEDSIGNAL_DATA_DIR`, else `data`), `--list-only`, `--ingredient <name>` (one ingredient), `--max-setids <n>` (0 means no limit), `--requests-per-second <n>` (default 4).
2. `DailyMedApi`:
   ```scala
   final case class SplRef(setId: String, currentVersion: Int, title: String, publishedDate: String)
   final case class SplVersion(version: Int, publishedDate: String)
   def listUrl(ingredient: String, page: Int): String        // URL-encode the name
   def decodeList(json: String): Either[String, (Seq[SplRef], Int)]   // refs and total pages
   def historyUrl(setId: String): String
   def decodeHistory(json: String): Either[String, Seq[SplVersion]]
   def versionUrl(setId: String, version: Int): String
   ```
3. `Http`: one shared client, a simple rate limiter, retries with a doubling pause on 429, 5xx and timeouts, a `User-Agent` such as `medsignal-course-project`. HTTP 404 is returned as `Left` without retry.
4. `DailyMedDownloader.run(http, dataDir, options): Summary` with `Summary(ingredients, setIds, versionsListed, downloaded, alreadyPresent, skipped, failed)`:
   - for each formulary row, page through the list until `total_pages`; a set id seen under two ingredients is downloaded once and keeps the first ingredient;
   - apply the prescription-only rule; write non-prescription set ids to `skipped.tsv`;
   - get the history; for each version not in the manifest (key `setId` + `version`, and the file exists), fetch it; if the response is a zip, extract the single `.xml` entry and discard images;
   - check the saved XML's `setId` and `versionNumber` match what was requested (a cheap regex or `scala.xml`-free string scan is enough; full parsing is I5); a mismatch is a failure;
   - a failed version is recorded in `failed` and does not stop the run; the exit code is non-zero if anything failed;
   - an ingredient with no prescription label is listed in the summary.
5. `--list-only` prints per ingredient: set ids, versions, and totals, without downloading XML beyond what the prescription check needs.
6. Run: `sbt "labels/runMain medsignal.download.DailyMedDownloader --list-only"`.
7. No `var`, no `null`; errors as `Either`.

## Tests

- `DailyMedApiSpec`: "decodes a list page to refs and total pages"; "decodes history to versions in order"; "URL-encodes an ingredient with a space".
- `LabelManifestSpec`: "write then read returns the same rows".
- `DailyMedDownloaderSpec` (fake `Http` serving fixtures, temp folder): "follows paging across two pages"; "saves each version under setId/version.xml"; "extracts the XML from a zip and drops images"; "second run downloads nothing"; "skips a non-prescription label and records it"; "a set id found under two ingredients is saved once"; "a 404 for one version is reported and the rest continue"; "--list-only writes no label files".
