## Goal

Gold table `Signal` holds one row per formulary drug and reaction that passes the statistical screen, with its 2x2 counts, statistics, a ranking score with every component stored, the first quarter it would have been flagged, and two caution flags. This is the list the safety officer works from.

## Context

- 2x2 table per drug and reaction: `a = n_dr`, `b = n_d - a`, `c = n_r - a`, `d = N - n_d - n_r + a`. Background is all of FAERS; rows are kept only for formulary drugs.
- Screen: PRR >= 2, chi-square >= 4, a >= 3 (the same rule as `Disproportionality.isCandidate`; the three thresholds are read from config, see step 8).
- No cross join of drugs and reactions. Only pairs that occur together exist as rows.
- The score formula is not fixed in the project documents. This brief defines the default; G4 compares it with a shrinkage ranking and may propose a change.
- Label columns and triage status belong to other tasks. `Signal` is rebuilt in full by this stage on every run with `labeledStatus = no_label` and `triageStatus = open`; `labeltext.status` (L5) and `triage.status` (A4) run after it and re-apply their columns (contracts.md, decision 16).
- Read: `docs/contracts.md` (Gold tables `Signal`, Statistics), `docs/pipeline-spec.md` section 4, `docs/ontology.md` (`Signal`), `docs/data-issues.md` rows 11 and 12, the G1 and G2 briefs.

## Implementation steps

1. 2x2 tables (`PairTables.build`), cumulative over all quarters:

   ```scala
   def build(stat: Dataset[AdverseEventStat], drugQ: Dataset[DrugQuarterTotal],
             reacQ: Dataset[ReactionQuarterTotal], totalQ: Dataset[QuarterTotal],
             formulary: Dataset[FormularyDrug]): Dataset[PairTable]

   val pair = stat.groupBy("rxcui", "term")
     .agg(sum("cases").as("nDr"), sum("seriousCases").as("seriousCases"))        // aggregation 1
   val drug = drugQ.groupBy("rxcui").agg(sum("cases").as("nD"))                  // aggregation 2
     .join(broadcast(formulary.select("rxcui").distinct()), "rxcui")             // about 150 rows
   val reac = reacQ.groupBy("term").agg(sum("cases").as("nR"))                   // aggregation 3
   val n    = totalQ.agg(sum("cases")).as[Long].head()

   pair.join(broadcast(drug), "rxcui")      // broadcast lookup, no shuffle
       .join(reac, "term")                  // the one real join
   ```

   Then map each row through `TwoByTwo.fromMarginals(n, nD, nR, nDr)`. `None` (a negative cell) means the inputs are inconsistent: fail the stage with the offending row in the message. The spec's "three aggregations and one join" counts the join to the reaction marginals; the two broadcast joins against 150 formulary rows are lookups.

2. Screen and statistics. Keep a pair when it passes the screen (`SignalSettings.passes`, step 8; identical to `isCandidate` under the default thresholds) and `ror` and `rorInterval` are defined (`Signal` columns are not optional). Pairs with `a >= 3` that drop out only because `b == 0` or `c == 0` are extreme, not weak: count them, log them, and list them in the results file. They are not `Reject` rows.

3. Score (pure, default subject to G4's comparison):

   ```scala
   object Score {
     def seriousShare(seriousCases: Long, a: Long): Double            // seriousCases / a, 0.0 when a == 0
     def growthFactor(growth4q: Double, growthCap: Double): Double    // 1 + min(max(growth4q, 0), growthCap)
     def score(rorLower: Double, seriousShare: Double, growth4q: Double, growthCap: Double): Double
   }
   // score = rorLower * (1 + seriousShare) * (1 + min(max(growth4q, 0), growthCap)); growthCap comes from config, default 1.0
   ```

   - `rorLower`: lower end of the 95% odds-ratio interval. It is the base because it shrinks towards 1 when counts are small.
   - `seriousShare`: cumulative `seriousCases / a`, between 0 and 1. A signal made only of serious cases ranks twice as high as one with none.
   - `growth4q`: defined in step 4. Falling counts do not lower the score; growth is capped at 1 so that a pair going from 0 to a handful of cases cannot dominate. Each factor is between 1 and 2, so the base statistic leads.
   - Stored components: `rorLower`, `seriousShare`, `growth4q` (uncapped), `score`. The app can recompute the score from the row.

4. Trend (pure, over the pair's cases per quarter; a missing quarter is 0):

   ```scala
   object Trend {
     def growth4q(quarters: Seq[String], cases: Map[String, Long]): Double
     def spike(quarters: Seq[String], cases: Map[String, Long], minCases: Long, ratio: Double): Boolean
     def firstFlagged(quarters: Seq[String], pair: Map[String, Long], drug: Map[String, Long],
                      reaction: Map[String, Long], total: Map[String, Long],
                      passes: TwoByTwo => Boolean): Option[String]   // passes = SignalSettings.passes
   }
   ```

   `quarters` is the sorted list of all quarters in `QuarterTotal`; `L` is its last element.
   - `growth4q = (recent - prior) / max(prior, 1)`, where `recent` is the sum over the last four quarters (L-3 to L) and `prior` the sum over the four before (L-7 to L-4). With fewer than eight quarters, use what exists; with fewer than five, 0.0.
   - `spike`: true when, for any quarter `q` in the last four, `cases(q) >= 5` and `cases(q) >= 3 * max(cases(q-1), 1)`. The 5 and the 3 are the config values `spike.minCases` and `spike.ratio` (step 8), passed in as arguments.
   - `firstFlagged`: walk the quarters in order keeping running sums of the four series; at each quarter build `TwoByTwo.fromMarginals` from the running sums and return the first quarter where `passes` (the configured screen) is true. This uses today's deduplicated data bucketed by quarter. It is an approximation; the exact as-of rebuild from the data available at the time is V1.

5. Assembling the series without a cross join (`SignalBuilder.build`): for candidate pairs only, `groupBy("rxcui", "term").agg(collect_list(struct("quarter", "cases")))` on `AdverseEventStat`; the same `collect_list` by `term` on `ReactionQuarterTotal`, joined on `term` to the candidates; `DrugQuarterTotal` for formulary drugs and `QuarterTotal` collected to the driver and broadcast as maps. Then a typed `map` calls the `Trend` functions.

6. `indicationFlag`: true when `silver.case_indication` has at least 3 distinct cases with the same (`rxcui`, `term`). Left join the candidates to `caseIndication.groupBy("rxcui", "term").agg(countDistinct("caseid"))`. The 3 is the config value `indication.minCases` (step 8).

7. Defaults for columns owned by other tasks: `labeledStatus = "no_label"`, `decidingSetId = None`, `decidingVersion = None`, `passage = None`, `sectionsSearched = Seq.empty`, `triageStatus = "open"`. This stage rebuilds `Signal` in full on every run (`Delta.overwrite`), always with these defaults. `labeltext.status` (L5, the label columns) and `triage.status` (A4, `triageStatus`) run after `signals.signal` on every run and re-apply their columns with `Delta.merge` on (`rxcui`, `term`) (contracts.md, decision 16). Neither edits this task's code, and this task does not read the previous `Signal` table to preserve their values.

8. Thresholds and score constants are read from `Settings.config`, never hard-coded; their defaults live in this task's own `pipeline/src/main/resources/conf.d/G3.conf` (contracts.md, decision 9). `application.conf` is owned by F3; do not add keys to it.

   ```
   medsignal.signals.screen     { minPrr = 2.0, minChiSquare = 4.0, minCases = 3 }
   medsignal.signals.score      { growthCap = 1.0 }
   medsignal.signals.spike      { minCases = 5, ratio = 3.0 }
   medsignal.signals.indication { minCases = 3 }
   ```

   ```scala
   final case class SignalSettings(minPrr: Double, minChiSquare: Double, minCases: Long, growthCap: Double,
                                   spikeMinCases: Long, spikeRatio: Double, indicationMinCases: Long) {
     def passes(t: TwoByTwo): Boolean   // a >= minCases, prr defined and >= minPrr, chiSquare defined and >= minChiSquare
   }
   object SignalSettings { def load(config: com.typesafe.config.Config): SignalSettings }
   ```

   `SignalStage` calls `SignalSettings.load(Settings.config)` once and passes the values to the pure functions, which take them as arguments. `passes` uses `Disproportionality.prr` and `chiSquare` from G2; a spec asserts it agrees with `Disproportionality.isCandidate` under the defaults.

9. `SignalStage`: `name = "signals.signal"`, `cadences = Set(Quarterly, Full)`. Return `StageResult(rowsIn = pair tables built, rowsOut = signals written, rowsRejected = 0)`. The stage does not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics. Conf: `class = "medsignal.signals.signal.SignalStage"`, `after = ["bronze.formulary", "signals.counts", "silver.case_indication"]`.

## Tests

- `ScoreSpec` (with `growthCap = 1.0`): "serious share" (30 of 40 gives 0.75); "score multiplies the components" (`rorLower = 2.0`, share 0.5, growth 0.25 gives 3.75); "negative growth does not lower the score" (growth -0.8 gives 3.0); "growth is capped" (growth 9.0 gives 6.0).
- `TrendSpec`: "growth over eight quarters" (prior 10, recent 15 gives 0.5); "growth from zero" (prior 0, recent 4 gives 4.0); "spike in the last four quarters" (2, 2, 9, 3 is true; 4, 5, 6, 7 is false; 1, 4, 1, 1 is false because 4 is below 5); "first flagged quarter" (a series that reaches `a = 3` with PRR above 2 in the third quarter returns that quarter; a series that never passes returns `None`).
- `PairTablesSpec` (Spark): "builds the worked example" (N 110,000, drug 10,000, reaction 1,300, both 300 gives `PairTable(.., 300, 9700, 1000, 99000, ..)`); "non-formulary drugs are dropped"; "pairs that never co-occur produce no row"; "inconsistent marginals fail the build".
- `SignalBuilderSpec` (Spark, small fixture): "only screened pairs are written"; "every stored score equals Score.score of its stored components"; "indication flag needs three cases"; "defaults are set for label and triage columns" (`no_label` and `open` on every row, also when the table already held other values before the run); "the configured screen agrees with isCandidate under the defaults"; "thresholds come from config" (a `SignalSettings` with `minCases = 10` drops a pair with `a = 5`); "primary key is unique".
