## Goal

A written decision, backed by timings, on which parser reads the bulk FAERS files: TableParser's row parser running inside Spark executors, or Spark's CSV reader with TableParser kept for the small files. I2 is built on this decision, so the record must also give I2 a working code pattern.

## Context

Read `docs/pipeline-spec.md` section 1 (the sketch is unconfirmed), `docs/architecture.md` ("How the professor's libraries are used"), `docs/project-plan.md` (Risks, first row) and `docs/contracts.md` (`FaersDrug`, `Reject`).

TableParser 1.7.2 is by Prof. Robin Hillyard: `github.com/rchillyard/TableParser`, branch `1.x`, Scala 2.13, packages `com.phasmidsoftware.tableparser.core` and `.spark`. What we believe, not yet verified: the `spark` package has a `DatasetMapper` that applies a `String => Try[T]` row parser over `spark.read.textFile`. Read the source and its tests before writing code; the exact class names for building a row parser from a header (likely around `RowParser`, `StandardRowParser`, `LineParser`, `CellParsers`, `ColumnHelper`, `Header`) must be taken from the source, not from this brief.

FAERS facts: files are `$`-delimited text with a header row; one zip per quarter from `https://fis.fda.gov/extensions/FPD-QDE-FAERS/FPD-QDE-FAERS.html`. Inside each zip the DRUG file is named like `DRUG24Q3.txt` (folder and letter case vary by year). Expected DRUG header: `primaryid$caseid$drug_seq$role_cod$drugname$prod_ai$val_vbm$route$dose_vbm$cum_dose_chr$cum_dose_unit$dechal$rechal$lot_num$exp_dt$nda_num$dose_amt$dose_unit$dose_form$dose_freq`; confirm it on both quarters. Drug names contain unbalanced double quotes, so quoting must be switched off in both parsers (Spark: `.option("quote", "")`), otherwise rows are silently merged.

I1 does not exist yet: download two zips by hand, 2014Q3 and the latest quarter, into `data/raw/faers/`.

## Implementation steps

1. Row parser. `def parser(header: String): String => Try[DrugRow]`. Columns are found by header name, not position. Optional fields (`prod_ai`) parse an empty cell to `None`. Delimiter `$`, no quote handling.
2. Run it in Spark:
   ```scala
   val lines  = spark.read.textFile(path)
   val header = lines.first()
   val parsed = lines.filter(_ != header).mapPartitions { it =>
     val p = TableParserDrugParser.parser(header)   // built on the executor
     it.map(line => p(line).toEither.left.map(_.getMessage))
   }
   ```
   Then try the library's own `DatasetMapper` and note which form is simpler.
3. Answer each question with evidence:
   - **Serialization.** Does the parser serialize into the closure? If not, does building it inside `mapPartitions` (as above) work? Record the exception text if any.
   - **Encoder.** Spark has no built-in `Encoder` for `Either`. Find what works: a wrapper `case class Parsed(row: Option[DrugRow], error: Option[String])`, or a tuple of two `Option`s. I2 needs one typed pass that yields rows and rejects.
   - **Header by name.** The same parser code must read both quarters. List the header of each and any difference.
   - **Line numbers.** `Reject.line` needs the line number. Test `spark.read.textFile(path).rdd.zipWithIndex()` on one file and confirm the index follows file order; record its cost.
   - **Bad lines.** Count failures on both real files and give the three most common failure messages. Lines broken by an embedded line break are expected (data-issues.md, issue 3).
   - **Encoding.** Check for non-ASCII bytes (`grep -P '[^\x00-\x7F]'`). If present, note whether the files are Latin-1 or UTF-8 and what `textFile` does with them.
   - **Throughput.** Time, three runs each after one warm-up, on the latest quarter's DRUG file with `local[8]`: (a) TableParser in `mapPartitions`, (b) `spark.read.option("sep","$").option("header",true).option("quote","").schema(...).csv` with `mode=PERMISSIVE` and a corrupt-record column, (c) plain `textFile.count()` as the floor. Force full evaluation with a `count` on the parsed rows. Report rows, seconds, rows per second, and check (a) and (b) give the same row count.
4. Decision rule. Extrapolate (a) to all quarters (about 45; five files each). If the full FAERS parse fits in roughly 15 minutes on 8 cores (criterion 3 allows 45 minutes for the whole rebuild), choose TableParser for bulk FAERS. Otherwise choose Spark's CSV reader for bulk FAERS and TableParser for RxNorm, Part D and the reference CSVs (the fallback in project-plan.md). Either way, describe how rejects with file, line and reason are produced under the chosen parser.
5. Write the decision record: Context, Options, Measurements (table), Choice, Why, Consequences for I2 (the code pattern, the wrapper type, how line numbers are obtained), Open issues. If contracts.md needs a change, list it; that is a separate `[Chore]` pull request.
