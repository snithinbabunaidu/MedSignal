## Goal

One pipeline stage, `changes.events`. At the end of each run it compares the signals, labels and recalls with their state at the end of the previous run and appends one `ChangeEvent` row per difference to `gold.ChangeEvent`. The "Today" page of the application is this table.

## Context

Read `docs/contracts.md` (Gold `ChangeEvent`, `Signal`, `Label`, `Recall`; Common library; the final section, items 1, 2, 6, 9 and 16), `docs/pipeline-spec.md` section 7, and briefs `docs/tasks/G3.md`, `L5.md`, `S4.md`, `S5.md`, `C1.md`.

Facts and decisions this brief fixes:

- Rule-based comparison of two table states. No model of any kind.
- "Previous run" means the state this stage saw the last time it ran, not the previous Delta version. `gold.Signal` is written three times per run (`signals.signal`, then `labeltext.status`, then `triage.status`), so "version minus one" is the wrong state.
- Preferred mechanism: Delta time travel. After computing events, the stage stores the current Delta version of each compared table in `RunManifest` (source `changes`, unit = table name, watermark = version number). The next run reads that version as "before". The exact API for the current version (`DeltaTable.history`) and for reading an old version (`versionAsOf` read option) must be checked against the Delta Lake documentation for the version in `build.sbt`; do not write it from memory.
- Fallback, if time travel is unreliable (history removed by vacuum or by an overwrite): the stage keeps its own snapshot tables `Tables.ops("changes_snapshot_signal")`, `..._label`, `..._recall`, overwritten at the end of each run with the compared columns only. Choose one mechanism, say which in `docs/results/C4.md`, and keep the comparison code independent of it (step 2).
- Sources. Signals: `Tables.gold("Signal")`. Labels: `Tables.gold("Label")` if `Delta.exists`, otherwise `Tables.silver("label_version")`. Recalls: `Tables.gold("Recall")` if it exists, otherwise `Tables.silver("recall")`. No backlog task is named as the writer of `gold.Label` and `gold.Recall`; the silver tables have every column the rules need. Record which were used.
- Case classes `Signal`, `LabelVersion`, `RecallClean` are defined by G3, S4 and S5; import them. `ChangeEvent` is defined here.
- The first run (no stored version, no snapshot) produces no events; it only stores the state.

## Implementation steps

1. Rules, each a function of (before, after) datasets returning `Dataset[ChangeEvent]`. Joins are full outer joins on the key.

   | kind | Fires when | objectKey | before | after |
   |---|---|---|---|---|
   | `new_signal` | (`rxcui`, `term`) is in `Signal` now and was absent before | `rxcui\|term` | None | `score`, formatted to 3 decimals |
   | `signal_labeled` | key present in both; `labeledStatus` was `unlabeled` and is now `labeled` | `rxcui\|term` | `unlabeled` | `labeled` |
   | `label_updated` | for a `setId` with `isReference = true` now, max `version` now is greater than max `version` before; the `setId` must have existed before | `setId` | old max version | new max version |
   | `recall_opened` | `recallNumber` absent before, and status now is not a closed status | `recallNumber` | None | status now |
   | `recall_closed` | `recallNumber` present in both; status before was not closed and status now is closed | `recallNumber` | status before | status now |

   A recall that first appears already closed produces no event. A signal that disappears produces no event. `rxcui` is filled for every kind where the row has one.
2. `PreviousState`:
   ```scala
   trait PreviousState {
     def before[T: Encoder](table: String, path: String)(implicit spark: SparkSession): Option[Dataset[T]]
     def remember(table: String, path: String)(implicit spark: SparkSession): Unit
   }
   ```
   `before` returns `None` on the first run.
3. `ChangeEventStage` (`name = "changes.events"`, `cadences = Set(Daily, Weekly, Quarterly, Full)`):
   1. For each of the three tables, get `before`. If any is `None`, call `remember` for all three and return `StageResult(0, 0, 0)`.
   2. Apply the five rules, union, set `runDate` to the date in `ctx.runId` (UTC).
   3. Idempotence: drop events whose (`runDate`, `kind`, `objectKey`) is already in the table, then `Delta.append`.
   4. Call `remember` only after the append succeeds.
   5. Return `StageResult(rowsIn = rows compared now, rowsOut = events appended, 0)`. Do not call `RunMetrics.record`; the runner records.
4. `stages/changes.events.conf`:
   ```hocon
   class = "medsignal.changes.ChangeEventStage"
   after = ["signals.signal", "labeltext.status", "triage.status", "silver.label_version", "silver.recall"]
   always = true
   ```

## Tests

`ChangeRulesSpec` (`SparkTestSession`, hand-made rows): one test per kind that fires, and one per kind that must not fire (signal present on both days; `no_label` to `labeled`; new version of a non-reference label; new recall already terminated; recall terminated on both days).

`ChangeEventStageSpec`:

- "first run produces no events".
- "a replayed day with a known new recall and a known label update yields exactly those events": load `C4/day1`, run; load `C4/day2` (one new ongoing recall, one new version of a reference `setId`, nothing else changed), run; the table holds exactly two rows, `recall_opened` and `label_updated`, with the expected keys.
- "re-running the same day adds nothing".
- "a signal rebuilt by signals.signal with the same rows yields no events": overwrite `gold.Signal` with identical rows between runs.
