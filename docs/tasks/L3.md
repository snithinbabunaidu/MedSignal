## Goal

A matcher that finds dictionary terms in label sentences and reports each match with its offsets in the section text. It builds a token trie on the driver, broadcasts it, and applies it in a typed `mapPartitions`. This is the step that turns label prose into reaction mentions.

## Context

Read `docs/pipeline-spec.md` section 5 (step 4), `docs/tasks/L1.md` (type `LabelSentence`, offsets) and `docs/tasks/L2.md` (types `ReactionDictionary`, `DictionaryEntry`, `Token`; `Normalizer.tokenize`).

- Rule-based only: exact match of normalized token sequences. No fuzzy matching, no language model, no embeddings.
- Sentence tokens must be produced by `Normalizer.tokenize` from L2, the same function that built the dictionary keys. Do not write a second tokenizer.
- Library only: no stage, no table. L5 calls `Matcher.run`. This task also adds one runnable object for a one-off count over all labels.

## Inputs

- `Dataset[LabelSentence]` from `Sentences.split` (L1).
- `ReactionDictionary` from `DictionaryLoader.load` (L2).

## Outputs

No table. Types in `medsignal.labeltext.matcher`:

```scala
final case class TrieNode(children: Map[String, TrieNode], term: Option[String])
final case class Trie(root: TrieNode)

final case class Mention(setId: String, version: Int, loinc: String, sentenceIndex: Int,
                         term: String,
                         matchStart: Int, matchEnd: Int,           // offsets of the matched words in the section text
                         sentenceStart: Int, sentenceEnd: Int,     // offsets of the sentence in the section text
                         sentence: String)
```

## Implementation steps

1. `Trie.build(entries: Seq[DictionaryEntry]): Trie`: fold the entries into an immutable tree; each step copies the nodes on one path. `term` is set on the node where a key ends. Case classes holding a `Map` are serializable; check with a test that round-trips the trie through Java serialization.
2. Pure matching:
   ```scala
   object Matcher {
     val Version: Int = 1
     final case class TokenMatch(firstToken: Int, lastToken: Int, term: String)
     def matchTokens(trie: Trie, tokens: IndexedSeq[String]): Seq[TokenMatch]
     def matchSentence(trie: Trie, s: LabelSentence): Seq[Mention]
     def run(sentences: Dataset[LabelSentence], trie: Broadcast[Trie])
            (implicit spark: SparkSession): Dataset[Mention]
   }
   ```
   `matchTokens` is leftmost-longest and non-overlapping:
   - At token position `i`, walk the trie along tokens `i, i+1, ...` as far as children exist, remembering the last position `j` whose node has a `term`.
   - If one was found, emit `TokenMatch(i, j, term)` and continue at `j + 1`.
   - Otherwise continue at `i + 1`.
   Write it as a tail-recursive function. With `ACUTE KIDNEY INJURY` and `KIDNEY INJURY` both in the dictionary, "acute kidney injury" yields one match, the longer one.
3. `matchSentence`: `tokens = Normalizer.tokenize(s.text)`; run `matchTokens` on the `norm` values; for each match
   `matchStart = s.startOffset + tokens(first).start`, `matchEnd = s.startOffset + tokens(last).end`, `sentenceStart = s.startOffset`, `sentenceEnd = s.endOffset`, `sentence = s.text`.
4. `run`:
   ```scala
   sentences.mapPartitions { rows =>
     val t = trie.value                    // read once per partition
     rows.flatMap(s => Matcher.matchSentence(t, s))
   }
   ```
   The caller builds the trie on the driver and broadcasts it: `spark.sparkContext.broadcast(Trie.build(dict.entries))`. Do not capture the trie in the closure without the broadcast.
5. `MatchAllLabels` (an `object` with `main`, not a `Stage`): read `bronze.label_section`, `silver.label_version` and `silver.case_reaction` with `Delta.read` and `Tables`; call `Sentences.select`, `Sentences.split`, `DictionaryLoader.load`, `Matcher.run`; print the number of sentences, mentions, distinct terms, mentions per LOINC code, the 30 most frequent terms, and the wall time. It writes nothing. Paste the output into `docs/results/L3.md`. Look at the frequent terms: common words that are also FAERS terms (for example `FALL`, `PAIN`, `SHOCK`) will show here; list them for L2's stop list or synonym file rather than patching the matcher.
6. No `Reject` and no `RunMetrics` here: a sentence with no match is normal, not unusable. L5 returns the counts in its `StageResult`.

## Tests

`TrieSpec`:

- "finds a term at the end of its key path".
- "survives Java serialization": serialize and deserialize; lookups still work.

`MatcherSpec` (no Spark; dictionary built from a few terms through `ReactionDictionary.build`):

- "matches a single-word term": "Pancreatitis has been reported." gives `PANCREATITIS`.
- "matches plural and case variants": "severe headaches" gives `HEADACHE`.
- "longest match wins": dictionary `KIDNEY INJURY`, `ACUTE KIDNEY INJURY`; "acute kidney injury occurred" gives one mention, `ACUTE KIDNEY INJURY`.
- "matches word-order variants": dictionary `BLOOD GLUCOSE INCREASED`; "increased blood glucose" matches.
- "matches a synonym to its term": synonym `low blood sugar` gives `HYPOGLYCAEMIA`.
- "finds two mentions in a list": "nausea, vomiting and rash" gives 3 mentions in order.
- "does not match across a partial word": dictionary `RASH`; "crash" gives nothing.
- "offsets point at the matched words": for a `LabelSentence` with `startOffset = 40`, `sectionText.substring(matchStart, matchEnd)` equals the words as written (for example `Headaches`), and `substring(sentenceStart, sentenceEnd)` equals the sentence.

`MatcherSparkSpec` (`SparkTestSession`, fixture `L3/sentences.jsonl`):

- "runs with a broadcast trie over two partitions": repartition to 2; the mention count equals the count from the pure function.
