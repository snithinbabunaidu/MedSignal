## Goal

A pipeline stage that downloads openFDA drug enforcement (recall) records, the bulk file for history and the API for weekly updates, and keeps them in `bronze.recall_raw` with an explicit schema. The record count matches the total openFDA reports for the same date range. Recalls feed the recall page and the weekly change feed.

## Context

Read `docs/contracts.md` (bronze `recall_raw`, Common library), `docs/pipeline-spec.md` sections 1 and 6 (Recalls row), `docs/data-sources.md` (openFDA row), `docs/data-issues.md` issue 13 and `https://open.fda.gov/apis/drug/enforcement/`.

Believed facts; make each call once by hand, save the response as a fixture, and correct this list in the results file:

- Bulk index: `GET https://api.fda.gov/download.json`; the zip URLs are at `results.drug.enforcement.partitions[].file`. Each zip holds one JSON document `{ "meta": {...}, "results": [ {...}, ... ] }`. It is one multi-line document, not JSON Lines.
- API: `GET https://api.fda.gov/drug/enforcement.json?search=report_date:[20240101+TO+20241231]&limit=1000&skip=0`. `meta.results.total` is the number of matches. `limit` is believed capped at 1000 and `skip` at 25000; without an API key the daily request allowance is small. A key is optional (`medsignal.openfda.apiKey`, sent as `api_key=`); never commit it.
- Record fields we use: `recall_number`, `classification` (`Class I`, `Class II`, `Class III`), `status` (`Ongoing`, `Completed`, `Terminated`), `reason_for_recall`, `product_description`, `recalling_firm`, `recall_initiation_date`, `report_date`, `termination_date` (often absent), and `openfda.rxcui` (an array, absent on most records). Dates are `yyyyMMdd` strings and stay strings in bronze.

`recall_raw` is the one bronze table that is not append-only (contracts.md, Bronze tables): the source re-publishes changed records, so the same recall comes back in later pulls with a changed status. This stage upserts by `recall_number` with `Delta.merge`, so bronze holds the latest copy of each recall and Delta table history holds the earlier ones.

The stage name is `bronze.recalls` (contracts.md, Stage names). The stage returns `StageResult` and never calls `RunMetrics.record`; `StageRunner` records the metrics (decision 6). Rejects are written with `Rejects.write(...)`.

## Inputs

- openFDA bulk file and API; raw copies under `Settings.rawDir("recalls")`: `bulk/<file>.json`, `api/<stamp>/page-<n>.json`.
- `RunManifest.watermark("recalls")` (greatest `report_date` loaded).
- Config via `Settings.config`: `medsignal.openfda.downloadIndexUrl`, `.enforcementUrl`, `.apiKey`, `medsignal.http.*` (connection settings in F3's `application.conf`). This task's own tunables, with defaults in `pipeline/src/main/resources/conf.d/I7.conf`: `medsignal.recalls.pageLimit = 1000` and `medsignal.recalls.maxSkip = 25000`.

## Outputs

- `Tables.bronze("recall_raw")`, key `recall_number`, not partitioned:
  ```scala
  final case class RecallRaw(recall_number: String, classification: String, status: String,
    reason_for_recall: String, product_description: String, recalling_firm: String,
    recall_initiation_date: String, report_date: String, termination_date: Option[String],
    openfda_rxcui: Seq[String])
  ```
  `openfda_rxcui` comes from nested `openfda.rxcui`; an absent value is an empty `Seq`.
- Rejects with `source = "recalls"`, written with `Rejects.write(...)`.
- `run_manifest` entry per pull: `source = "recalls"`, `unit` = bulk file name plus `meta.last_updated`, or `api-<stamp>`; `watermark = Some(<greatest report_date in the pull>)`.
- `run_metrics`: one row for stage `bronze.recalls`, recorded by `StageRunner` from the returned `StageResult`.

## Implementation steps

1. `fileSchema`: `results: array<struct<...the nine string fields..., openfda: struct<rxcui: array<string>>>>`. All fields nullable in the read schema; requiredness is enforced in step 3.
2. `OpenFdaClient`:
   - `downloadBulk(): Either[String, Seq[String]]`: read the index, download each partition zip to a `.part` file then rename, unzip; return paths.
   - `downloadSince(fromDate: String, toDate: String): Either[String, Seq[String]]`: page with `limit=<medsignal.recalls.pageLimit>` until `skip >= total`; if `total` exceeds the `skip` cap (`medsignal.recalls.maxSkip`), split the date range in half and recurse. Then the same for `search=status:"Ongoing"` (the spec's "plus open recalls"). Save every page unchanged. Throttle and retry as configured; a 404 with "No matches found" means zero records, not an error.
3. `RecallJsonReader.read(paths, ctx)`: `spark.read.schema(fileSchema).option("multiLine", true).json(paths)` with `input_file_name()`; explode `results`.
   - A file whose `results` is null: one `Reject("recalls", file, 0, "", "unparseable file", runId)`.
   - A record missing any non-`Option` field: `Reject("recalls", file, 0, to_json(record), "missing <field>", runId)`.
   - Otherwise a `RecallRaw`. No trimming, no date parsing.
   - Within one pull keep one row per `recall_number` (identical copies; prefer the API copy over the bulk copy when both exist).
4. Stage (`name = "bronze.recalls"`, `cadences = Set(Cadence.Weekly, Cadence.Full)`):
   - `Full`, or no watermark yet: bulk download, then the API from the bulk's greatest `report_date` to today.
   - `Weekly`: API from the watermark to today, plus open recalls.
   - `Delta.merge(rows, Tables.bronze("recall_raw"), Seq("recall_number"))`; `Rejects.write(rejects)`; `RunManifest.record` (its watermark carries the greatest `report_date`); return `StageResult` with `rowsIn` = records read, `rowsOut` = rows merged, `rowsRejected` = rejects. Do not call `RunMetrics.record`; `StageRunner` records the row.
   - Zero new records: return `StageResult(0, 0, 0)` and log `bronze.recalls: nothing new`.
5. `RecallCountCheck.run()`: take the table's least and greatest `report_date`, ask the API for `meta.results.total` over that range, compare with `count` of rows in the range, print both and the difference. Runnable as a `main`.
6. No `var`, no `null`; JSON nulls become `Option`, empty `Seq` or rejects at the reader.
