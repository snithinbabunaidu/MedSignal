## Goal

A hand-made answer key: for 50 real labels, the reactions listed in the adverse reactions and boxed warning sections, written as FAERS terms, with a flag for reactions the label says did not occur. L7 scores the extractor against it (criterion 5). Ten more labels are annotated by both engineers so we can report how far two people agree.

## Context

Read `docs/acceptance-criteria.md` criterion 5, `docs/data-issues.md` rows 9 and 10, `docs/contracts.md` (Conventions: `term`; `label_section`; `label_version`), `docs/branching.md` (reference data: one file per item).

- Annotation is done by a person reading the label text. Do not pre-fill files from the extractor's output and do not use any AI tool to annotate: the key must be independent of the thing it scores.
- This task owns data files only. Any helper code is a throwaway `spark-shell` snippet, pasted into `docs/results/L6.md`, not committed as source.
- 50 labels are annotated by one engineer each (25 and 25). These 50 are the gold set that criterion 5 refers to. 10 further labels are annotated by both, independently; they are used for agreement only and are not scored by L7.

## Inputs

- `Tables.silver("label_version")` (`LabelVersion`): candidates are rows with `isReference = true`.
- `Tables.bronze("label_section")` (`LabelSection`): the text to read, sections `34084-4` (adverse reactions) and `34066-1` (boxed warning).
- `Tables.silver("case_reaction")`: the list of valid terms.
- `data/reference/formulary.csv`: drug classes, for a balanced sample.

## Outputs

One JSON file per label and annotator. Schema (all five fields required, no others):

```json
{
  "setId": "0f9d4f6b-2c8e-4a5b-9b0a-3f1c2d7e8a11",
  "version": 14,
  "annotator": "A",
  "sectionsAnnotated": ["34066-1", "34084-4"],
  "reactions": [
    { "term": "DIABETIC KETOACIDOSIS", "loinc": "34066-1", "negated": false },
    { "term": "PANCREATITIS", "loinc": "34084-4", "negated": true }
  ]
}
```

| Field | Type | Rule |
|---|---|---|
| `setId` | string | As in `label_version.setId` |
| `version` | integer | The exact version that was read |
| `annotator` | string | `A` or `B` |
| `sectionsAnnotated` | array of string | LOINC codes actually read: the subset of `34066-1`, `34084-4` that the label has. A label with no boxed warning lists only `34084-4` |
| `reactions` | array of object | One object per distinct (`term`, `loinc`). Empty array allowed |
| `reactions[].term` | string | Upper case, exactly as in `silver.case_reaction.term` |
| `reactions[].loinc` | string | The section where it was found; must be in `sectionsAnnotated` |
| `reactions[].negated` | boolean | `true` only when every mention of the term in that section says it did not occur or was not observed |

The (`setId`, `version`) in the example is invented.

## Files to create

- `data/reference/gold_labels/GUIDELINES.md`: the annotation rules below, plus decisions made on hard cases.
- `data/reference/gold_labels/selection.csv`: columns `setId,version,rxcui,ingredient,drugClass,assignedTo` with `assignedTo` in `A`, `B`, `shared`. 60 rows.
- `data/reference/gold_labels/<setId>_v<version>.json`: 50 files, the single-annotator labels.
- `data/reference/gold_labels/shared/<setId>_v<version>_<annotator>.json`: 20 files, two per shared label.
- `docs/results/L6.md`

## Implementation steps

1. Selection (one engineer, first commit on the branch, so the other can start). In `spark-shell`: take reference label versions of formulary drugs that have a non-empty adverse reactions section; one label per `rxcui`; order by SHA-256 of `setId` (a fixed, arbitrary order); walk the list taking labels round-robin across the formulary's drug classes until 60 are chosen. Assign them in order: A, B, A, B, ... for the first 50, `shared` for the last 10. Write `selection.csv`. Check that at least 10 of the 60 have a boxed warning; if not, swap in the next candidates that do and say so in the results file.
2. Export the text for reading into a git-ignored folder (for example `data/raw/gold_export/<setId>_v<version>_<loinc>.txt`), plus the distinct FAERS terms as one sorted text file for lookup. Never commit the export.
3. Annotation rules (`GUIDELINES.md`):
   1. Read only the two sections. Record a reaction when the section states or lists it as an adverse reaction of this drug, in prose, a list or a table, whatever the frequency.
   2. Write it as the FAERS term for that reaction. Search the term list; mind British spelling (`DIARRHOEA`, `HYPOGLYCAEMIA`). If the label's wording maps to a term through a synonym ("low blood sugar"), record the term. If no FAERS term exists for it, do not record it, and add the wording to a "no term" list in `docs/results/L6.md`.
   3. One object per term and section, however many times it is mentioned.
   4. `negated = true` when the section mentions the reaction only to say it did not occur ("No cases of pancreatitis were observed"). If the section has both a negated and a plain mention, `negated = false`.
   5. Do not record: reactions listed only for a comparator or placebo with an explicit statement that the drug did not differ; conditions that are the reason for treatment; laboratory names without a direction.
   6. Use the most specific term the text supports. Do not add broader terms as well.
   7. When unsure, decide, and add the case and the decision to `GUIDELINES.md` so the other engineer decides the same way.
4. Each engineer annotates their 25 and the 10 shared labels without looking at the other's shared files. Each engineer commits only files with their own annotator letter, so the two never touch the same file. Both push to the one branch `chore/L6-gold-set`.
5. Validate before the pull request with a `spark-shell` snippet: every file parses as the schema above (`spark.read.option("multiLine", "true")`); every (`setId`, `version`) is in `selection.csv` and in `silver.label_version`; every `term` is in the FAERS term list; every `loinc` is in the file's `sectionsAnnotated`; no duplicate (`term`, `loinc`) in a file. Fix every failure.
6. Agreement on the 10 shared labels. For each label, each annotator's items are the set of (`loinc`, `term`). Report, pooled over the 10 labels:
   - items by A, items by B, items in both;
   - agreement F1 = `2 * both / (A + B)`;
   - for items in both, the share with the same `negated` value;
   - the list of disagreements, each with a one-line reason.
   Do not edit the shared files after comparing; record the agreed answer for each disagreement in `docs/results/L6.md`.

## Tests

No ScalaTest code (this task owns no Scala folder). The checks are the validation in step 5, run by the engineer and repeated by the reviewer:

- "every file parses": 70 files read, 0 corrupt records.
- "every term is a FAERS term": 0 unknown terms.
- "counts are right": 50 files at the top level, 25 per annotator; 20 files in `shared/`, 10 per annotator, 10 distinct labels.
- "sections are consistent": 0 reactions with a `loinc` outside `sectionsAnnotated`.

No fixture files; L7 adds its own small gold files under `src/test/resources/L7/`.

## Done when

- [ ] 50 single-annotator files and 20 shared files are checked in and pass step 5 (backlog: "gold set checked in").
- [ ] `docs/results/L6.md` reports agreement on the shared labels (backlog), the number of reactions and negated reactions in the gold set, the "no term" list, and the snippets used.
- [ ] Feeds criterion 5: L7 computes precision, recall and negation accuracy against these files. If the gold set holds fewer than 20 negated items, say so; the negation accuracy will then be a rough number.

## Out of scope

- Scoring the extractor (L7). Changing the extractor to fit the key (L2, L4).
- Warnings and precautions and drug interactions sections: not annotated.
- Annotating more than one version of a label.
