## Goal

The command line entry point of the pipeline: `run daily`, `run weekly`, `run quarterly` or `run full`. It finds every registered stage, orders them, runs the ones that belong to the requested cadence and have new input, and reports what happened. No task edits a central list of stages; this loader is what makes that possible.

## Context

Read `docs/contracts.md` (Common library: `Stage`, `RunContext`, `StageResult`, `RunMetrics`; the paragraph on `stages/<name>.conf`; the final section: `StageRunner`, `RunContext.start`, `Cadence`, the stage names), `docs/architecture.md` "Cadence", `docs/branching.md` "Shared files", `docs/pipeline-spec.md` sections 6 and 8, and `docs/tasks/F7.md`.

Facts and decisions this brief fixes:

- A stage file is HOCON, read with Typesafe Config (`com.typesafe.config`, already in the build). Keys: `class` (required), `after` (list of stage names, default empty), `always` (boolean, default `false`; defined by this task).
- Cadences are not in the file. They come from `Stage.cadences`.
- `after` is a soft constraint. A name that is registered but not part of this run is ignored. A name that is not registered at all is ignored with a warning in the run summary. Reason: tasks merge in dependency order, and a stage often has to run after a stage that will only exist later (`changes.events` after `triage.status`, `publish.serving` after `quality.checks`).
- The `Stage` trait has no "has new input" method. Each stage checks `RunManifest` itself and returns `StageResult(0, 0, 0)` when there is nothing to do. The orchestrator uses those results to skip downstream stages (step 5).
- Metrics: by contract (contracts.md final section, item 6) a stage only returns `StageResult`; it never calls `RunMetrics.record`. The orchestrator runs every stage through F7's `StageRunner.run(stage, ctx)`, which times the stage and records its one metrics row. The orchestrator never calls `RunMetrics.record` itself (that would double the rows).
- The run context comes from F7's `RunContext.start(spark, cadence, asOfQuarter)`, which also creates the `runId`. Do not build a `RunContext` or a run id by hand.
- Quality checks (C5) are an ordinary stage, `quality.checks`; its exception stops the run like any stage failure, so C5 needs no edit here. The hook mechanism (step 6) stays available, but no task registers a hook.

## Inputs

- Classpath folder `stages/` (`pipeline/src/main/resources/stages/*.conf`) and `hooks/` (`*.conf`, may be absent).
- Command line arguments.
- Configuration through `medsignal.common.Settings` (F7).

## Outputs

- Console summary and process exit code.
- One row in `data/ops/run_metrics` per stage that ran, written by `StageRunner`, not by this task's code.
- No data tables.

## Implementation steps

1. Command line: `run <daily|weekly|quarterly|full> [--as-of <quarter>] [--force] [--dry-run]`.
   - `--as-of 2024Q3` fills `RunContext.asOfQuarter`. `--force` disables skipping. `--dry-run` prints the plan and runs nothing.
   - Anything else prints usage and exits with code 1.
   - Invocation: `sbt "pipeline/runMain medsignal.run.Main run daily"` or `spark-submit --class medsignal.run.Main <jar> run daily`. Spark is a `provided` dependency; check `docs/setup.md` (F3) for how `runMain` gets it on the classpath.
2. Types:
   ```scala
   final case class Registered(stage: Stage, after: Seq[String], always: Boolean)
   trait StageHook {
     def name: String
     def afterStage(stageName: String, result: StageResult, ctx: RunContext): Either[String, Unit]
   }
   sealed trait Outcome
   final case class Ran(result: StageResult, durationMs: Long) extends Outcome
   case object Skipped extends Outcome
   final case class Failed(message: String) extends Outcome
   final case class RunReport(cadence: Cadence, outcomes: Seq[(String, Outcome)], warnings: Seq[String])
   ```
3. `StageRegistry.load(folder: String = "stages"): Either[String, Seq[Registered]]` and `loadHooks(folder: String = "hooks"): Either[String, Seq[StageHook]]`.
   - List `*.conf` in the folder on every classpath root: `getClassLoader.getResources(folder)`; for a `file:` URL list the directory; for a `jar:` URL open the `JarURLConnection` and filter entries that start with `folder + "/"` and end with `.conf`. Both cases need a test or a manual check with the assembled jar; a directory listing alone breaks under `spark-submit`.
   - Parse each file with `ConfigFactory.parseURL`. Instantiate `class`: if the name ends with `$`, read the static field `MODULE$` (a Scala `object`); otherwise call the no-argument constructor. Wrap in `Try`.
   - Errors (returned as `Left`, naming the file): missing `class`, class not found, not a `Stage`, the file name without `.conf` differs from `stage.name`, two stages with one name.
4. `StagePlan.order(all: Seq[Registered], cadence: Cadence): Either[String, (Seq[Registered], Seq[String])]` (pure):
   - Selected = stages whose `cadences` contain `cadence`.
   - Edges: for each selected stage, each `after` name that is selected. Names registered but not selected: dropped. Names not registered: dropped, with a warning string.
   - Topological sort (Kahn). Among stages that are ready, pick the alphabetically first name, so the order is deterministic.
   - A cycle returns `Left` listing the stages in it.
5. `Orchestrator.run(plan, ctx, hooks, force): RunReport`. For each stage in order:
   - "Did work" means `rowsIn > 0 || rowsOut > 0 || rowsRejected > 0`.
   - Skip rule: run the stage when `force`, or `always`, or it has no selected upstream stage, or at least one of its selected upstream stages ran and did work. Otherwise mark it `Skipped` and call nothing.
   - Run with `StageRunner.run(stage, ctx)` inside `Try`; never call `stage.run` directly. `StageRunner` records the metrics; time the call here only for the console line. On an exception: mark `Failed(message)`, stop; later stages are not run.
   - After a successful stage, call each hook's `afterStage`. A `Left(msg)` is treated as a failure of that stage with `msg`.
   - Use `foldLeft` over the plan carrying the outcomes so far; no `var`.
6. Hooks are registered like stages: a file `pipeline/src/main/resources/hooks/<name>.conf` with `class = "..."`. This task ships no hook, and C5 does not use one (it registers the stage `quality.checks`).
7. `Main`:
   - Build the session with the factory in `medsignal.common` if F7 provides one for production use; otherwise build it here with the two Delta settings (`spark.sql.extensions`, `spark.sql.catalog.spark_catalog`) copied from the Delta Lake documentation for the version in `build.sbt`.
   - `ctx = RunContext.start(spark, cadence, asOfQuarter)`; the `runId` is the one F7 creates.
   - Print one line per stage: name, `ran`/`skipped`/`failed`, rows in, out, rejected, seconds. Then warnings.
   - If no stage did work, print exactly `No new data: nothing to do.`
   - No call to `RunMetrics.record` anywhere in this task: the per-stage rows written by `StageRunner` are the run's metrics, and a summary row would double the counts.
   - Exit code 0 on success (including nothing to do), 1 for usage or registry errors, 2 when a stage or hook failed.
   - Keep `Main.main` thin: put the logic in `def execute(args: Seq[String]): Int` so tests do not call `sys.exit`.

## Tests

`StagePlanSpec` (no Spark, fake stages):

- "orders by after": c after b after a gives a, b, c.
- "breaks ties by name".
- "keeps only stages of the cadence": a `Set(Full)` stage is absent from a daily plan.
- "ignores after for a stage outside the cadence".
- "warns about an unknown after name" and still returns a plan.
- "reports a cycle" naming both stages.

`StageRegistrySpec` (fixtures under `C1/`):

- "loads objects and classes" from `C1/stages-basic`.
- "fails when the class does not exist" (`C1/stages-badclass`).
- "fails when file name and stage name differ".

`OrchestratorSpec` (`SparkTestSession`; fake stages record their calls in an `AtomicReference` list):

- "a run with no new data does no work and says so": every source stage returns zeros; downstream stages are `Skipped`; the report says nothing was done.
- "runs downstream when upstream did work".
- "always = true runs despite idle upstream".
- "force runs everything".
- "stops at the first failing stage": the next stage is never called.
- "records each stage once": after a run, `run_metrics` has exactly one row per stage that ran and none for skipped stages.
- "a hook failure stops the run with its message".

`MainSpec`:

- "rejects an unknown cadence with exit code 1".
- "dry run calls no stage".
- "returns 2 when a stage fails".
