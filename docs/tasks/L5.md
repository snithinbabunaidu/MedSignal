## Goal

Two pipeline stages. The first runs the extractor (L1 to L4) over label versions not yet processed and writes `gold.LabeledReaction`. The second sets the labeled-status columns on `gold.Signal`, so every signal says whether the reaction is already on the drug's reference label and shows the passage, or the sections that were searched. This is what separates "known" from "new" in the application.

## Context

Read `docs/pipeline-spec.md` section 5, `docs/contracts.md` (Gold `LabeledReaction`, `Signal`; Common library; stage registration), `docs/architecture.md` decision 3, `docs/ontology.md`, and briefs `docs/tasks/L1.md` to `L4.md`, `G3.md`, `S4.md`, `C1.md`.

- Rule-based only. This task wires existing pure rules together; it adds no model of any kind.
- Ownership: `gold.Signal` is created by G3 in `signals/signal/`. Do not edit G3's files. The status stage here runs after G3's stage and updates five columns with `Delta.merge` on (`rxcui`, `term`). Assumption to verify in G3's code: G3 writes `labeledStatus = "no_label"`, `decidingSetId = None`, `decidingVersion = None`, `passage = None`, `sectionsSearched = Seq.empty`. If G3 writes something else the stage still works, because it sets all five columns.
- `LabeledReaction` has one row per (`setId`, `version`, `term`, `extractorVersion`), but a term can be mentioned many times. One mention is chosen (step 4).
- Offsets: `passage` is the sentence, and `startOffset`/`endOffset` are the sentence's offsets in the section text, so `sectionText.substring(startOffset, endOffset) == passage` (the test required by pipeline-spec.md). The contract has no columns for the offsets of the matched words inside the passage; they are kept in `LabelMention` but not stored. Do not add columns; this gap is reported to the lead.
- Case classes `Signal`, `LabelSection`, `LabelVersion` are defined by G3, I6 and S4; find them by searching, do not redefine them. `LabeledReaction` is defined here.
- Stage names are fixed in contracts.md ("Stage names"): this task registers `labeltext.extract` and `labeltext.status`; `after` lists use the names listed there.
- `signals.signal` rebuilds `gold.Signal` in full with `labeledStatus = no_label` (contracts.md final section, item 16). `labeltext.status` therefore runs after it on every run and re-applies the five columns.
- Stages return `StageResult` and never call `RunMetrics.record`; the runner records (item 6). Rejects are written with `Rejects.write`.

## Implementation steps

1. Version string:
   ```scala
   object ExtractorVersion {
     def current(): String =
       s"s${SentenceSplitter.Version}.${DictionaryLoader.rulesVersion()}.m${Matcher.Version}.n${Negation.Version}"
   }
   ```
   It changes when any rule or the synonym file changes, and not when FAERS adds terms.
2. Mentions:
   ```scala
   final case class LabelMention(setId: String, version: Int, loinc: String, term: String, sentenceIndex: Int,
                                 passage: String, startOffset: Int, endOffset: Int,   // sentence, in section text
                                 matchStart: Int, matchEnd: Int, negated: Boolean)
   object LabelExtractor {
     def mentions(sections: Dataset[LabelSection], trie: Broadcast[Trie])
                 (implicit spark: SparkSession): Dataset[LabelMention]
     def choose(mentions: Dataset[LabelMention], extractorVersion: String)
               (implicit spark: SparkSession): Dataset[LabeledReaction]
   }
   ```
   `mentions` = `Sentences.split` then `Matcher.run`, then a typed `map` that calls `Negation.isNegated(m.sentence, m.matchStart - m.sentenceStart, m.matchEnd - m.sentenceStart)`.
3. Extraction stage `LabeledReactionStage` (`name = "labeltext.extract"`, `cadences = Set(Daily, Full)`):
   1. `v = ExtractorVersion.current()`. Pending = (`setId`, `version`) pairs in `silver.label_version` whose unit `s"$setId:$version:$v"` is not in `RunManifest.loaded("label_extraction")`. All label versions are extracted, not only reference labels (L7's drift report and V1 need history). If nothing is pending, return `StageResult(0, 0, 0)`.
   2. `Sentences.select` on the sections of the pending pairs; `DictionaryLoader.load`; `Trie.build`; broadcast; `LabelExtractor.mentions`; `LabelExtractor.choose`.
   3. Write with `Delta.merge(rows, Tables.gold("LabeledReaction"), Seq("setId", "version", "term", "extractorVersion"))`. By contract `merge` creates the table when it does not exist.
   4. Write the rejects from L1 and L2 with `Rejects.write`.
   5. After the write succeeds, `RunManifest.record("label_extraction", unit, checksum = v, watermark = None)` for every pending pair, including pairs that produced no rows (otherwise they are re-read on every run).
   6. Return `StageResult(rowsIn = sections read, rowsOut = rows written, rowsRejected)`. Do not call `RunMetrics.record`; the runner records.
   The stage never reads or writes a FAERS table other than the distinct terms of `case_reaction`.
4. `choose`: group mentions by (`setId`, `version`, `term`) and keep one, ordered by: not negated before negated; then section priority `Loinc.searched` (boxed warning, warnings and precautions, adverse reactions, drug interactions); then lowest `startOffset`; then lowest `matchStart`. So `negated = true` only when every mention of the term on that label version is negated. Use `groupByKey(...).reduceGroups(...)` with a pure `better(a, b)` function.
5. Status decision (pure, in `LabeledStatus`):
   ```scala
   final case class StatusColumns(labeledStatus: String, decidingSetId: Option[String], decidingVersion: Option[Int],
                                  passage: Option[String], sectionsSearched: Seq[String])
   def decide(reference: Option[(String, Int, Seq[String])],        // setId, version, LOINC codes present
              reaction: Option[LabeledReaction]): StatusColumns
   ```
   | Case | labeledStatus | decidingSetId, decidingVersion | passage | sectionsSearched |
   |---|---|---|---|---|
   | Drug has no reference label | `no_label` | None | None | empty |
   | Row exists, `negated = false` | `labeled` | the reference label | the row's passage | codes present |
   | Row exists, `negated = true` | `negated_only` | the reference label | the row's passage | codes present |
   | No row | `unlabeled` | the reference label | None | codes present |
   "Codes present" = the sorted distinct `loinc` values, among the four, that the reference label has in `bronze.label_section`.
6. Status stage `LabeledStatusStage` (`name = "labeltext.status"`, `cadences = Set(Daily, Weekly, Quarterly, Full)`). It runs on every cadence, after `signals.signal`, because G3 rebuilds `gold.Signal` with default status columns.
   1. Reference label per `rxcui`: rows of `silver.label_version` with `isReference = true`. S4 should give one per `rxcui`; if there are several, take the newest `effectiveDate`, then highest `version`, then smallest `setId`, and report the count.
   2. Left-join signals to the reference label on `rxcui`, then to `LabeledReaction` rows with `extractorVersion = ExtractorVersion.current()` on (`setId`, `version`, `term`).
   3. If a reference label's unit is missing from the manifest (not extracted yet at this version), leave that signal's columns unchanged and count it as pending in the log.
   4. Build full `Signal` rows with `signal.copy(labeledStatus = ..., ...)`, keep only rows where one of the five columns changed, and `Delta.merge(changed, Tables.gold("Signal"), Seq("rxcui", "term"))`. Merging whole rows uses only the contract's `Delta.merge`; do not write partial rows.
   5. Return `StageResult(rowsIn = signals, rowsOut = changed rows, rowsRejected = 0)`. Do not call `RunMetrics.record`.
7. Registration. `stages/labeltext.extract.conf`:
   ```hocon
   class = "medsignal.labeltext.labeled.LabeledReactionStage"
   after = ["silver.label_version", "silver.case_reaction", "bronze.labels", "incremental.labels"]
   always = true
   ```
   `stages/labeltext.status.conf`: `after = ["labeltext.extract", "signals.signal", "incremental.faers", "incremental.labels"]`, also with `always = true`. `incremental.faers` and `incremental.labels` are the names the C2 and C3 briefs use for their stages, which merge later; C1 ignores an `after` name that is not registered (see `docs/tasks/C1.md`). `always = true` tells C1 not to skip the stage when upstream stages had no new data, because a rule change creates work with no new input.

## Tests

`LabelExtractorSpec` (`SparkTestSession`, fixtures in `L5/`):

- "offsets reproduce the passage exactly for every row": for every output row, the section text's `substring(startOffset, endOffset)` equals `passage`.
- "No cases of pancreatitis were observed is negated": one row for `PANCREATITIS` with `negated = true`.
- "a non-negated mention beats a negated one": a label with both gives `negated = false` and the non-negated sentence as passage.
- "section priority picks the boxed warning": the same term in `34066-1` and `34084-4` gives `loinc = "34066-1"`.

`LabeledReactionStageSpec`:

- "second run does nothing": run twice; the second `StageResult` is all zeros and the table is unchanged.
- "a new label version is extracted alone": add one version; only its unit is added to the manifest.
- "a rule change re-runs extraction and leaves FAERS tables untouched": change the synonym file in the temp dataDir; rows appear under a new `extractorVersion`, old rows remain, and the Delta version of `silver.case_reaction` is unchanged.
- "a label with no matches is not re-read".

`LabeledStatusSpec`:

- One test per row of the table in step 5 on the pure `decide`.
- "every signal ends with a status": after the stage, no signal has a status outside the four values; every `labeled` and `negated_only` row has a passage; every `unlabeled` row has a non-empty `sectionsSearched`.
- "merge is idempotent": a second run changes zero rows.
- "status survives a signal rebuild": overwrite `gold.Signal` with defaults, run the stage, statuses return.
