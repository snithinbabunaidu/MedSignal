## Goal

The `app` module becomes a running http4s server that answers the six endpoints in contracts.md from the serving database, accepts triage decisions, and serves the static web pages. It has no Spark dependency and reads nothing but the serving database.

## Context

- Read `docs/contracts.md` sections "Toolchain", "Serving database", "HTTP API", "Gold tables"; `docs/pipeline-spec.md` section 9; `docs/branching.md` row "API routes"; `docs/tasks/A1.md` section "Outputs" for the exact serving DDL.
- `app` is Scala 3 with http4s (ember server, dsl, circe) and doobie. It does not depend on `pipeline`, so the case classes are written again here; JSON field names are the camelCase gold field names.
- One file per route group. The route list is one file you own; V7 will add one line to it.
- A1 replaces the published tables in one transaction, so a request always sees a complete set. The app writes one table only: `triage_event(event_id, rxcui, term, decision, note, user_name, decided_at)`.
- Check the http4s, doobie and circe versions in `build.sbt` before copying any sketch below. The sketches assume http4s 0.23 with cats-effect 3 and a doobie 1.0 release candidate; names differ slightly between versions (for example the arguments of `Transactor.fromDriverManager`, and where the `java.sql`/`java.time` column instances are imported from). Use each library's documentation for the version in the build.
- `app` cannot use the pipeline's `Settings` (different module, Scala 3). `com.typesafe:config` is in every module (contracts.md, "Toolchain additions (F1)"), so `AppConfig` may load the keys below with `ConfigFactory.load()`, which already lets a Java system property override a file value; the environment variable is the second choice, then the default (see Inputs).

## Outputs

| Method and path | Response |
|---|---|
| `GET /api/changes?since=<yyyy-MM-dd>` | `List[ChangeEvent]`, newest first. Without `since`: the events of the latest `runDate` |
| `GET /api/signals?class=&status=&labeled=&limit=` | `List[SignalRow]` ordered by `score` descending, then `rxcui`, `term`. `class` matches `drugClass`, `status` matches `triageStatus`, `labeled` matches `labeledStatus`. `limit` default 100, maximum 1000 |
| `GET /api/drugs/{rxcui}` | `DrugDetail`; 404 when the drug is unknown |
| `GET /api/recalls?status=open` | `List[Recall]` for formulary drugs, newest `reportDate` first. `status` filter is case-insensitive on the stored status text (for `open`, check what S5 stores for an ongoing recall and match that). Optional `unresolved=true` returns recalls with no `rxcui` instead |
| `GET /api/health` | `Health` |
| `POST /api/triage` | Body `{rxcui, term, decision, note, user}`. 201 with the stored `TriageDecision` |
| `GET /`, `/*.html`, `/css/*`, `/js/*` | Files from classpath folder `web/` (A3 fills it) |

Case classes (in `Model.scala`): `Drug`, `Signal`, `AdverseEventStat`, `LabeledReaction`, `Recall`, `ChangeEvent`, `TriageDecision` with the fields of contracts.md (dates as `java.time.LocalDate`, written as ISO strings), plus:

```scala
final case class SignalRow(signal: Signal, drugName: String, drugClass: Option[String])
final case class DrugDetail(drug: Drug, signals: List[Signal],
  countsByQuarter: List[AdverseEventStat], labeledReactions: List[LabeledReaction])
final case class RunMetric(runId: Option[String], stage: String, rowsIn: Long, rowsOut: Long,
  rowsRejected: Long, durationMs: Long, newestSourceDate: Option[String], recordedAt: Option[String])
final case class CheckResult(stage: String, check: String, passed: Boolean, message: Option[String])
final case class ExtractionScore(extractorVersion: String, precision: Double, recall: Double,
  negationAccuracy: Double, scoredAt: Option[String])
final case class Health(metrics: List[RunMetric], checks: List[CheckResult],
  extractionScores: List[ExtractionScore])
final case class TriageRequest(rxcui: String, term: String, decision: String,
  note: Option[String], user: String)
final case class ApiError(error: String)
```

`Signal.sectionsSearched` is `List[String]` in JSON; the database column is a comma-joined string, split it on read. Adjust `RunMetric`, `CheckResult` and `ExtractionScore` to the columns A1 actually published.

## Implementation steps

1. `Routes.scala`:

   ```scala
   object Routes:
     val groups: List[RouteGroup] = List(
       ChangesRoutes, SignalsRoutes, DrugsRoutes, RecallsRoutes, HealthRoutes, TriageRoutes
       // later tasks add one line each here
     )
     def api(xa: Transactor[IO]): HttpRoutes[IO] = groups.map(_.routes(xa)).reduce(_ <+> _)
   ```

   `Main` serves `(Routes.api(xa) <+> StaticRoutes.routes).orNotFound`.

2. A route group, shape:

   ```scala
   object SignalsRoutes extends RouteGroup:
     private object ClassQ   extends OptionalQueryParamDecoderMatcher[String]("class")
     private object StatusQ  extends OptionalQueryParamDecoderMatcher[String]("status")
     private object LabeledQ extends OptionalQueryParamDecoderMatcher[String]("labeled")
     private object LimitQ   extends OptionalQueryParamDecoderMatcher[Int]("limit")
     def routes(xa: Transactor[IO]): HttpRoutes[IO] = HttpRoutes.of[IO] {
       case GET -> Root / "api" / "signals" :? ClassQ(c) +& StatusQ(s) +& LabeledQ(l) +& LimitQ(n) =>
         query(c, s, l, n.getOrElse(100).min(1000).max(1)).transact(xa).flatMap(Ok(_))
     }
   ```

3. Signals query. Build the `WHERE` from optional parts with doobie fragments (`Fragments.whereAndOpt`). The triage status shown must reflect a decision made a moment ago, before the next pipeline run, so overlay the latest triage event:

   ```sql
   SELECT s.*, d.name, d.drug_class, COALESCE(t.decision, s.triage_status) AS current_status
   FROM signal s JOIN drug d ON d.rxcui = s.rxcui
   LEFT JOIN (
     SELECT e.rxcui, e.term, e.decision FROM triage_event e
     JOIN (SELECT rxcui, term, MAX(decided_at) AS m FROM triage_event GROUP BY rxcui, term) x
       ON x.rxcui = e.rxcui AND x.term = e.term AND x.m = e.decided_at
   ) t ON t.rxcui = s.rxcui AND t.term = s.term
   ```

   The `status` filter applies to `current_status`. Use the same overlay for the signals inside `DrugDetail`. Never build SQL by string concatenation of request values; use doobie interpolation.

4. `DrugDetail`: four queries in one `ConnectionIO`: the drug; its signals (score descending); `adverse_event_stat` rows for the drug ordered by term, quarter (A1 publishes stats only for signal pairs, so this is bounded); `labeled_reaction` rows for the drug.

5. `Health`: `metrics` = for each stage the row with the newest `recorded_at`; `checks` = rows of `check_result`, or an empty list when that table does not exist; `extractionScores` = all rows, newest first.

6. `POST /api/triage`: decode `TriageRequest`. Reject with 400 and `ApiError` when `decision` is not one of `review`, `escalate`, `dismiss`, or `user` is blank. Return 404 when (rxcui, term) is not in `signal`. Upper-case and trim `term`. Insert with `event_id = UUID.randomUUID().toString` and `decided_at` = server time. Events are append only: no update, no delete.

7. Errors: malformed `since` or `limit` gives 400 with `ApiError`; an unexpected database error gives 500 with a generic message and the detail in the log. If a published table is missing (pipeline never ran), `GET` endpoints return 503 with `ApiError("serving database not published yet")`.

8. Static files: `resourceServiceBuilder[IO]("/web").toRoutes` and a redirect or direct response for `/` to `index.html`. Check the builder's name in the http4s version in use.

9. `ensureTriageTable` at startup:

   ```sql
   CREATE TABLE IF NOT EXISTS triage_event (
     event_id VARCHAR PRIMARY KEY, rxcui VARCHAR NOT NULL, term VARCHAR NOT NULL,
     decision VARCHAR NOT NULL, note VARCHAR, user_name VARCHAR NOT NULL, decided_at TIMESTAMP NOT NULL);
   ```

## Tests

`ApiSpecBase` opens `jdbc:h2:mem:<random>;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1`, runs `schema.sql` and `seed.sql`, and calls routes in process with `Routes.api(xa).orNotFound.run(Request(...))` (no socket). Seed: 3 drugs in 2 classes; 5 signals (3 unlabeled, 1 labeled, 1 negated_only) with distinct scores; stats for 2 quarters; 2 labeled reactions; 3 recalls (2 open, 1 terminated, one of them Class I); change events on two run dates; 2 run-metric rows for one stage.

- `ChangesRoutesSpec`: "returns events on or after since, newest first"; "without since returns the latest run date only"; "bad date gives 400".
- `SignalsRoutesSpec`: "orders by score descending"; "filters by class"; "filters by labeled=unlabeled" (3 rows); "limit=2 returns 2"; "status reflects a triage event posted after publish" (insert a dismiss event; `status=dismiss` returns that signal, `status=open` no longer does).
- `DrugsRoutesSpec`: "returns drug, signals, counts and labeled reactions"; "unknown rxcui gives 404"; "sectionsSearched is a JSON array".
- `RecallsRoutesSpec`: "status=open returns the 2 open recalls"; "unresolved=true returns only recalls without rxcui".
- `HealthRoutesSpec`: "returns the latest metric row per stage"; "checks is empty when the table is absent".
- `TriageRoutesSpec`: "valid body inserts one row and returns 201"; "unknown decision gives 400"; "unknown signal gives 404"; "two posts leave two rows" (append only).
- `ModelSpec`: "JSON field names are camelCase" (encode one `Signal`, check `rorLower`, `firstFlaggedQuarter`).
