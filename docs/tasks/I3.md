## Goal

Three bronze tables: `rxnorm_names`, the RxNorm name table that the drug identity resolver (S2) matches against; `rxnorm_ingredient_map`, which maps brand, salt and product concepts to their ingredient; and `rxclass`, the drug classes of the formulary ingredients. Row counts are recorded. All three are written by one stage, `bronze.rxnorm` (the only stage name contracts.md gives this task).

## Context

Read `docs/contracts.md` (Bronze tables `rxnorm_names`, `rxnorm_ingredient_map` and `rxclass`, Common library, and the final section "Decisions settled after the first draft of the briefs": decisions 1 to 4, 6, 7, 9, "Common library (F7) additions", "Stage names"), `docs/pipeline-spec.md` sections 1 and 6 (RxNorm row), `docs/data-sources.md` (RxNorm and RxClass) and `docs/decisions/F4-tableparser-in-spark.md` if it is merged (how TableParser was driven).

Facts and things to verify:

- The prescribable subset is believed to download without a UMLS licence from `https://download.nlm.nih.gov/rxnorm/RxNorm_full_prescribe_current.zip` (the full release needs a login; do not use it). Confirm the URL works with a plain GET.
- Inside the zip, `rrf/RXNCONSO.RRF`: pipe-delimited, **no header**, no quoting, each line ends with a trailing `|`. Expected 18 columns in order: `RXCUI, LAT, TS, LUI, STT, SUI, ISPREF, RXAUI, SAUI, SCUI, SDUI, SAB, TTY, CODE, STR, SRL, SUPPRESS, CVF`. Confirm against the RxNorm technical documentation and the first lines of the file. `STR` can contain double quotes; quote handling must be off.
- TableParser normally takes column names from a header row. This file has none, so find in the 1.7.2 source how to supply a header explicitly. If that proves impractical, prepend the header line in memory before parsing. Record which was used.
- RxClass: `GET {base}/class/byRxcui.json?rxcui=<id>&relaSource=ATC` is believed to return `rxclassDrugInfoList.rxclassDrugInfo[]`, each with `rxclassMinConceptItem { classId, className, classType }`. Check one real response, and check that `relaSource=ATC` returns classes for an ingredient (if not, try `ATCPROD` or `MEDRT` and record the choice). NLM asks for at most 20 requests per second; we use far fewer.
- This task needs the formulary's `rxcui` list. F6 (a dependency) loads it into `bronze.formulary` with stage `bronze.formulary`. Read that bronze table with `Delta.readOrEmpty[FormularyDrug](Tables.bronze("formulary"))`, importing `medsignal.bronze.reference.formulary.FormularyDrug`; never read `data/reference/formulary.csv` and never redefine the case class (contracts.md, decisions 2 and 3). If the table is absent or empty, the RxClass part logs that and does nothing.
- Ingredient map: the same zip is believed to hold `rrf/RXNREL.RRF` (pipe-delimited, no header, trailing `|`; expected columns `RXCUI1, RXAUI1, STYPE1, REL, RXCUI2, RXAUI2, STYPE2, RELA, RUI, SRUI, SAB, SL, DIR, RG, SUPPRESS, CVF`). Relationships believed to lead to an ingredient (`IN`): brand name `BN` by `tradename_of`; precise ingredient or salt `PIN` by `form_of`; multiple ingredient `MIN` by `has_part`; clinical drug component `SCDC` by `has_ingredient`; clinical drug `SCD` by `consists_of` to `SCDC`; branded forms (`SBD`, `SBDC`, `SBDF`) by `tradename_of` to their clinical form. The direction of a row (which of `RXCUI1` and `RXCUI2` is the subject of `RELA`) is easy to get backwards: confirm it in the RxNorm technical documentation and on canagliflozin and one of its brands, and record the relationships and direction used.
- There is no monthly cadence; this stage runs under `Quarterly` and `Full` only (contracts.md, Stage names).

## Inputs

- The RxNorm zip, saved to `data/raw/rxnorm/<zip sha prefix>/`.
- `Tables.bronze("formulary")` (`FormularyDrug`, written by F6's stage `bronze.formulary`).
- RxClass responses, saved to `data/raw/rxclass/<rxcui>.json`.
- Config through `Settings.config`: `medsignal.rxnorm.prescribeUrl`, `medsignal.rxnorm.rxclassBaseUrl`, `medsignal.http.*` (connection settings in F3's `application.conf`), and this task's own tunables with their defaults in `pipeline/src/main/resources/conf.d/I3.conf`: `medsignal.rxnorm.relaSource = "ATC"` and `medsignal.rxnorm.maxIngredientHops = 4`. Do not edit `application.conf`.

## Outputs

- `Tables.bronze("rxnorm_names")`: `RxNormName(rxcui: String, tty: String, name: String, sab: String)`, from `RXCUI`, `TTY`, `STR`, `SAB`. All lines are kept (every term type, every source, suppressed or not); S2 filters. Not partitioned. Replaced on each new release.
- `Tables.bronze("rxnorm_ingredient_map")`: `RxNormIngredientMap(rxcui: String, ingredientRxcui: String, tty: String)`. One row per concept and ingredient: `rxcui` is a brand, salt or product concept, `ingredientRxcui` is its `IN` concept, `tty` is the term type of `rxcui`. A combination product has one row per ingredient. Every `IN` concept also maps to itself. Not partitioned. Replaced on each new release.
- `Tables.bronze("rxclass")`: `RxClassMember(rxcui: String, classId: String, className: String)`, distinct, replaced on each run.
- Rejects with `source = "rxnorm"` or `"rxclass"`, written with `Rejects.write(...)`.
- One `StageResult` for stage `bronze.rxnorm`; `StageRunner` records the metrics row (the stage never calls `RunMetrics.record`).

## Implementation steps

1. `RxConsoParser`: parse with TableParser as decided above. Reject when the field count is wrong, or `RXCUI`, `TTY` or `STR` is empty. Keep `STR` exactly as written.
2. `RxNormDownload.fetch(): Either[String, Release]` with `Release(id: String, sha256: String, rrfPath: String)`: download with `java.net.http.HttpClient` to a `.part` file, compute `Checksum.sha256`, `id` = first 16 hex characters, unzip only `rrf/RXNCONSO.RRF` and `rrf/RXNREL.RRF`. Put HTTP behind a small trait so tests need no network.
3. `RxNormBronzeStage` (`name = "bronze.rxnorm"`, `cadences = Set(Cadence.Quarterly, Cadence.Full)`) runs `RxNormNamesLoader`, then `IngredientMapBuilder`, then `RxClassLoader`, and returns one `StageResult` whose three counts are the sums over the parts. It never calls `RunMetrics.record`; `StageRunner` records the metrics. `RxNormNamesLoader`:
   - Fetch. If `id` is in `RunManifest.loaded("rxnorm")` and cadence is not `Full`, log `no new release` and return `StageResult(0, 0, 0)` for this part and the ingredient map part.
   - Read the file with line numbers, parse in executors, split rows and rejects (same pattern as I2).
   - `Delta.overwrite(rows, Tables.bronze("rxnorm_names"))`; `Rejects.write(rejects)` with `file = "RXNCONSO.RRF"`.
   - Check lines = rows + rejects. Call `RunManifest.record("rxnorm", id, sha256, Some(<today yyyyMMdd>))` only after the ingredient map below is also written.
   `IngredientMapBuilder` (same release, same skip rule):
   - Parse `RXNREL.RRF` like `RXNCONSO.RRF` (line numbers, rejects with `file = "RXNREL.RRF"`), keeping only the relationships listed in Context.
   - Term type per concept: from the parsed names, `SAB = RXNORM` rows, one `tty` per `rxcui` (if a concept has several, prefer `IN`, then `PIN`, `MIN`, `BN`, then any).
   - Start with every `IN` concept mapped to itself. Then repeat up to `medsignal.rxnorm.maxIngredientHops` times: join the concepts mapped so far with the relationship edges to map the concepts one step further from the ingredient. Stop early when a pass adds no rows. Use typed Datasets and joins, not a driver-side loop over rows.
   - Output `RxNormIngredientMap(rxcui, ingredientRxcui, tty)`, distinct, where `ingredientRxcui` is always an `IN` concept. `Delta.overwrite(map, Tables.bronze("rxnorm_ingredient_map"))`.
   - Count for the results file: concepts by `tty` with and without an ingredient. Concepts with no path to an ingredient are not rejects; they are simply absent.
4. `RxClassLoader` (called by the same stage, same cadences):
   - Formulary `rxcui` list = `Delta.readOrEmpty[FormularyDrug](Tables.bronze("formulary")).map(_.rxcui).distinct`. If it is empty, log `bronze.formulary is empty; run bronze.formulary first` and return `StageResult(0, 0, 0)`.
   - For each formulary `rxcui` without a saved response (all of them under `Full`), call RxClass at no more than `medsignal.http.requestsPerSecond`, save the body unchanged.
   - Read the saved files with Spark's JSON reader, `multiLine = true`, an explicit schema for the path above, and the `rxcui` taken from the file name. Explode to one row per class; `distinct`.
   - A response that does not parse, or an ingredient with no class, becomes one `Reject` (`reason = "unparseable response"` or `"no class returned"`, `file = "<rxcui>.json"`, `line = 0`).
   - `Delta.overwrite(rows, Tables.bronze("rxclass"))`; `Rejects.write(rejects)`; `RunManifest.record("rxclass", <SHA-256 of the sorted formulary rxcui list joined by commas, first 16 hex>, <same>, Some(<today>))`; return a `StageResult` with `rowsIn` = class entries read. The `relaSource` comes from `Settings.config.getString("medsignal.rxnorm.relaSource")`.
5. Run with `sbt "pipeline/runMain medsignal.common.StageRunner bronze.rxnorm --cadence full"` (after `bronze.formulary` has run).
