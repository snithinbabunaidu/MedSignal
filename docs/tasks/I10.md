## Goal

A pipeline stage that loads the CMS "Medicare Part D Spending by Drug" file with TableParser into `bronze.partd_drug`: claims and beneficiaries per drug and year. FAERS has no count of patients exposed (data issue 15); V8 uses these claims to show reports per 100,000 claims.

## Context

Read `docs/contracts.md` (bronze `partd_drug`, Common library), `docs/data-sources.md` (Medicare Part D row), `docs/data-issues.md` issue 15 and `docs/decisions/F4-tableparser-in-spark.md` (how TableParser was driven).

Believed facts about the file; download it, open it and correct this list in the results file:

- Published on `https://data.cms.gov` as "Medicare Part D Spending by Drug", one CSV per release. Find the dataset page and the CSV link by hand; the link changes with each release, so the file is placed manually (below) and no URL is hard-coded.
- The CSV is comma-separated with a header and quoted fields (drug names can contain commas), so quote handling must be on, unlike FAERS.
- It is wide: one row per brand name and manufacturer, with a block of columns per year for about five years. Expected columns: `Brnd_Name`, `Gnrc_Name`, `Tot_Mftr`, `Mftr_Name`, then for each year `Tot_Spndng_<yyyy>`, `Tot_Dsg_Unts_<yyyy>`, `Tot_Clms_<yyyy>`, `Tot_Benes_<yyyy>` and more.
- Each brand has one row with `Mftr_Name = Overall` (the total across manufacturers) and further rows per manufacturer. Only `Overall` rows are loaded; loading both would count claims twice.
- `Tot_Benes_<yyyy>` is blank when CMS suppresses a small count. A blank `Tot_Clms_<yyyy>` means the drug had no data that year.

The contract's table is long, not wide: one row per (line, year), carrying both `genericName` and `brandName`. Several brands share a generic name, so `(year, genericName)` is not unique in bronze; V8 sums them.

The stage name is `bronze.partd` (contracts.md, Stage names). The stage returns `StageResult` and never calls `RunMetrics.record`; `StageRunner` records the metrics (decision 6). Rejects are written with `Rejects.write(...)`.

The wide, year-suffixed header means the columns are not known at compile time. Find in the TableParser 1.7.2 source how to get a row as cells addressed by header name (a raw or untyped row). If that is not available, parse each line into cells with TableParser's line parser and look cells up by header position yourself. Record which was used.

## Inputs

`Settings.rawDir("partd")/*.csv`, placed by hand. Several releases may be present; later releases overlap earlier years.

## Outputs

- `Tables.bronze("partd_drug")`, not partitioned, replaced on each run:
  ```scala
  final case class PartDDrug(year: Int, genericName: String, brandName: String, totalClaims: Long,
                             totalBeneficiaries: Option[Long])
  ```
  Field names and order exactly as contracts.md. `genericName` is `Gnrc_Name` and `brandName` is `Brnd_Name`, both as written (only outer whitespace trimmed).
- Rejects with `source = "partd"`, `file` = CSV name, `line` = 1-based line number with the header as line 1, written with `Rejects.write(...)`.
- `run_manifest`: one entry per file, `source = "partd"`, `unit` = file name, `checksum` = `Checksum.sha256`, `watermark = Some(<latest year in the file>)`.
- `run_metrics`: one row for stage `bronze.partd`, recorded by `StageRunner` from the returned `StageResult`.

## Implementation steps

1. `PartDHeader.parse(header: String): Either[String, PartDHeader]` with `PartDHeader(generic: Int, brand: Int, manufacturer: Int, years: Seq[YearColumns])` and `YearColumns(year: Int, claims: Int, beneficiaries: Int)`. Years come from header names matching `Tot_Clms_(\d{4})` and `Tot_Benes_(\d{4})`, case-insensitive. A header without `Gnrc_Name`, `Brnd_Name`, `Mftr_Name` or any year block is a `Left`; the stage then fails for that file with the message.
2. `PartDLineParser`:
   ```scala
   sealed trait LineResult
   final case class Rows(rows: Seq[PartDDrug]) extends LineResult
   case object ManufacturerDetail extends LineResult          // not Overall: skipped by design, counted
   final case class Bad(reason: String) extends LineResult
   def parse(h: PartDHeader)(line: String): LineResult
   ```
   Rules: wrong field count gives `Bad("expected N fields, found M")`; `Mftr_Name` other than `Overall` (case-insensitive, trimmed) gives `ManufacturerDetail`; empty `Gnrc_Name` gives `Bad("missing Gnrc_Name")`; empty `Brnd_Name` gives `Bad("missing Brnd_Name")`; each row carries `brandName` from `Brnd_Name`; for each year, blank claims gives no row for that year, non-numeric claims gives `Bad("bad Tot_Clms_<yyyy>: <value>")` for the whole line, blank or non-numeric beneficiaries gives `None`. Numbers may carry thousands separators or a decimal point; check the real file and handle what is there.
   A quoted field can in principle contain a line break; check the real file. If it happens, such lines fail the field count and are rejected; report how many.
3. Stage (`name = "bronze.partd"`, `cadences = Set(Cadence.Full)`):
   - For each CSV: read lines with line numbers (`rdd.zipWithIndex`), parse the header on the driver, parse lines in `mapPartitions` (build the parser there), persist the result.
   - Accounting per file, checked with an exception on mismatch: data lines = `Overall` lines parsed + manufacturer lines skipped + lines rejected.
   - When several files cover the same year, keep rows from the newest release only (the file with the greatest latest year) for that year.
   - `Delta.overwrite(rows, Tables.bronze("partd_drug"))`; `Rejects.write(rejects)`; `RunManifest.record` per file (its watermark carries the latest year).
   - Return `StageResult(rowsIn = data lines, rowsOut = rows written, rowsRejected)`. Do not call `RunMetrics.record`; `StageRunner` times the stage and records the row. Note in the results file that `rowsOut` is in (line, year) units, so it is not comparable with `rowsIn`; the line accounting above is the check.
   - No file present: log `bronze.partd: no file in <path>` and return `StageResult(0, 0, 0)`.
4. Run: `sbt "pipeline/runMain medsignal.common.StageRunner bronze.partd --cadence full"`.
5. No `var`, no `null`.
