## Goal

FAERS has no count of patients who took a drug, so a widely used drug collects more reports simply by being used more. This task puts a denominator beside the reports: Medicare Part D claims per drug and year, giving reports per 100,000 claims for each drug and for each signal.

## Context

- Read `docs/contracts.md` (rows `partd_drug`, `drug_xref`, `case`, `case_drug`, `case_reaction`, and the final section, which wins); `docs/tasks/S2.md` for `DrugIdentity.ensureResolved` and `NameCandidate`; `docs/tasks/I10.md`; `docs/tasks/A3.md` step 6.
- `PartDDrug(year, genericName, brandName, totalClaims, totalBeneficiaries)`. The I10 brief shows it without `brandName`; contracts.md is right. Only `genericName` is used for identity.
- Limits, to be written in the results file and never softened:
  - Part D covers Medicare patients only (mostly 65 and over); FAERS reports come from all patients and many countries. The rate is a rough scale, not a rate in any real population.
  - Spontaneous reports are not incidence. Most events are never reported, and reporting varies by drug and year.
  - Part D years lag; FAERS years with no Part D file have no rate.
- Do not edit G3's `Signal`. The per-signal rate goes in a separate table.
- This task owns no path in `publish/` or `app/`. A3 already hides its optional column when `GET /api/exposure` returns 404. Getting the rate onto the Signals page needs a publisher and a route, which is a backlog change; see Done when.

## Outputs

Both in gold, `Delta.overwrite`, defined in `medsignal.advanced.exposure`:

```scala
final case class Exposure(rxcui: String, year: Int, totalClaims: Long,
  reportsPer100kClaims: Option[Double])       // key (rxcui, year); reports = distinct FAERS cases of the drug in that year
final case class SignalExposure(rxcui: String, term: String, year: Int,
  reportsPer100kClaims: Option[Double])       // key (rxcui, term, year); reports = distinct cases with the drug and the term
```

The rate is `Option` because contracts forbid `null` and the rate is absent below `minClaims`. Rate = `reports * 100000.0 / totalClaims`.

## Implementation steps

1. `ClaimsByDrug.claims(partd, xref): Dataset[DrugYearClaims]` with `DrugYearClaims(rxcui, year, totalClaims)`. Call `DrugIdentity.ensureResolved` with the distinct `genericName` values (build candidates as S2's brief shows; use its key function, not your own), join back on the same key, keep rows with `rxcui` defined, and sum `totalClaims` per (`rxcui`, `year`). Several brands of one generic sum together.
2. Combination products resolve to one row per ingredient (decision 10). Count the claims for each ingredient; state this in the results, since it counts those claims more than once across drugs.
3. If the Part D file has an "Overall" manufacturer row besides per-manufacturer rows, summing double counts. Check what I10 loaded (`docs/results/I10.md`) and test with a fixture of that shape.
4. `ExposureRates.byDrug(cases, caseDrug, claims)`: year = first four characters of `Case.quarter`; distinct `caseid` per (`rxcui`, year); inner join to claims.
5. `ExposureRates.bySignal(...)`: the same with `case_reaction`, restricted to pairs in `gold.Signal` (broadcast the pairs).
6. `ExposureStage` (`name = "advanced.exposure"`, `cadences = Set(Quarterly, Full)`): write both tables; return `StageResult`. Never call `RunMetrics.record` (decision 6). Unresolved generic names are counted, not rejected (decision 18).
7. `docs/results/V8.md`: Part D years loaded; share of generic names and of claims resolved; formulary drugs with and without a rate; the top 20 signals by `score` beside the top 20 by rate for the latest common year, to show how the order changes; the limits from Context.
