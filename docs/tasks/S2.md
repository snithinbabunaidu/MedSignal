## Goal

`silver.drug_xref` maps every distinct drug name string to RxNorm ingredient identifiers, with the method used and a confidence. It is the only place in the project where a name becomes an `rxcui`; FAERS, labels and recalls all join through it, so a fix here fixes every downstream table.

## Context

- FAERS drug names are free text: brands, doses, forms, misspellings. FAERS also carries `prod_ai`, an active-ingredient column filled in by the FDA, which is far cleaner.
- Resolution runs on DISTINCT strings (hundreds of thousands), never on the tens of millions of drug rows.
- Order of resolution, first hit wins (contracts.md, decision 10): override file, `prod_ai`, exact normalized, dose and form stripped. An override always wins, and adding an override re-resolves that string. Unmatched strings are kept as one row with `rxcui = None`.
- A combination product maps to each ingredient, so one `rawName` can have several rows.
- Incremental: a string already in the table is not recomputed, with one exception: a string that has a row in the override file is re-resolved, so a new or changed override replaces the rows that string already has.
- Read: `docs/contracts.md` (Common library, Bronze tables, Silver tables), `docs/pipeline-spec.md` section 2, `docs/architecture.md` ("Decisions that matter most", item 1), `docs/data-issues.md` rows 5 and 6, `docs/acceptance-criteria.md` row 2.

Two facts to verify before coding:

1. What `bronze.rxnorm_ingredient_map` covers. `bronze.rxnorm_names.rxcui` is each concept's own identifier, so only rows with `tty = "IN"` are ingredients themselves. I3 also writes `bronze.rxnorm_ingredient_map(rxcui, ingredientRxcui, tty)`, which maps brand (`BN`), salt (`PIN`) and product concepts to their ingredient (contracts.md, decision 4). The name index uses `IN` rows as they are and every other row through this map. Check which `tty` values the map holds and whether a combination concept has one row per ingredient, and record both in the results file; do not parse RxNorm relationship files here.
2. The separator FAERS uses between ingredients in `prod_ai`. It is believed to be a backslash (`AMLODIPINE BESYLATE\BENAZEPRIL HYDROCHLORIDE`). Confirm with `select prod_ai from faers_drug where prod_ai like '%\\%' limit 20`.

## Outputs

`silver.drug_xref`, appended with `Delta.append` (rewritten with `Delta.overwrite` only when an override changes rows that already exist, see step 4):

```scala
package medsignal.identity
final case class DrugXref(rawName: String, rxcui: Option[String], method: String, confidence: Double)
```

`method` is one of `override`, `prod_ai`, `exact`, `stripped`, `none`. Fixed confidences: `override` 1.0, `prod_ai` 0.95, `exact` 0.90, `stripped` 0.70, `none` 0.0. `rawName` is always `DrugNames.key(original string)`. Rows are unique on (`rawName`, `rxcui`), which is the key in contracts.md: a combination product has one row per ingredient, and an unmatched string has one row with `rxcui` empty.

`data/reference/drug_overrides.csv`, header `rawName,rxcui,note`, one row per ingredient (two rows for a two-ingredient product).

## Implementation steps

1. Pure string functions:

   ```scala
   object DrugNames {
     def key(s: String): String                     // trim, upper-case, collapse runs of whitespace
     def normalize(s: String): String               // key, then every non-alphanumeric to a space, collapse
     def strip(s: String): String                   // normalize, then remove dose, unit, form and salt tokens
     def splitCombination(s: String): Seq[String]   // on  \  /  +  ;  " AND "  " WITH " ; applied to key(s)
   }
   ```

   `strip` removes: text in parentheses; number tokens and number-plus-unit tokens (`500`, `500MG`, `0.5`, `10 ML`); unit words (`MG, MCG, G, ML, IU, UNIT, UNITS, MEQ`, percent); form words (`TABLET(S), TAB, CAPSULE(S), CAP, INJECTION, SOLUTION, SUSPENSION, CREAM, OINTMENT, PATCH, ORAL, ER, XR, SR, CR, EXTENDED, RELEASE, USP`); salt words (`HYDROCHLORIDE, HCL, SODIUM, POTASSIUM, PHOSPHATE, SULFATE, MALEATE, TARTRATE, MESYLATE, BESYLATE, SUCCINATE, ACETATE, CITRATE, FUMARATE`). Keep the lists in `strip_words.txt`. If stripping leaves nothing, return the normalized string unchanged. Whole-string exact matching always runs first, so `SODIUM CHLORIDE` still resolves.

2. Name index:

   ```scala
   final class NameIndex(byName: Map[String, Seq[String]]) extends Serializable {
     def lookup(normalized: String): Option[Seq[String]]   // ingredient rxcuis; more than one for a combination brand or product
   }
   object NameIndex { def build(names: Dataset[RxNormName], ingredientMap: Dataset[RxNormIngredientMap]): NameIndex }
   ```

   For each `RxNormName` row find its ingredient `rxcui`s: a `tty = "IN"` row is its own ingredient; any other row (brand, salt, product) is joined to `bronze.rxnorm_ingredient_map` on `rxcui` and takes every `ingredientRxcui` (a row with no map entry is left out). Key by `DrugNames.normalize(name)`. A normalized name whose concepts lead to different ingredient sets is ambiguous: leave it out of the index and count it. Collect the index and broadcast it.

3. Resolver (pure, the heart of the task):

   ```scala
   final case class NameCandidate(rawName: String, prodAi: Option[String])
   object Resolver {
     def resolve(c: NameCandidate, index: NameIndex, overrides: Map[String, Seq[String]]): Seq[DrugXref]
   }
   ```

   Helper `ingredients(text, f)`: try `index.lookup(f(text))`; if that misses, split with `splitCombination` and look up `f(part)` for each part; succeed only when every part resolves; return the distinct `rxcui`s. Then, in this order (contracts.md, decision 10):

   1. `override`: `overrides.get(key(rawName))`. An override always wins, even when `prod_ai` or the name would also resolve.
   2. `prod_ai`: if `prodAi` is present, `ingredients(prodAi, normalize)`, else `ingredients(prodAi, strip)`.
   3. `exact`: `ingredients(rawName, normalize)`.
   4. `stripped`: `ingredients(rawName, strip)`.
   5. Otherwise one row with `rxcui = None`, method `none`.

   Return one `DrugXref` per ingredient. Never return an empty sequence.

4. Spark API:

   ```scala
   object DrugIdentity {
     /** Contract entry point (contracts.md, decision 10), called by S4 and S5 with label and recall names: same as ensureResolvedCandidates with prodAi = None. */
     def ensureResolved(names: Dataset[String])(implicit spark: SparkSession): Dataset[DrugXref]
     /** Resolves the candidates not yet in silver.drug_xref, appends them, returns all rows for the given names. Used by this stage, which also has prod_ai. */
     def ensureResolvedCandidates(candidates: Dataset[NameCandidate])(implicit spark: SparkSession): Dataset[DrugXref]
     /** Re-resolves every string that has an override row and whose rows in the table differ from the override; rewrites the table. Returns rows changed. */
     def applyOverrides()(implicit spark: SparkSession): Long
     /** After a new RxNorm release: re-resolves rows with method "none" and rewrites the table. Returns rows changed. */
     def reresolveUnmatched()(implicit spark: SparkSession): Long
   }
   ```

   `ensureResolved` wraps each name in `NameCandidate(name, None)` and calls `ensureResolvedCandidates`. `ensureResolvedCandidates`: first call `applyOverrides()`, then apply `key` to `rawName`, `distinct`, `left_anti` join on `rawName` against the existing table (a table that does not exist yet counts as empty), `flatMap` with the broadcast index and overrides, `Delta.append`. Appending only anti-joined strings is what makes a re-run add nothing. `reresolveUnmatched` reads the table, re-resolves the `none` rows (with `prodAi = None`), unions them with the untouched rows and calls `Delta.overwrite`; resolved rows are passed through unchanged. `applyOverrides` reads the table and the override file; for each `rawName` in the override file whose existing rows are not exactly the override rows (method `override`, same `rxcui`s), it drops that string's rows, adds the override rows, and calls `Delta.overwrite`; when nothing differs it writes nothing, so a re-run stays a no-op. This is how adding an override re-resolves that string. Cover the read-then-overwrite of the same table with a test.

5. FAERS candidates in `DrugXrefStage` (`name = "identity.drug_xref"`, `cadences = Set(Quarterly, Full)`): distinct `key(drugname)`; anti-join against the existing table first; only for the new keys, pick the most frequent non-empty `prod_ai` (ties: alphabetically first) with a `groupBy` and a window; pass to `ensureResolvedCandidates`. Rows with an empty `drugname` and a `prod_ai` use `key(prod_ai)` as `rawName`. S3 must build its join key the same way, so expose `DrugIdentity.faersKey(drugname: String, prodAi: Option[String]): String`.

6. Metrics: return `StageResult(rowsIn = new distinct strings, rowsOut = rows appended plus rows changed by overrides, rowsRejected = 0)`. The stage does not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics from the `StageResult`. Unmatched strings are kept in the table with method `none` and counted in the results file; they are not `Reject` rows (contracts.md, decision 18).

7. Override file: read with TableParser following the pattern I3 uses for small delimited files (see the F4 decision record). Start with a header only. After the first real run, add rows for the most frequent unmatched strings that are clearly formulary drugs (brand names are the expected case). Take each `rxcui` from `bronze.formulary` (loaded by F6 from `data/reference/formulary.csv`); never type one from memory.

8. `IdentityReport`:
   - Overall: share of `bronze.faers_drug` rows whose key resolves to at least one `rxcui`.
   - Formulary (criterion 2). The criterion does not define its denominator, so use this: a FAERS drug row is a "formulary mention" when `normalize(drugname)` or `normalize(prod_ai)` contains a formulary `ingredient` name as a whole word. Numerator: those rows whose key resolves. Report numerator, denominator and rate. Brand-only mentions are outside this denominator; say so in the results file.
   - Unmatched strings by mention count, top 200.

9. `stages/identity.drug_xref.conf`: `class = "medsignal.identity.DrugXrefStage"`, `after = ["bronze.faers", "bronze.rxnorm"]` (I2's and I3's stages, as listed in contracts.md).

## Tests

- `DrugNamesSpec`: "normalizes case, punctuation and spaces" (`" Metformin-HCl  "` gives `METFORMIN HCL`); "strips dose and form" (`METFORMIN HCL 500 MG TABLETS` gives `METFORMIN`); "keeps the string when stripping empties it"; "splits combinations" (`A\B`, `A / B`, `A AND B` give two parts).
- `ResolverSpec`, one case per method on hand-made names: "an override wins over prod_ai and the name" (`rawName = "METFORMIN"`, `prodAi = "METFORMIN HYDROCHLORIDE"` and an override row to another `rxcui` gives the override `rxcui`, `override`, 1.0); "a brand name resolves through the ingredient map" (a `BN` row mapped to its ingredient); "prod_ai wins over the name" (`rawName = "GLUCOPHAG"`, `prodAi = "METFORMIN HYDROCHLORIDE"` gives metformin, `prod_ai`, 0.95); "exact" (`metformin`); "stripped" (`METFORMIN 500MG TAB`); "override" (`JARDIANCE` with an override row); "none" (`XYZZY` gives one row, `rxcui = None`); "a combination product yields two rows" (`EMPAGLIFLOZIN\LINAGLIPTIN`); "a half-resolved combination is unmatched"; "an ambiguous name does not match".
- `DrugIdentitySpec` (Spark): "idempotent on re-run" (second run appends zero rows; table is identical); "new strings only" (add one name, exactly its rows are appended); "re-resolve fills a previously unmatched string after the index gains the name and leaves resolved rows unchanged"; "adding an override re-resolves that string" (a string already resolved by `exact` gets an override row; after the next run its only rows are the override rows, and a further run changes nothing).
