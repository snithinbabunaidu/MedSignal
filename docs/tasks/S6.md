## Goal

Every row of `docs/data-issues.md` has a measured number from the real data in its "Measured" column, and any new problem found while building bronze and silver is added with its size. The document is the project's honest statement of what the data is like and what was done about it.

## Context

- This is a documentation task. It adds no code to the repository and changes exactly one file.
- Feature branches never edit `docs/data-issues.md`. They write their numbers to `docs/results/<task id>.md`; this task collects them (see `docs/branching.md`, "Shared files").
- Read: `docs/data-issues.md`, every file in `docs/results/` that exists (I2, I3, S1 to S5 at least), `docs/contracts.md` (table names).
- A number means a count and, where it makes sense, a rate with its denominator: "1,204,311 of 19,880,412 DEMO rows (6.1%)", not "about 6%".

## Inputs

- `docs/results/I2.md`, `S1.md`, `S2.md`, `S3.md`, `S4.md`, `S5.md`.
- The Delta tables under `data/bronze`, `data/silver` and `data/ops`, queried from a Spark shell for anything the results files do not hold.

## Outputs

`docs/data-issues.md` with the same table and columns, the "Measured" column filled, and new rows appended for new issues (numbered from 17).

## Files to create

None. One file is edited: `docs/data-issues.md`.

## Implementation steps

1. Split the rows. Nithin: 1 to 7, 11, 12, 14 to 16. Zenish: 8, 9, 10, 13. Both commit to the one branch; each reviews the other's numbers.

2. Fill each row from the source below. Where a results file already has the number, copy it and name the file. Otherwise run the query in a Spark shell against the full data. Do not commit the queries; paste them in the pull request description so the numbers can be reproduced.

   | # | Number to record | Source |
   |---|---|---|
   | 1 | Superseded versions removed, as a count and a share of DEMO rows | `docs/results/S1.md` |
   | 2 | Deleted cases removed | `docs/results/S1.md` |
   | 3 | Rejected lines and reject rate per FAERS file type | `docs/results/I2.md`, or `data/ops/rejects` grouped by `file` and `reason` |
   | 4 | Number of distinct header layouts seen per file type, and the quarters where they change | `docs/results/I2.md` or the F4 decision record |
   | 5 | Share of FAERS drug mentions unresolved, overall and for formulary drugs; rows per method | `docs/results/S2.md` |
   | 6 | Distinct names that map to more than one ingredient: `drug_xref` grouped by `rawName` having `count(rxcui) > 1` | query |
   | 7 | Cases with a partial received date; cases with none | `docs/results/S1.md` |
   | 8 | Formulary ingredients with more than one label `setId`; median labels per ingredient; ingredients with no reference label | `docs/results/S4.md` |
   | 9 | Recall on the gold set | Not measurable yet: needs L7. Write "pending L7 (criterion 5)" |
   | 10 | Negation accuracy on the gold set | Same: "pending L7 (criterion 5)" |
   | 11 | Formulary (drug, reaction) pairs where the reaction term is also an indication term for that drug in at least 3 cases, and the share of all pairs with at least 3 cases | query below |
   | 12 | Formulary drugs with at least one quarter of 5 or more cases that is at least 3 times the previous quarter | query below; G3 later stores the flag per signal |
   | 13 | Share of recalls with no `rxcui` | `docs/results/S5.md` |
   | 14 | No size applies. Write "applies to 100% of reports; no causality field is used" | none |
   | 15 | Write "0 exposure counts in FAERS; measured in V8" | none |
   | 16 | Reaction terms first seen after the first four quarters, and terms not seen in the last four quarters | query below |

   ```scala
   // 11
   val pairs = caseDrug.join(caseReaction, "caseid").groupBy("rxcui", "term").agg(count("*").as("n")).where("n >= 3")
   val indi  = caseIndication.groupBy("rxcui", "term").agg(countDistinct("caseid").as("ni")).where("ni >= 3")
   pairs.join(broadcast(formulary.select("rxcui")), "rxcui").join(indi, Seq("rxcui", "term"), "left_semi").count()

   // 12
   val q = caseDrug.join(cases.select("caseid", "quarter"), "caseid").groupBy("rxcui", "quarter").agg(count("*").as("n"))
   val w = Window.partitionBy("rxcui").orderBy("quarter")
   q.withColumn("prev", lag("n", 1).over(w)).where("n >= 5 and n >= 3 * prev")
     .join(broadcast(formulary.select("rxcui")), "rxcui").select("rxcui").distinct().count()

   // 16
   val firstLast = caseReaction.join(cases.select("caseid", "quarter"), "caseid")
     .groupBy("term").agg(min("quarter").as("first"), max("quarter").as("last"))
   ```

   In these queries `formulary` is `bronze.formulary` (loaded by F6), read with `Delta.read`; do not read the CSV file. `lag` in query 12 looks at the previous row, which is the previous quarter only when the drug has cases in every quarter. That is true for most formulary drugs; say so beside the number.

3. Check the "Handling" and "Status" text of each row against what was built. If the build did something different (for example S1's rule for the case quarter, or S4's rule for combination labels), correct the text.

4. Add new issues. Read the "surprises" in every results file and add one row each, with handling, status and size. Known candidates from the briefs: recalls carry one `rxcui` although products can be combinations (S5); brand, salt and product names resolve only through `bronze.rxnorm_ingredient_map` (S2; record how many names that map does not cover); suspect drug rows left unresolved are counted, not rejected (S3); any recall that still appears more than once in bronze although `recall_raw` is upserted by `recall_number` (S5).

5. Keep the table format unchanged: other documents link to row numbers.
