## Goal

One pipeline stage, `quality.checks`, that runs six kinds of check over the tables and the run's metrics, writes every result to `data/ops/check_result`, and fails the run with a clear message when any check fails. Bad data then stops before it is published.

## Context

Read `docs/pipeline-spec.md` section 8, `docs/contracts.md` (table lists with keys; Common library; final section items 1, 6, 9 and "Stage names"), and briefs `docs/tasks/F7.md`, `C1.md`, `L7.md` (`ExtractionScore`).

Facts and decisions this brief fixes:

- Rule-based checks only: comparisons against thresholds.
- This is a stage named `quality.checks` (contracts.md), not a per-stage hook. It runs once, after the data stages and before `publish.serving`. A failure is an exception thrown from `run`; the orchestrator (C1) stops the run and exits with code 2.
- C5 depends only on F7, so it may merge before the tables it checks exist. Therefore the list of tables is configuration, not imports, and a table or class that is absent gives a `skipped` result, never a failure.
- The case-class schema is derived from a class name at run time. Whether Spark 4.0 offers a supported way to get a `StructType` from a runtime class (for example through `ScalaReflection` and a runtime mirror) must be checked against the Spark documentation and source for the version in `build.sbt`. Fallback: a hand-written `Seq[TableSpec]` using `Encoders.product[T].schema`, added once the other tasks are merged.
- Previous values for the row-count check come from this stage's own `check_result` rows, so no other task's table layout is assumed.
- `run_metrics` and `extraction_score` are read as DataFrames by column name (`stage`, `runId`, `rowsIn`, `rowsRejected`, `newestSourceDate`; `precision`, `recall`, `scoredAt`, `regressed`). Check the real column names in F7's and L7's code.

## Inputs

- Every table listed in `medsignal.quality.tables`.
- `Tables.ops("run_metrics")`, `Tables.ops("extraction_score")`, `Tables.ops("check_result")`.
- `Settings.config`, defaults in `conf.d/C5.conf`:
  ```hocon
  medsignal.quality {
    rowCount { maxDropShare = 0.05, maxGrowthShare = 0.50 }
    rejects  { maxShare = 0.01, perStage { } }              # perStage."bronze.faers" = 0.02 overrides
    freshness.maxAgeDays { "bronze.faers" = 200, "bronze.labels" = 7, "bronze.recalls" = 14, "bronze.rxnorm" = 200 }
    extraction { tolerance = 0.0, minPrecision = 0.0, minRecall = 0.0 }
    tables = [ { table = "silver.case", class = "medsignal.silver.cases.Case", keys = ["caseid"] } ]
  }
  ```
  `tables` lists every silver and gold table in contracts.md with its key columns and class; find each class's real package by searching the code.

## Outputs

`Tables.ops("check_result")`, appended:

```scala
final case class CheckResult(runId: String, check: String,        // schema, row_count, rejects, freshness, keys, extraction
                             target: String,                      // table or stage name
                             status: String,                      // pass, fail, skipped
                             observed: Option[Double], threshold: Option[Double],
                             message: String, checkedAt: java.sql.Timestamp)
```

## Implementation steps

1. Checks. Each takes plain inputs (datasets, numbers, thresholds), so it is testable without the stage.

   | check | Passes when | First run or missing input |
   |---|---|---|
   | `schema` | the table's column names and data types equal the case class's, ignoring column order and nullability | `skipped` |
   | `row_count` | `prev * (1 - maxDropShare) <= now <= prev * (1 + maxGrowthShare)`, where `prev` is `observed` of the newest earlier `row_count` row for the table | `pass`, message "no previous count" |
   | `rejects` | for each stage row of this `runId` in `run_metrics` with `rowsIn > 0`: `rowsRejected / rowsIn <= maxShare` (or the stage's override) | `skipped` |
   | `freshness` | for each stage in `maxAgeDays`: run date minus its newest `newestSourceDate` in `run_metrics` is at most the limit | `skipped` |
   | `keys` | `count == distinct count over the key columns`; `observed` = number of duplicated keys | `skipped` |
   | `extraction` | newest score has `precision` and `recall` not below the last accepted, minus `tolerance`. Last accepted = the newest earlier row with `regressed = false`; with none, the `minPrecision` and `minRecall` floors | `skipped` |
2. `QualityStage` (`name = "quality.checks"`, `cadences = Set(Daily, Weekly, Quarterly, Full)`):
   1. Build specs from config; for each existing table run `schema`, `row_count`, `keys`; then `rejects`, `freshness`, `extraction` once.
   2. `Delta.append` all results, passes included.
   3. If any result is `fail`, throw `QualityCheckFailed` whose message has one line per failure: check, target, observed, threshold. Example: `keys silver.case: 3 duplicated keys (allowed 0)`.
   4. Otherwise return `StageResult(rowsIn = checks run, rowsOut = results written, rowsRejected = 0)`. Do not call `RunMetrics.record`; the runner records. No `Reject` rows: a failed check is not a rejected input row.
3. `stages/quality.checks.conf`: `class = "medsignal.quality.QualityStage"`, `after` = every other stage name in contracts.md except `publish.serving`, `always = true`. A1 lists `quality.checks` in its own `after`.

## Tests

`ChecksSpec` (`SparkTestSession`). Each check has one passing test and one test that makes it fail:

- "schema fails when a column is missing" and "when a type differs".
- "row count fails on a drop beyond tolerance"; "passes with no previous count".
- "rejects fails when a stage is over its threshold"; "a per-stage override applies".
- "freshness fails when the newest source date is too old".
- "keys fails on a duplicated key" with the duplicate count in `observed`.
- "extraction fails when recall is below the last accepted".

`QualityStageSpec`:

- "a failed check fails the run with a clear message": the exception message names the check and table, and the result rows were written before the throw.
- "an absent table is skipped, not failed".
- "all passing returns counts and writes one row per check".

## Done when

## Out of scope

- Fixing data that fails a check. Computing extraction scores (L7).
- Publishing or showing `check_result` (A1, A2, A3); tell their owners the columns.
- Editing C1 or any checked task's code.
