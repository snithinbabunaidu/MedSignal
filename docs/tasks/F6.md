## Goal

A reviewed list of about 150 drug ingredients that the hypothetical hospital stocks. Everything the application shows is scoped to this list: signals, labels, recalls and the backtest. The list must contain the drugs behind the known FDA warnings, or the backtest (V2) has nothing to find. This task also owns the small reference loader that loads the CSV into the bronze table `bronze.formulary` (stage name `bronze.formulary`); every other task reads that bronze table, not the CSV file (contracts.md, decision 3).

## Context

Read `docs/data-sources.md` ("Reference files kept in the repository", "Known FDA warnings in the formulary's classes"), `docs/contracts.md` (bronze table `formulary`, case class `FormularyDrug`; convention: `rxcui` is the RxNorm ingredient identifier as a `String`) and `docs/branching.md` (reference data, shared tasks split by row).

Also read the final section of `docs/contracts.md` ("Decisions settled after the first draft of the briefs": decisions 1, 2, 3, 6, 7 and 17, "Common library (F7) additions" and "Stage names"). The loader part of this task uses `medsignal.common` (F7: `Stage`, `StageResult`, `Delta`, `Tables`, `Settings`, `Rejects`, `SparkTestSession`), so write the loader once F1 and F7 are merged; the CSV itself needs neither.

The file is read by this task's loader with TableParser, which matches header names to case-class fields. So the header uses the `FormularyDrug` field names exactly (`rxcui,ingredient,drugClass,reason`; contracts.md, decision 17). The backlog wording ("rxcui, ingredient, class, reason included") describes the same four columns.

An ingredient `rxcui` is an RxNorm concept with term type `IN` (single ingredient). Not `MIN` (multiple ingredients), `BN` (brand), `PIN` (precise ingredient, for example a salt) or a product. Combination products are covered by listing each ingredient.

## Inputs

RxNav, to look up and check identifiers (no account needed):

- Find: `https://rxnav.nlm.nih.gov/REST/rxcui.json?name=canagliflozin&search=2`
- Check: `https://rxnav.nlm.nih.gov/REST/rxcui/<rxcui>/properties.json` returns `properties.tty` and `properties.name`.

Verify the response shape on the first call; do not copy identifiers from memory or from a chat tool.

## Outputs

`data/reference/formulary.csv`, UTF-8, comma-separated, header row, one row per ingredient:

| Column | Type | Rule |
|---|---|---|
| `rxcui` | String | RxNorm `IN` identifier; unique in the file |
| `ingredient` | String | RxNorm name, lower case, exactly as `properties.name` |
| `drugClass` | String | One of the seven values below, spelled exactly |
| `reason` | String | Why it is on the list, under 80 characters, no commas |

Allowed `drugClass` values: `SGLT2 inhibitor`, `DPP-4 inhibitor`, `Fluoroquinolone`, `Sleep drug`, `Gabapentinoid`, `Asthma and allergy`, `Hospital common`.

Example row shape (look the identifier up; this one is a placeholder): `<rxcui>,canagliflozin,SGLT2 inhibitor,FDA warning 2017 amputation`.

Bronze Delta table `bronze.formulary` at `Tables.bronze("formulary")`, unpartitioned, one row per CSV row, written by stage `bronze.formulary`:

```scala
package medsignal.bronze.reference.formulary
final case class FormularyDrug(rxcui: String, ingredient: String, drugClass: String, reason: String)
```

The case class lives in this task's package (contracts.md, decision 2); other tasks import it and do not redefine it.

## Implementation steps

1. Both engineers work on the one branch and split by row, so there is no overlap:
   - Nithin: `SGLT2 inhibitor`, `DPP-4 inhibitor`, `Fluoroquinolone`, `Gabapentinoid`, and `Hospital common` ingredients starting with A to L.
   - Zenish: `Sleep drug`, `Asthma and allergy`, and `Hospital common` ingredients starting with M to Z.
   Keep rows sorted by `drugClass`, then `ingredient`, so the two halves do not touch the same lines.
2. Must-have ingredients (from the known warnings table): canagliflozin, dapagliflozin, empagliflozin, ertugliflozin; sitagliptin, saxagliptin, linagliptin, alogliptin; ciprofloxacin, levofloxacin, moxifloxacin, ofloxacin, and any other fluoroquinolone marketed in the US since 2014; zolpidem, eszopiclone, zaleplon; gabapentin, pregabalin; montelukast.
3. Fill each warning class with the other marketed members of that class, plus for `Sleep drug` and `Asthma and allergy` the common alternatives (other hypnotics; other leukotriene modifiers, inhaled steroids, antihistamines). These act as comparison drugs with no known warning.
4. `Hospital common`: about 100 widely used hospital ingredients across anticoagulants, antibiotics, analgesics, cardiovascular drugs, insulin and other diabetes drugs, antiemetics, proton pump inhibitors, anticonvulsants, antipsychotics and antidepressants. Prefer ingredients with high report volume; they test scale.
5. For every row, call the RxNav check URL and confirm `tty` is `IN` and `name` equals the `ingredient` column (case-insensitive). A short shell loop with `curl` is enough; keep it in `docs/results/F6.md` so the check can be repeated. Do not add a script file; this task owns only the CSV and the loader package.
6. Second-person review: each engineer re-runs the check on the other's rows and reads them for wrong class or missing class members. Record it in `docs/results/F6.md`.
7. Format rules: no blank lines, no trailing spaces, no quotes, Unix line endings, final newline.
8. Reference loader, `FormularyStage` (Nithin writes it; Zenish reviews):
   - `name = "bronze.formulary"`; `cadences = Set(Cadence.Daily, Cadence.Weekly, Cadence.Quarterly, Cadence.Full)` (the file is tiny and every run needs it).
   - Input path: `Settings.dataDir + "/reference/formulary.csv"`. Never hard-code `data/`.
   - Read the file as lines, skip the header, and parse each line into `FormularyDrug` with TableParser (header names match the field names). A line that does not parse, has other than four fields, or has an empty `rxcui`, `ingredient` or `drugClass` becomes a `Reject(source = "formulary", file = "formulary.csv", line = <1-based line number>, raw = <the line>, reason = <message>, runId = ctx.runId)`. A second row with an `rxcui` already seen is also a `Reject` (reason `duplicate rxcui`).
   - Write the good rows with `Delta.overwrite(rows, Tables.bronze("formulary"))`: the table is a full snapshot of the file on every run, so re-running never duplicates rows and a removed row disappears.
   - Write rejects with `Rejects.write(rejects)`.
   - Return `StageResult(rowsIn = data lines read, rowsOut = rows written, rowsRejected = rejects)`. Do not call `RunMetrics.record`; `StageRunner` records the metrics (contracts.md, decision 6).
   - Run it with `sbt "pipeline/runMain medsignal.common.StageRunner bronze.formulary"`.
   - No tunables, so no `conf.d/F6.conf` is needed. No `var`, no `null`.

## Tests

`FormularyStageSpec` (`AnyFlatSpec with Matchers with SparkTestSession`; copy the fixture to `<temp dataDir>/reference/formulary.csv` before running the stage):

- "loads every row of the file into bronze.formulary": three rows in, `StageResult(3, 3, 0)`, and `Delta.read[FormularyDrug](Tables.bronze("formulary"))` returns the three rows.
- "rejects a short row and a row without rxcui": on the `bad` fixture, `StageResult(4, 2, 2)` and two rows in `Tables.ops("rejects")` with `source = "formulary"` and the right line numbers.
- "running twice does not duplicate rows": count is still 3 after a second run.
- "is registered under the name bronze.formulary": `StageRunner.load("bronze.formulary")` returns a `FormularyStage`.
- "the committed formulary.csv loads with no rejects": run against the real `data/reference/formulary.csv`.

Checks on the data file, to run and paste into the pull request:

- Row count is between 130 and 170.
- `cut -d, -f1 formulary.csv | sort | uniq -d` prints nothing (no duplicate `rxcui`).
- Every line has exactly four fields: `awk -F, 'NF!=4' formulary.csv` prints nothing.
- Every `drugClass` is one of the seven allowed values.
- The RxNav loop reports `IN` for every row.
- Every must-have ingredient from step 2 is present.
