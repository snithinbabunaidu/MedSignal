## Goal

A check of whether the top 50 drug pairs from V4 are real: for each pair, does the drug interactions section of either drug's reference label name the other drug? The same check on random pairs gives the baseline. The result is the confirmation rate of the top 50 against random pairs (acceptance criterion 12: at least 3 times as often).

## Context

- Read `docs/acceptance-criteria.md` row 12; `docs/data-sources.md` section "Label sections used" (drug interactions is LOINC `34073-7`); `docs/contracts.md` rows `label_section`, `label_version`, `formulary`; `docs/tasks/V4.md` (`InteractionSignal`, `Interactions.topPairs`, `TopPair`).
- The label text comes from `bronze.label_section` (one row per label version and section) joined to `silver.label_version` where `isReference = true`. `isReference` is true for every version of an ingredient's reference `setId` (contracts.md decision 13), so per `rxcui` keep only the current version: the latest `effectiveDate`, ties broken by the highest `version`. Those two tables are certain to exist; do not rely on `gold.Label`.
- "Confirmed" is a text match of an ingredient name, which is simple and transparent but imperfect: labels often name a class ("diuretics", "CYP3A4 inhibitors") instead of a drug. Report the class-name match as a second number; the headline uses the ingredient-name match only.
- A pair can be checked only if at least one of its drugs has a reference label with an interactions section. Pairs that cannot be checked are counted and reported, and excluded from both rates.
- Random formulary pairs are an easy baseline: most are never taken together. So also report a harder baseline, random pairs that are co-reported in FAERS but are not in the top 50. Criterion 12 says "random pairs", so the first baseline is the headline; the second is shown beside it.
- This is an evaluation job: it runs only when `medsignal.evaluation.enabled` is `true` (default false when the key is absent).
- contracts.md lists no table for this result. This brief defines `gold.InteractionCheck` below; its case classes live in this task's package, `medsignal.advanced.interactioncheck`. `InteractionSignal` and `TopPair` are imported from `medsignal.advanced.interactions`, not redefined.
- Metrics are recorded by the runner (contracts.md decision 6): the stage returns `StageResult` and never calls `RunMetrics.record`.

## Outputs

`gold.InteractionCheck`, key (`sample`, `rxcuiA`, `rxcuiB`):

```scala
final case class InteractionCheck(
  sample: String,                // top, random_formulary, random_coreported
  rxcuiA: String, rxcuiB: String,
  nameA: String, nameB: String,
  checkable: Boolean,            // at least one drug has an interactions section
  aMentionsB: Boolean,           // B's ingredient name found in A's section
  bMentionsA: Boolean,
  confirmed: Boolean,            // aMentionsB || bMentionsA

```

Summary case class, printed and written to the results file:

```scala
final case class CheckSummary(sample: String, pairs: Int, checkable: Int, confirmed: Int,

```

## Implementation steps

1. `Mention` (no Spark):

   ```scala
   object Mention {
     /** Whole-word, case-insensitive. Returns the sentence around the first hit. */
     def find(text: String, name: String): Option[String]
     def mentions(text: String, name: String): Boolean = find(text, name).isDefined
   }
   ```

   Build the pattern with `java.util.regex.Pattern.quote(name)` between word boundaries, with flags `CASE_INSENSITIVE | UNICODE_CASE`. Names with several words ("insulin glargine") match as a phrase with any whitespace between words. A blank name never matches. The sentence is the text between the nearest full stops, cut to 300 characters.

2. Interaction text per drug: join `label_section` (`loinc = "34073-7"`) to the current reference `label_version` of each drug (see Context) on (`setId`, `version`), keep `rxcui` and `text`; concatenate if a label has several such sections. A drug with no row is "no interactions section". Broadcast this map (about 150 entries) or join it twice.

3. `PairSamples`:

   ```scala
   object PairSamples {
     def top(signals: Dataset[InteractionSignal], n: Int): Seq[(String, String)]      // Interactions.topPairs
     def randomFormulary(rxcuis: Seq[String], n: Int, seed: Long, exclude: Set[(String, String)]): Seq[(String, String)]
     def randomCoReported(signals: Dataset[InteractionSignal], n: Int, seed: Long, exclude: Set[(String, String)]): Seq[(String, String)]
   }
   ```

   Pairs are ordered `rxcuiA < rxcuiB`, distinct, and never in the top list. Use `new scala.util.Random(seed)` on a sorted input so the sample is reproducible. If fewer than `n` pairs exist, take all and report the number.

4. `InteractionValidation.check(sample, pairs, textByRxcui, formulary): Seq[InteractionCheck]`. The data is small after sampling; plain Scala collections on the driver are fine here. `classMention` uses `Mention.mentions(text, otherDrug.drugClass)`.

5. `InteractionValidation.summary`: `rate = confirmed / checkable` (`None` when `checkable` is 0). The ratio for criterion 12 is `rate(top) / rate(random_formulary)`. When the random rate is 0, report "undefined (0 of n random pairs confirmed)" and give the two rates; do not print infinity.

6. Add an interval, because 50 pairs is few: a 95% Wilson interval for each rate (formula in any statistics reference; implement as a pure function with a test against a known value, for example 10 of 50 gives roughly 0.11 to 0.33).

7. `InteractionCheckStage` (`name = "advanced.interactioncheck"`, `cadences = Set(Full)`): skip unless evaluation is enabled; write all three samples to `Tables.gold("InteractionCheck")` with `Delta.overwrite`; print summaries; return `StageResult(rowsIn = pairs sampled, rowsOut = rows written, rowsRejected = 0)`. Do not call `RunMetrics.record`; the runner records the stage. The stage file holds `class = "medsignal.advanced.interactioncheck.InteractionCheckStage"` and `after = ["advanced.interactions", "bronze.labels", "silver.label_version", "bronze.formulary"]`.

8. Read 10 confirmed and 10 unconfirmed top pairs by hand (the `evidence` column helps) and note false matches (for example an ingredient name that is also a common word) and misses (label names a brand or a class) in the results file.

## Tests

Fixtures in `pipeline/src/test/resources/V5/`: `label_section.json` (drug A's section says "Concomitant use with Warfarin increases bleeding risk."; drug B has a section without other drug names; drug C has no interactions section), `label_version.json`, `formulary.json` (A, B, C, WARFARIN, D), `interaction_signal.json`.

- `MentionSpec` "matches ignoring case"; "does not match inside a longer word" ("warfarinoid"); "matches a two-word name across a line break"; "blank name never matches"; "returns the containing sentence, at most 300 characters".
- `PairSamplesSpec` "random pairs are distinct, ordered and exclude the top pairs"; "same seed gives the same sample"; "asks for more than exist returns all".
- `InteractionValidationSpec` "uses the current version when the reference setId has several versions" (an older version of A's label without the Warfarin sentence is ignored); "pair confirmed when A's label names B"; "pair confirmed when only B's label names A"; "pair with one section and no mention is checkable and unconfirmed"; "pair where neither drug has a section is not checkable"; "class mention is recorded but does not confirm"; "rate ignores uncheckable pairs"; "ratio is reported as undefined when the random rate is zero"; "Wilson interval for 10 of 50".
