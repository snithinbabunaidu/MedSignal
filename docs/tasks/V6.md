## Goal

A measured answer to one question: can a trained model rank unlabeled signals better than the project's transparent score? Two Spark MLlib models, `GBTClassifier` and `LogisticRegression`, predict which unlabeled candidate signals later became label changes; each is compared with the transparent score by PR-AUC on held-out later years (acceptance criterion 13). The result is a comparison, reported honestly, not a replacement for the score.

## Context

- Read `docs/acceptance-criteria.md` row 13; `docs/pipeline-spec.md` section 10 ("Ranking model"); `docs/project-plan.md` risk "Few known FDA warnings to train a model on"; `docs/tasks/V1.md` (`SignalHistory`, `Quarters`); `docs/tasks/V2.md` (`WarningMatcher`); `docs/tasks/V3.md`; `docs/tasks/V4.md`.
- This is Spark MLlib, a classical statistical model. No language model, no external AI service.
- Everything depends on avoiding look-ahead. A feature for an example dated quarter Q may use only `SignalHistory` rows with `asOfQuarter <= Q`. A training label must be knowable by the training cut-off.
- Positives will be few. Report counts beside every metric. If the test set holds fewer than 10 positives, say plainly that the comparison is not conclusive; do not present a ratio as a finding.
- MLlib API facts to confirm in the Spark 4.0 MLlib guide before relying on them: `GBTClassifier` and `LogisticRegression` both accept `setWeightCol`; `GBTClassifier` outputs `rawPrediction` and `probability`; `BinaryClassificationEvaluator` with `metricName = "areaUnderPR"` accepts a `rawPredictionCol` of type Double as well as Vector (needed to score the baseline directly); the evaluator's `weightCol` is left unset so the test metric reflects true prevalence.
- Evaluation job: runs only when `medsignal.evaluation.enabled` is `true`.

## Outputs

`ops.ranking_metrics` (not in contracts.md; defined here, case class in this task's package `medsignal.advanced.ranking`), one row per run and ranker. `SignalHistory`, `InteractionSignal`, `ClassSignal` and `WarningMatcher` are imported from the packages of V1, V4, V3 and V2, not redefined:

```scala
final case class RankingMetric(
  runId: String,
  ranker: String,              // score, logistic, gbt, gbt_with_interactions
  trainThrough: String, horizonQuarters: Int,
  trainRows: Long, trainPositives: Long,
```

## Implementation steps

1. One example per (`rxcui`, `term`): its row at the first `asOfQuarter` Q0 in which it was a candidate (`Disproportionality.isCandidate`) with `labeledStatus == "unlabeled"`. One row per pair avoids many near-identical rows of the same signal.

   ```scala
   final case class RankingExample(
     rxcui: String, term: String, quarter: String,          // Q0
     logCases: Double, prr: Double, chiSquare: Double, rorLower: Double,
     seriousShare: Double, growth4q: Double,
     indicationFlag: Double, spikeFlag: Double,
     classPeers: Double,       // other drugs of the same class that are unlabeled candidates for the term as of Q0
     score: Double,            // the transparent score as of Q0: the baseline, never a model feature
     label: Double)            // 1.0 or 0.0
   ```

   `classPeers` is computed from `SignalHistory` at Q0 and the formulary classes (V3's rule, applied as of Q0). Cap extreme `prr` and `chiSquare` with a log transform (`log1p`).

2. Label. Positive when, within `horizonQuarters` after Q0, either:
   - the same pair has a `SignalHistory` row with `labeledStatus == "labeled"` (the label caught up), or
   - an FDA warning matching the pair (`WarningMatcher.pairs`) has `warningDate` in that window.

   Otherwise negative. Keep the two sources as separate boolean columns before combining, and report how many positives come from each.

3. `TimeSplit.split(examples, trainThrough, horizon, lastQuarter)`:
   - train: `index(Q0) + horizon <= index(trainThrough)`, so every training label was known by the cut-off;
   - test: `Q0 > trainThrough` and `index(Q0) + horizon <= index(lastQuarter)`, so the outcome window is complete;
   - examples in neither set are dropped and counted. No random split anywhere.

4. Instance weights, computed on the training set only: negatives 1.0, positives `trainNegatives / trainPositives`. Column `weight`.

5. Pipelines:

   ```scala
   val features = Array("logCases","prr","chiSquare","rorLower","seriousShare","growth4q",
                        "indicationFlag","spikeFlag","classPeers")
   val assembler = new VectorAssembler().setInputCols(features).setOutputCol("features")
   val scaler    = new StandardScaler().setInputCol("features").setOutputCol("scaled")
   val logistic  = new LogisticRegression().setFeaturesCol("scaled").setLabelCol("label")
                     .setWeightCol("weight").setRegParam(0.1).setMaxIter(100)
   val gbt       = new GBTClassifier().setFeaturesCol("features").setLabelCol("label")
                     .setWeightCol("weight").setMaxDepth(3).setMaxIter(50).setStepSize(0.1).setSeed(seed)
   val lrModel   = new Pipeline().setStages(Array(assembler, scaler, logistic)).fit(train)
   val gbtModel  = new Pipeline().setStages(Array(assembler, gbt)).fit(train)
   ```

   Keep the models small (shallow trees, regularisation): with few positives a large model memorises. Do not tune on the test set. If tuning is wanted, split the training period by time once more for validation and say so.

6. Evaluation on the test set, unweighted:

   ```scala
   val eval = new BinaryClassificationEvaluator().setLabelCol("label").setMetricName("areaUnderPR")
   val prModel = eval.setRawPredictionCol("rawPrediction").evaluate(model.transform(test))
   val prScore = eval.setRawPredictionCol("score").evaluate(test)       // the baseline
   ```

   Bootstrap interval in `PrAuc.interval`: collect (prediction, label) pairs of the test set to the driver (it is small), resample with replacement `bootstrap` times with the fixed seed, compute PR-AUC of each resample with a small pure function (average precision over the ranked list), and take the 2.5th and 97.5th percentiles. Test the pure function against the evaluator on a fixture so the two agree to within a small tolerance; MLlib's value is computed from a binned curve, so allow a tolerance rather than expecting equality.

7. Extra variant `gbt_with_interactions`: adds the pair's best interaction ratio from `gold.InteractionSignal` (maximum over partner drugs for the same term, 0 when absent). That table is computed from all data, including quarters after Q0, so this feature leaks the future. Report it only under that name with that warning; it never enters the criterion 13 number.

8. `RankingStage` (`name = "advanced.ranking"`, `cadences = Set(Full)`, `after = ["backtest.scoring", "advanced.classeffect", "advanced.interactions"]`): skip unless evaluation is enabled; if the training set has zero positives or the test set has zero positives, write no metrics, log the counts and return (a PR-AUC is meaningless there); otherwise `Delta.append` the `RankingMetric` rows to `Tables.ops("ranking_metrics")`. Return `StageResult(rowsIn = history rows, rowsOut = examples, rowsRejected = 0)`; log the number of examples dropped by censoring (they are not `Reject` rows). Do not call `RunMetrics.record`; the runner records the stage (contracts.md decision 6).

## Tests

Fixtures in `pipeline/src/test/resources/V6/`: `signal_history.json` (hand-made: 12 pairs over 2016Q1 to 2022Q4, some becoming labeled), `fda_warning.json`, `formulary.json`, and `separable.json` (200 synthetic examples where `rorLower` separates the classes).

- `ExamplesSpec` "one example per pair at its first unlabeled candidate quarter"; "features use only rows up to that quarter" (a later huge `a` does not change `logCases`); "label is 1 when the pair is labeled within the horizon"; "label is 0 when labeled after the horizon"; "label is 1 for a matching FDA warning in the window"; "classPeers counts other drugs of the class as of Q0".
- `TimeSplitSpec` "training rows have complete outcome windows before the cut-off"; "test rows start after the cut-off"; "rows too recent to label are dropped and counted"; "train and test share no row".
- `PrAucSpec` "perfect ranking gives 1.0"; "average precision of labels (1,0,1,0) ranked in that order is 0.8333"; "pure function agrees with the MLlib evaluator within 0.02 on the fixture"; "interval contains the point estimate"; "same seed gives the same interval".
- `RankersSpec` "both models beat prevalence on separable data"; "weights make positives count trainNegatives over trainPositives"; "stage writes no metrics when the test set has no positives".
