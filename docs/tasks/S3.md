## Goal

Four silver tables exist: `case_drug`, `case_reaction`, `case_outcome` and `case_indication`. Each holds one row per case and thing, only for the case versions kept in `silver.case`, with drugs identified by ingredient `rxcui`. These are the tables every count is built from.

## Context

- Bronze DRUG, REAC, OUTC and INDI contain rows for every version of every case. Only rows whose `primaryid` is the one kept in `silver.case` are used.
- `role_cod`: `PS` primary suspect, `SS` secondary suspect, `C` concomitant, `I` interacting. `case_drug` keeps `PS` and `SS` only.
- One case can list the same ingredient several times (two brands, two doses, a combination). It must count once.
- Outcome codes: `DE, LT, HO, DS, CA, RI, OT`.
- Read: `docs/contracts.md` (Conventions, Bronze tables, Silver tables), `docs/pipeline-spec.md` section 3, the S1 and S2 briefs.

## Outputs

All written with `Delta.overwrite`, not partitioned. Define in `medsignal.silver.casedetail`, exactly as in contracts.md:

```scala
final case class CaseDrug(caseid: Long, rxcui: String, role: String)          // key caseid, rxcui
final case class CaseReaction(caseid: Long, term: String)                     // key caseid, term
final case class CaseOutcome(caseid: Long, outcome: String)                   // key caseid, outcome
final case class CaseIndication(caseid: Long, rxcui: String, term: String)    // key caseid, rxcui, term
```

## Implementation steps

1. Signatures:

   ```scala
   object CaseDetailTransforms {
     def currentRows[T](rows: Dataset[T], cases: Dataset[Case]): DataFrame   // left_semi on primaryid
     def caseDrug(drug: Dataset[FaersDrug], cases: Dataset[Case], xref: Dataset[DrugXref]): Dataset[CaseDrug]
     def caseReaction(reac: Dataset[FaersReac], cases: Dataset[Case]): (Dataset[CaseReaction], Dataset[Reject])
     def caseOutcome(outc: Dataset[FaersOutc], cases: Dataset[Case]): (Dataset[CaseOutcome], Dataset[Reject])
     def caseIndication(indi: Dataset[FaersIndi], drug: Dataset[FaersDrug], cases: Dataset[Case],
                        xref: Dataset[DrugXref]): Dataset[CaseIndication]
   }
   ```

2. Current rows. Join each bronze table to `silver.case` on `primaryid` with `left_semi`. Do not join on `caseid` alone: that would bring back superseded versions. Do not join on `quarter`: `Case.quarter` can differ from the file quarter (see S1).

3. `caseDrug`:
   - Keep `upper(trim(role_cod))` in (`PS`, `SS`).
   - Join key: `DrugIdentity.faersKey(drugname, prod_ai)` (S2), wrapped in a UDF, equal to `drug_xref.rawName`. Use the S2 function; do not re-implement the key.
   - Inner join to `xref` rows with `rxcui` present. A combination gives several rows.
   - One row per (`caseid`, `rxcui`): `role = "PS"` if any contributing row was `PS`, else `"SS"`.

   ```scala
   joined.groupBy("caseid", "rxcui")
     .agg(max(when(col("role_cod") === "PS", 1).otherwise(0)).as("ps"))
     .select(col("caseid"), col("rxcui"), when(col("ps") === 1, "PS").otherwise("SS").as("role"))
   ```

   - Suspect rows whose name is unresolved are left out of `case_drug`. They are counted, not written as `Reject` rows (contracts.md, decision 18: there are too many, and the string is already listed in `drug_xref` with method `none`). Return the count from the transform's caller, add it to `rowsRejected` in the `silver.case_drug` `StageResult`, log it and report the number in the results file.

4. `caseReaction`: `term = upper(trim(pt))`; `distinct` on (`caseid`, `term`). An empty term becomes a `Reject`.

5. `caseOutcome`: `outcome = upper(trim(outc_cod))`; keep the seven codes above; `distinct`. Any other code becomes a `Reject`.

6. `caseIndication`: join current INDI rows to current DRUG rows on (`primaryid`, `indi_drug_seq = drug_seq`), resolve the drug as in step 3 but for all roles (the reason a drug was taken is useful whatever its role), `term = upper(trim(indi_pt))`, `distinct` on (`caseid`, `rxcui`, `term`). Terms are kept as reported, including "unknown indication" wording.

7. Rejects use the contracts type: `Reject(source = "faers", file = "bronze.faers_reac" (or `bronze.faers_outc`), line = 0, raw = s"$primaryid:$value" (the `primaryid` and the offending value), reason = "empty reaction term" or "unknown outcome code", runId = ctx.runId)`, written with `Rejects.write(rejects)`. These stages read tables, not files, so `file` is the input table name and `line` is 0 (contracts.md, decision 7).

8. Stages. Names `silver.case_drug`, `silver.case_reaction`, `silver.case_outcome`, `silver.case_indication`; `cadences = Set(Quarterly, Full)`. Each reads its inputs, calls its transform, overwrites its table, writes rejects with `Rejects.write`, and returns `StageResult(rowsIn, rowsOut, rowsRejected)` where `rowsIn` is the number of current bronze rows (after step 2). For `silver.case_drug`, `rowsRejected` is the count of unresolved suspect rows (step 3). The stages do not call `RunMetrics.record`; the runner (`StageRunner`) records the metrics. Conf files: `after = ["silver.case", "identity.drug_xref"]` for the drug and indication stages, `after = ["silver.case"]` for the other two.

9. Performance: `silver.case` is tens of millions of rows; do not broadcast it. `drug_xref` (resolved rows only) is small enough to broadcast.

## Tests

`CaseDetailTransformsSpec` (Spark, inline data):

- "superseded versions are ignored": a case with versions 1 and 2, different drugs in each; only the version 2 drug appears.
- "a drug listed twice in one case counts once": two DRUG rows, same ingredient under two names; one `case_drug` row.
- "primary suspect wins": the same ingredient as `SS` and `PS` gives `role = "PS"`.
- "concomitant and interacting drugs are excluded": `C` and `I` rows give no `case_drug` row.
- "a combination product gives one row per ingredient".
- "an unresolved drug gives no row and no reject, and is counted".
- "reaction terms are upper-cased, trimmed and distinct": `" nausea"` and `"NAUSEA"` give one row.
- "an unknown outcome code is rejected": `XX` gives one `Reject`, no row.
- "indications follow drug_seq": the indication attaches to the drug with the matching sequence number, not to the others.

`CaseDetailStagesSpec`: runs the four stages on fixtures; runs them with `StageRunner.run`; asserts each primary key is unique and each returned `StageResult` has the expected counts (the runner, not the stage, writes the `run_metrics` rows).
