## Goal

One sbt build with three independent modules (`labels`, `pipeline`, `app`) that compiles and runs `sbt test` on JDK 21 on both engineers' machines. `build.sbt` is written once here with every dependency the whole plan needs, so no later feature branch has to edit it.

## Context

Read `docs/contracts.md` (Toolchain), `docs/architecture.md` (Modules) and `docs/branching.md` (Shared files). Three modules exist because Spark is published for Scala 2.13 only, XmlDoc needs Scala 3.9, and TableParser's Spark support is on its 1.x line for Scala 2.13. The modules exchange files and database tables only; there is no `dependsOn` between them.

Unverified facts you must check while doing this task:

- Whether TableParser 1.7.2 (`tableparser-core`, `tableparser-spark`) and XmlDoc 1.2 (`xmldoc-core`, `xmldoc-json`) are on Maven Central, and under which organization (expected `com.phasmidsoftware`). Check `https://github.com/rchillyard/TableParser` (branch `1.x`, its `build.sbt`) and `https://github.com/rchillyard/XmlDoc`, then search Maven Central. If an artifact is not published, the fallback is `git clone`, check out the tag or branch, `sbt publishLocal`; write the exact commands in `docs/results/F1.md` because F2 (CI) and F3 (setup guide) must repeat them.
- The exact Scala 3.9.x patch XmlDoc was built with, and the Scala 2.13 patch Spark 4.0.x uses (take it from the `spark-sql_2.13` POM).
- The Delta Lake artifact for Spark 4.0 (expected `io.delta %% delta-spark % 4.0.x`) and the GraphFrames artifact built for Spark 4.0 and Scala 2.13 (the coordinates changed between releases; check the GraphFrames README).

## Inputs

None.

## Outputs

A build in which `sbt test`, `sbt labels/test`, `sbt pipeline/test` and `sbt app/test` all pass.

## Files to create

- `build.sbt`: root project plus the three modules.
- `project/build.properties`: sbt version (latest 1.x).
- `project/plugins.sbt`: `sbt-scalafmt`, `sbt-scoverage`, `sbt-assembly`.
- `labels/src/test/scala/medsignal/BuildSmokeSpec.scala`: one test that references an XmlDoc class.
- `pipeline/src/test/scala/medsignal/BuildSmokeSpec.scala`: starts a `local[2]` Spark session with Delta, writes and reads a three-row Delta table in a temp folder, and references a TableParser class.
- `app/src/test/scala/medsignal/BuildSmokeSpec.scala`: one test that references an http4s class and opens an in-memory H2 connection.
- `docs/results/F1.md`: resolved versions and any `publishLocal` steps (convention path; see contracts.md and branching.md).

Git does not keep empty folders, so the smoke specs are what make the module folders exist.

## Implementation steps

1. Root project: `lazy val root = (project in file(".")).aggregate(labels, pipeline, app)` with `publish / skip := true`. No `dependsOn` anywhere.
2. Common settings: `organization := "medsignal"`, `javacOptions ++= Seq("--release", "21")`, `scalacOptions ++= Seq("-deprecation", "-feature", "-unchecked")`, `Test / fork := true`, `Test / parallelExecution := false`.
3. `pipeline` (Scala 2.13.x):
   - `spark-sql`, `spark-mllib` 4.0.x as `% Provided`; `delta-spark`; `tableparser-core` and `tableparser-spark` 1.7.2; GraphFrames; `com.typesafe % config` (for `application.conf`, task F3); H2 and PostgreSQL JDBC drivers (publish job A1 writes over JDBC); ScalaTest and `scalatestplus` ScalaCheck as `% Test`.
   - Make `sbt pipeline/run` and `runMain` see the provided jars:
     ```scala
     Compile / run := Defaults.runTask(Compile / fullClasspath, Compile / run / mainClass, Compile / run / runner).evaluated,
     Compile / runMain := Defaults.runMainTask(Compile / fullClasspath, Compile / run / runner).evaluated,
     run / fork := true
     ```
   - Spark on JDK 21 needs module opens in forked JVMs. Add to `Test / javaOptions` and `run / javaOptions` the `--add-opens` list Spark itself uses (copy it from `JavaModuleOptions` in the Spark source for the 4.0.x tag; at minimum `java.base/java.lang`, `java.lang.invoke`, `java.nio`, `java.util`, `java.util.concurrent`, `sun.nio.ch`, `sun.security.action`, `sun.util.calendar`, each `=ALL-UNNAMED`). Also `-Xmx4g`.
   - If TableParser pulls a conflicting Scala library or parser-combinator version, exclude or override it and note it in `docs/results/F1.md`.
4. `labels` (Scala 3.9.x): `xmldoc-core`, `xmldoc-json`, circe (`core`, `generic`, `parser`), `com.typesafe % config`, ScalaTest and `scalatestplus` ScalaCheck as `% Test`. HTTP uses the JDK's `java.net.http`; no client library.
5. `app` (Scala 3.9.x): http4s `ember-server`, `dsl`, `circe`; circe; doobie `core` and `hikari`; H2 and PostgreSQL drivers; `com.typesafe % config`; a logging backend (logback); ScalaTest and `scalatestplus` ScalaCheck as `% Test`.
6. `sbt-assembly`: enable for `pipeline`, `labels` and `app`; for `pipeline` keep Spark out of the jar (it is `Provided`) and add a merge strategy that discards `META-INF` signatures and concatenates `reference.conf` and service files. Task A6 uses these jars.
7. scoverage: set `coverageFailOnMinimum := false` and `coverageExcludedPackages := "medsignal\\.spike\\..*"`. The 75% target (criterion 9) is reported by F2, not enforced here.
8. Do not add `.scalafmt.conf` (F2 owns it) or `application.conf` (F3 owns it).
9. Run `sbt clean test` under WSL2 or Linux/macOS. Native Windows needs winutils for Spark; do not chase that here, F3 documents it.
