## Goal

A hand-curated list of about 20 safety warnings the FDA actually issued for formulary drugs, each with the drug or class, the reaction terms, the date and a source link. It is the answer key for the backtest (V2): did MedSignal flag the reaction as unlabeled before the FDA warned about it? This task also owns the small reference loader that loads the CSV into the bronze table `bronze.fda_warning` (stage name `bronze.fda_warning`); V2 and every other task read that bronze table, not the CSV file (contracts.md, decision 3).

## Context

Read `docs/data-sources.md` ("FDA Drug Safety Communications" row and "Known FDA warnings in the formulary's classes", the eight starting rows), `docs/contracts.md` (bronze `fda_warning`, case class `FdaWarning`; convention for `term`), `docs/acceptance-criteria.md` criteria 10 and 11, and `docs/tasks/F6.md` (formulary columns and the allowed `drugClass` values).

Also read the final section of `docs/contracts.md` ("Decisions settled after the first draft of the briefs": decisions 1, 2, 3, 6, 7 and 17, "Common library (F7) additions" and "Stage names"). The loader part of this task uses `medsignal.common` (F7: `Stage`, `StageResult`, `Delta`, `Tables`, `Settings`, `Rejects`, `SparkTestSession`) and reads `bronze.formulary` (F6), so write the loader once F1, F7 and F6 are merged; the CSV itself needs only F6.

The file is read by this task's loader with TableParser, which matches header names to case-class fields, so the header uses the `FdaWarning` field names exactly: `warningId,scope,target,terms,warningDate,sourceUrl` (contracts.md, decision 17).

Sources: FDA Drug Safety Communications, `https://www.fda.gov/drugs/drug-safety-and-availability/drug-safety-communications`, and for label changes the FDA's Drug Safety-related Labeling Changes database. Use only FDA pages. Open every link yourself; do not take dates, wording or URLs from memory or from a chat tool.

FAERS reaction terms are MedDRA preferred terms, upper case, with British spelling (for example `DIABETIC KETOACIDOSIS`, `ANEURYSM`, `SOMNAMBULISM`). A warning in plain words usually maps to several preferred terms.

Because scoring starts in 2014 Q3 (the first FAERS quarter loaded), only warnings dated 2015 or later can be detected "before the FDA". Earlier warnings are not useful rows.

## Inputs

`data/reference/formulary.csv` (to check that every target exists) and the FDA pages.

## Outputs

`data/reference/fda_warnings.csv`, UTF-8, comma-separated, header row, one row per warning and target:

| Column | Type | Rule |
|---|---|---|
| `warningId` | String | Unique slug: `<yyyy>-<target>-<short reaction>`, lower case, hyphens, for example `2015-sglt2-ketoacidosis` |
| `scope` | String | `drug` or `class` |
| `target` | String | For `drug`: the ingredient `rxcui` from `formulary.csv`. For `class`: a `drugClass` value from `formulary.csv`, spelled exactly |
| `terms` | String | MedDRA preferred terms, upper case, separated by `;` with no spaces around it |
| `warningDate` | Date | `yyyy-MM-dd`, the date the FDA first published this warning |
| `sourceUrl` | String | The FDA page, starting `https://www.fda.gov/` |

No commas inside any field. A warning that names several drugs which are not a whole formulary class gets one row per drug (`2019-zolpidem-complex-sleep`, `2019-eszopiclone-complex-sleep`), unless those drugs are exactly the members of a formulary class.

Bronze Delta table `bronze.fda_warning` at `Tables.bronze("fda_warning")`, unpartitioned, one row per CSV row, written by stage `bronze.fda_warning`:

```scala
package medsignal.bronze.reference.warnings
final case class FdaWarning(warningId: String, scope: String, target: String, terms: Seq[String],
                            warningDate: java.sql.Date, sourceUrl: String)
```

The case class lives in this task's package (contracts.md, decision 2); other tasks import it and do not redefine it.

## Implementation steps

1. Start from the eight warnings in `docs/data-sources.md`. Find the FDA page for each and take the date from the page, not from that table's year.
2. Extend to about 20 rows. Look for further warnings dated 2015 or later on formulary drugs, including the `Hospital common` ones. If a strong candidate needs a drug that is missing from the formulary, note it in `docs/results/I8.md`; adding it is a separate change to F6's file.
3. Choosing the date: use the first communication about that reaction for that drug. If the FDA first announced an investigation and later a confirmed warning, use the first date and say so in the results file. Follow-up communications are not new rows.
4. Choosing terms: list every preferred term a reporter would plausibly use for that reaction, 1 to 6 terms. If FAERS bronze (I2) is loaded, check each term exists in `bronze.faers_reac.pt` (compare upper-cased) and record its count; if I2 is not loaded yet, use the terms the FDA page or the label names and mark the row "terms unverified" in the results file for a later check.
5. `scope = class` only when the FDA communication covers the class. These rows also serve criterion 11 (class effects); aim for at least four class rows.
6. Split so there is no overlap: Nithin curates rows for `SGLT2 inhibitor`, `DPP-4 inhibitor`, `Fluoroquinolone`, `Gabapentinoid`; Zenish curates `Sleep drug`, `Asthma and allergy`, `Hospital common`. Keep rows sorted by `warningDate`, then `warningId`.
7. Second check: each engineer opens every link in the other's rows and confirms target, terms and date. Record initials in `docs/results/I8.md`.
8. Format: no blank lines, no quotes, Unix line endings, final newline.
9. Reference loader, `FdaWarningStage` (Nithin writes it; Zenish reviews):
   - `name = "bronze.fda_warning"`; `cadences = Set(Cadence.Daily, Cadence.Weekly, Cadence.Quarterly, Cadence.Full)` (the file is tiny).
   - Input path: `Settings.dataDir + "/reference/fda_warnings.csv"`. Never hard-code `data/`.
   - Read the file as lines, skip the header, parse each line into `FdaWarningLine` with TableParser, then convert to `FdaWarning`: `terms` split on `;`, each term trimmed and upper-cased, empty pieces dropped; `warningDate` parsed as `yyyy-MM-dd` with `Try` into `java.sql.Date`.
   - A line becomes a `Reject(source = "fda_warning", file = "fda_warnings.csv", line = <1-based line number>, raw = <the line>, reason = <message>, runId = ctx.runId)` when: it does not have six fields; `warningId`, `target` or `sourceUrl` is empty; `scope` is not `drug` or `class`; `terms` is empty after splitting; `warningDate` does not parse; the `warningId` was already seen; or the target is unknown. Target check against `Delta.readOrEmpty[FormularyDrug](Tables.bronze("formulary"))` (import `medsignal.bronze.reference.formulary.FormularyDrug`; do not read `formulary.csv`): for `scope = drug` the `target` must be a formulary `rxcui`; for `scope = class` it must be a formulary `drugClass`. If `bronze.formulary` is empty, fail the stage with the message `bronze.formulary is empty; run bronze.formulary first`.
   - Write the good rows with `Delta.overwrite(rows, Tables.bronze("fda_warning"))`: a full snapshot of the file on every run, so re-running never duplicates rows.
   - Write rejects with `Rejects.write(rejects)`.
   - Return `StageResult(rowsIn = data lines read, rowsOut = rows written, rowsRejected = rejects)`. Do not call `RunMetrics.record`; `StageRunner` records the metrics (contracts.md, decision 6).
   - Run it with `sbt "pipeline/runMain medsignal.common.StageRunner bronze.fda_warning"`.
   - No tunables, so no `conf.d/I8.conf` is needed. No `var`, no `null`.

## Tests

`FdaWarningStageSpec` (`AnyFlatSpec with Matchers with SparkTestSession`; copy the fixture to `<temp dataDir>/reference/fda_warnings.csv` and write a small `bronze.formulary` with `Delta.overwrite` before running the stage):

- "loads every row of the file into bronze.fda_warning": `StageResult(3, 3, 0)`.
- "splits terms on semicolons into a sequence": the three-term row has `terms.size == 3`, upper case.
- "parses warningDate as a date".
- "rejects a short row, a bad scope, a bad date and an unknown target": on the `bad` fixture, `StageResult(5, 1, 4)` and four rows in `Tables.ops("rejects")` with `source = "fda_warning"` and the right line numbers.
- "running twice does not duplicate rows".
- "fails when bronze.formulary is empty".
- "is registered under the name bronze.fda_warning": `StageRunner.load("bronze.fda_warning")` returns an `FdaWarningStage`.
- "table schema equals FdaWarning".

Checks on the data file, to run and paste into the pull request:

- Header is exactly `warningId,scope,target,terms,warningDate,sourceUrl`.
- `awk -F, 'NF!=6' fda_warnings.csv` prints nothing.
- `warningId` values are unique.
- Every `scope` is `drug` or `class`; every `drug` target is an `rxcui` in `formulary.csv`; every `class` target is a `drugClass` in `formulary.csv`.
- Every `warningDate` matches `^\d{4}-\d{2}-\d{2}$` and is 2015-01-01 or later.
- Every `sourceUrl` starts with `https://www.fda.gov/` and returns HTTP 200 on the day of the check.
- Every term is upper case with no leading or trailing space.
