## Goal

Decisions the safety officer makes in the app flow back into the gold layer. At the start of each run, triage events in the serving table `triage_event` are merged into `gold.TriageDecision` (stage `triage.merge`); later in the run, after `signals.signal` and `labeltext.status`, the latest decision per signal is merged into `gold.Signal.triageStatus` (stage `triage.status`). Both stages run on every run. A dismissed signal stays dismissed after a full rebuild.

## Context

- Read `docs/contracts.md` sections "Common library", "Gold tables" (`Signal`, `TriageDecision`), "Serving database"; `docs/pipeline-spec.md` section 9; `docs/ontology.md` row `TriageDecision`.
- The API (A2) only inserts rows into `triage_event(event_id, rxcui, term, decision, note, user_name, decided_at)`. It never updates or deletes. A1's publish job never touches that table. So `triage_event` holds every decision ever made, and re-reading all of it on every run is both cheap and safe.
- G3's stage `signals.signal` rebuilds `gold.Signal` in full on every run with `triageStatus = open` (contracts.md decision 16) and does not know about triage. This task must not edit G3's files. Stage `triage.status` re-applies the status afterwards, on every run, with `Delta.merge` on (`rxcui`, `term`).
- Both steps live in this task's own package, each as its own `Stage`.
- Decisions are `review`, `escalate`, `dismiss`. A signal with no decision is `open`.

## Outputs

- `gold.TriageDecision`, case class `TriageDecision(eventId: String, rxcui: String, term: String, decision: String, note: Option[String], user: String, decidedAt: Timestamp)`, key `eventId`. Append-only in effect: an event is inserted once and never changed.
- `gold.Signal` with `triageStatus` set to the latest decision for each (`rxcui`, `term`); all other columns untouched.
- Rejects for unusable events (unknown decision, blank key), `source = "triage_event"`, `file = "triage_event"`, `line = 0` (contracts.md decision 7), written with `Rejects.write`.

## Implementation steps

1. `TriageEventReader`:

   ```scala
   object TriageEventReader {
     def tableExists(url: String, user: String, password: String): Boolean  // DatabaseMetaData.getTables
     def read(url: String, user: String, password: String)
             (implicit spark: SparkSession): Dataset[TriageDecision]
   }
   ```

   Read with `spark.read.format("jdbc").option("url", url).option("dbtable", "triage_event")...load()`, then select `event_id as eventId`, `rxcui`, `term`, `decision`, `note`, `user_name as user`, `decided_at as decidedAt`. If the table does not exist (the app has never started) return an empty Dataset and log one line; do not fail the run. If the database cannot be reached, fail the run with a clear message.

2. `TriageStatus` (no Spark):

   ```scala
   object TriageStatus {
     val Decisions: Set[String] = Set("review", "escalate", "dismiss")
     def validate(d: TriageDecision): Either[String, TriageDecision]   // trims, upper-cases term
     def latest(ds: Dataset[TriageDecision]): Dataset[TriageDecision]  // one row per (rxcui, term)
   }
   ```

   `latest` keeps the row with the greatest `decidedAt` per (`rxcui`, `term`), ties broken by the greatest `eventId`, using a window `row_number`.

3. `TriageMergeStage` (`name = "triage.merge"`, all four cadences, `after = []` so it runs at the start):
   - read all events; split with `validate` into good rows and `Reject`s (write rejects to the rejects table through the common library);
   - `Delta.merge(good, Tables.gold("TriageDecision"), Seq("eventId"))`. `Delta.merge` creates the table when it does not exist (contracts.md, "Common library (F7) additions");
   - return `StageResult(rowsIn = events read, rowsOut = events merged, rowsRejected)`. Do not call `RunMetrics.record`; the runner records the stage.

4. `TriageStatusStage` (`name = "triage.status"`, all four cadences, `after = ["triage.merge", "signals.signal", "labeltext.status"]`). `Signal` is imported from G3's package (`medsignal.signals.signal.Signal`), not redefined:

   ```scala
   val signals  = Delta.read[Signal](Tables.gold("Signal"))
   val decided  = TriageStatus.latest(Delta.readOrEmpty[TriageDecision](Tables.gold("TriageDecision")))
   val changed: Dataset[Signal] = signals
     .joinWith(decided, signals("rxcui") === decided("rxcui") && signals("term") === decided("term"), "left")
     .flatMap { case (s, d) =>
       val status = Option(d).map(_.decision).getOrElse("open")
       if (status == s.triageStatus) None else Some(s.copy(triageStatus = status))
     }
   if (!changed.isEmpty) Delta.merge(changed, Tables.gold("Signal"), Seq("rxcui", "term"))
   ```

   `Option(d)` is the one accepted place for a possible null: a left `joinWith` yields null on the right side. Merge only rows whose status differs, and skip the write when there are none, so a run with no triage adds no commit to `gold.Signal`. A decision for a (rxcui, term) that is not in `gold.Signal` is kept in `gold.TriageDecision` and simply has no effect now; if the signal reappears it is applied then. Return `StageResult(rowsIn = signals, rowsOut = rows changed, rowsRejected = 0)`; the runner records it.

5. Stage files:

   ```
   # stages/triage.merge.conf
   class = "medsignal.triage.TriageMergeStage"
   after = []
   # stages/triage.status.conf
   class = "medsignal.triage.TriageStatusStage"
   after = ["triage.merge", "signals.signal", "labeltext.status"]
   ```

6. Why a full rebuild cannot lose a dismissal: the source of truth is `triage_event` in the serving database, which no pipeline job deletes. Even if `data/gold` is wiped, `triage.merge` re-imports every event by `eventId` and `triage.status` re-applies them after `signals.signal` has rebuilt the table and `labeltext.status` has merged its columns.

## Tests

Use `SparkTestSession` and in-memory H2 (`jdbc:h2:mem:a4;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1`). Fixtures in `pipeline/src/test/resources/A4/`: `triage_event.sql` (create table plus 4 events: drug 1 term X `review` at 09:00, the same pair `dismiss` at 10:00, drug 2 term Y `escalate`, one row with decision `maybe`) and `signals.json` (3 signals, all `open`).

- `TriageStatusSpec` "latest keeps the newest decision per signal" (X is `dismiss`); "ties break by eventId"; "validate rejects an unknown decision"; "validate upper-cases the term".
- `TriageMergeStageSpec` "imports valid events and rejects the bad one" (3 rows in gold, 1 reject); "is idempotent" (second run leaves 3 rows); "missing triage_event table yields zero rows and no failure".
- `TriageStatusStageSpec` "sets triageStatus from the latest decision" (X `dismiss`, Y `escalate`, third signal `open`); "changes no other column"; "writes nothing when nothing changed" (Delta table version unchanged on a second run); "ignores a decision for a signal that is absent".
- `TriageSurvivesRebuildSpec` "a dismissed signal stays dismissed after a full rebuild": apply; overwrite `gold.Signal` with all rows `open` (what G3 does); delete the `gold.TriageDecision` folder; run `triage.merge` then `triage.status`; X is `dismiss` again.
